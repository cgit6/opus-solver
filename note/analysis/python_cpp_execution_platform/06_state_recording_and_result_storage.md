## 二 提交內容與不可變快照

每次實際提交保留開發者定義的文字狀態、當時的編碼、各項真實目標、對應可行性，以及在整場開關允許時提交的外部資料。單一解保存該解，種群提交保存該次全部個體；順序、對應關係與資料語意不可因輸出而改變。

- 外部資料為空值時，表示本次沒有外部快照，不補上上一筆資料、不假造物件。關閉開關只省略外部資料，不取消基本提交，也不停止算法更新必要的外部工作狀態。
- 算法先維護編碼、評分及可行性的對應，再在自選時點呼叫 `addAct`。這可以是整輪內已完成的小操作，不必限制在代末；記錄器不為了同步而重新評估，也不新增「未評估」標記。
- 例如 MKP 移除物品並正確扣分、更新負載及可行性後，可提交修復後快照；記錄本身不增加評估次數，也不再完整重算一次。
- 快照須保留提交當時的值。之後修改溫度、換代、重用編碼緩存或執行下一個 task，不能連帶改寫舊紀錄。這不要求深複製整個算法、RNG 或共用題庫。
- 搜尋罰分、排序值及其他算法專用狀態可以另存在外部資料，但不得覆蓋或冒充真實目標；關閉外部保存也不改變算法使用這些值的行為。

上述一致性是開發原則及測試要求，不新增 Python 管理端逐筆數學檢查。正式提交器綁定、外部資料型別及開關欄位名稱由單元 10 落實，不在此新增函式參數或通訊格式。

固定且對齊的輸入、seed、迭代與執行條件下，提交或外部保存開關不得改變搜尋與 RNG。時間限制模式不承諾相同迭代數。所有實際提交在該 task 求解期間累積於記憶體，完成後才交給輸出功能；完整歷史可能耗用大量記憶體的風險仍接受，不新增抽樣、截斷、循環覆寫、Redis 或背景 writer。

## 三 結果、歷史與實際輸入的責任

| 內容 | 保存要求 | 不可替代的責任 |
| --- | --- | --- |
| 最終結果 JSON | 保存單一最終解或算法自身維護的最終解集合；每個解都有對應編碼、真實目標及可行性。記錄全部成立停止原因、實際完成迭代、搜尋評估及另計的最終驗證。 | 不任選一個解／目標／停止原因，不強制額外維護全程非支配集合，也不以最後一筆歷史冒充算法返回結果。 |
| 完整歷史 JSONL | 每行保存一筆實際提交，保留提交順序及全部基本資料；外部資料依整場開關及本次空值處理。 | 最終集合不取代歷史；未收錄 seed 的 task 也不能只留摘要或丟棄歷史。 |
| 實際輸入及 task 關聯 | C++ 在算法開始前，將實際讀入的題目內容、選中算法參數值及其 task 關聯，連同本次 seed、停止安排等，寫入本場可追查的保存紀錄，不能只留在 C++ 程序記憶體中。 | 不能只保存來源路徑或組號，也不能在求解後重讀可能已改動的檔案冒充當次輸入。Python 不為此開算法 YAML。 |
| 本場終結摘要及位置 | C++ 提供本場已知結果與紀錄位置，Python 保存收到的資訊並據此彙整；完整題庫及歷史不往返搬給 Python。 | 摘要不取代完整輸出，不由平均值推算 task 或候選 seed；未取得的完成事實不能補造。 |

JSON／JSONL 是文字格式選擇，不是已完成的型別契約。二元、整數、實數及類別的型別、值與意義必須可辨識，多目標須保留各項目標及方向；SCVRP 等問題須保留完整路線與 transfer 狀態，不能只留無法解讀的一維數列。正式欄位、數值表示及讀回規則歸單元 10，不能先全轉浮點再宣稱保真。

正常沒有候選解時，如實表示沒有編碼／評分，不填零分或假解；有候選但不可行、正常無候選及算法錯誤分開。評估計數遵守單元 5：完整評分與正確增量完成評分均計搜尋評估，提交或複製既有分數不計，最終驗證不混入搜尋次數。多個停止條件在同一檢查點成立就全部保存，不額外評估以取得更多原因。

已保存的實際題目輸入可由場內多 task 的明確引用共用，不要求每題再複製一份完整題庫；但引用必須對到已保存的實際內容，不是只指向可變動的來源檔案。正式輸入格式歸單元 10、保存失敗歸單元 7，不新增硬體保存保證。輸入本身若是距離表，仍須保存；不另存的是從座標等輸入重新計算的衍生表。這不過濾算法已提交的外部歷史資料，也不新增重跑時自動恢復歷史輸入的能力。

## 四 C++ 保存與整場交付流程

```text
Python 保存本場安排，啟動 C++ 並一次交付安排
    ↓
C++ 完成全部預檢、題目準備與工作安排
    ↓
每條 C++ 工作鏈：
    留存實際輸入與 task 關聯
    → 求解與最終驗證
    → 同步保存結果 JSON 與完整歷史 JSONL
    → 完成仍需資料的工作，清理 task 私有資源
    → 接下一個 task
    ↓
C++ 完成整場工作、所需保存與清理，釋放已無使用者的題庫
    ↓
向 Python 交付整場終結摘要、紀錄位置及可取得的錯誤資訊
    ↓
Python 記錄本場交付並彙整；正常關閉本場 C++ 程序
```

工作鏈保存由 C++ 獨立輸出功能執行，並非算法或 `addAct` 自行寫檔；「獨立功能」不表示另外開背景程序。該工作鏈同步完成所需保存及清理才能接新 task，其他工作鏈可繼續自己的合法工作。各 task 仍只使用自己的可變狀態與 RNG。

準備完成、task 開始、求解完成及本機保存完成仍是 C++ 內部不同事實，但不要求逐項通知 Python，不等待逐 task ACK。Python 不掌握或批准下一個 task，也不靠檔案掃描追蹤進度。全部預檢才求解及開始前輸入留存的閘門，不能因取消登記通知而省略。

### 本機保存不等於管理端已取得整場交付

- 結果 JSON 已寫、歷史 JSONL 尚未完整保存，不能稱該 task 的完整資料已保存。寫檔失敗及部分檔案的處置歸單元 7，不把它冒充算法錯誤或成功。
- 本場終結回報未取得時，Python 只能留下已知事實及本場安排，不能靠正常退出碼、路徑存在或掃描既有檔案補登整場成功，也不自動重跑。
- C++ 已成功保存的資料不因之後程序退出而被撤銷；但本機存在完整檔案，不代表 Python 已收到整場交付。未確認交付與已保存資料可同時存在。
- 取消 task 通知後，Python 不保證即時知道正在執行哪些 task。原生崩潰也未必能指出肇因 task；C++ 留存的輸入與關聯供追查，不以未完成清單猜測原因。
- 在整場完成交付前確認 Python 退出或通訊中斷，仍依單元 4 停止整個 C++ 程序，不等在途算完；正常交付後關閉通道不算異常。致命停止可能遺失未保存結果或歷史，不保證所有清理函式或錯誤回報都能執行。

### 資料有效期間

輸出器、收集判斷或其他合法使用者仍引用 task 結果時，不得提前釋放或覆寫該資料。完成保存與相關使用後，才能清理 task 私有資源；不因工作執行緒重用延續前題狀態。本場題庫則依單元 3 保留至整場工作結束且全部引用釋放後統一回收，不隨某一 task 完成提早回收。

「全部歷史一次交給輸出器」是完整求解後的責任交接，不要求額外複製整份歷史，也不把具體記憶體轉移方式定案。正式所有權與清理接線歸單元 10；異常時安全收尾及交付交錯歸單元 7，不把正常生命週期寫成致命退出時的保證。

## 五 新場次識別與不覆蓋前場

每次啟動的實驗取得新的 hash／識別碼並加入輸出檔名。相同 `experiment_name`、相同設定再次執行仍是新場次，不接續也不覆蓋上次結果；不能只用設定內容摘要，讓完全相同設定必然碰到同一份輸出。

實際輸入、task 結果、完整歷史、候選摘要、終結摘要及相互引用，都須能辨識所屬場次與 task。這不要求每份場次層資料都代表一個 task，也不指定目錄樹、hash 算法或正式欄位；命名及關聯接線由單元 10 確認。

若新檔與既有檔撞名，不得以覆寫解決；命名不使用算法 RNG，不改變任何 task 的 seed 或抽樣順序。舊檔保留政策與本場候選摘要可持續更新不同：後者更新的是同一新場次自己的資料，不能寫到前場摘要或讓引用指錯場次。

本輪不建立去重實驗、跨場快取或自動接續能力，也不宣稱新識別碼機制已完成或不存在碰撞。檔名產生、碰撞處置與正式寫入保護須由單元 10 落實及驗證。

## 六 exp 候選摘要與更新時點

候選摘要是下次 exp 優先試用舊 seed 的來源，與每個 task 的完整結果、全場統計報告是不同資料用途。摘要直接包含可對應題目的有序 seed 清單，不從平均分數、執行次數或完整歷史推算。原組別若有則保留，沒有也不猜測補造；它不覆寫下次實驗的算法選取或停止設定。

本場只將正式收錄的 seed 列入候選清單。沒有通過收集條件的嘗試，仍保存所有已完成 task 的結果與全部實際提交歷史；不能為了摘要較小而只保存合格者。下次讀取候選 seed 仍須按下次題目、算法、參數及收集條件重新求解及判斷，不沿用歷史分數或合格結論。

### 「一個 seed 輪次」的白話例子

若題目 P 選了 BSMA 2 組、BSCA 1 組，本輪 seed 是 7，這一輪就是三個 task：P／BSMA／組 0／7、P／BSMA／組 1／7、P／BSCA／組 0／7。三者的必要結果齊備後，C++ 收集功能才按本次條件判斷 seed 7 是否正式收錄。**這不是算法的一代，也不是其中一個 task 做完就算整輪完成。**

每個 seed 輪次完成判斷及所需 task 保存後，C++ 更新本場候選摘要，不等待 Python 確認。若該輪正式收錄，就按既定順序加入該題清單；若不收錄，該 seed 不加入，但相應 task 檔案仍保留。缺少判斷所需結果或必要保存未完成，不得先把 seed 列為可使用的收錄成果；具體失敗處置歸單元 7。

同題仍等目前輪次完成判斷才考慮下一 seed，收滿不再追加；輪內及跨題可並行。不因更新摘要改變原先舊 seed 順序、`repeat` 只計新 seed、避重或額度不足正常結束的規則。不同題目並行完成時，摘要更新不得互相覆蓋而遺失已確認的收錄清單；正式協調由單元 10 落實，不選定鎖或另新增背景輸出功能。

本場候選清單可在整場尚未完成時已有已確認內容；那不是整場成功、checkpoint 或自動續算的證據。中斷後哪些檔案可讀、如何區分未完成交付及錯誤原因歸單元 7；摘要／明細正式表示與路徑、統計報告歸單元 9、10。既有 replay 入口限制不自行擴成所有明細路徑規則。
