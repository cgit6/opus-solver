## 一 本輪決議與唯一重開的設定責任

使用者確認「種群大小是算法參數」，取代單元 2 原先「Python 提供整場固定種群大小」的安排。這是有明確來源的責任修正，不重開其餘選題、組號、配對、收集及程序政策。

| 項目 | 目前有效決議 |

| 單一解及特殊算法 | 單一解算法不強制新增種群參數，也不改成多次獨立求解。依題目或自身公式決定種群的算法保留其規則，不為了統一設定覆寫公式；具體移植適用性仍逐算法核對。 |
| 停止條件 | 仍由 Python 讀實驗 YAML，run、exp 各自整場一份，逐 task 套用。沒有隨種群設定移入算法 YAML，也不新增分組覆寫。 |

## 二 算法狀態與工作流程

主／內／外結構是共同責任概念，不要求所有算法採同一個 C++ 容器或函式簽章：

```text
每個 task 的算法主結構
├─ 解狀態：編碼、各項真實目標與可行性的對應
├─ 內部結構：算法參數、唯讀題目引用、工作緩存與私有搜尋狀態
├─ 外部結構：算法選擇暴露的數值、標籤、最佳解或結果集合等
└─ task 私有 RNG、迭代／評估紀錄及提交控制
```

固定問題資料由本場 C++ 題庫持有，算法取得唯讀引用，不深複製整份題庫來代表隔離。編碼、已用容量、搜尋路線、權重查表、當前與下一代緩存及 RNG 等可變或算法專用資料保持 task 私有；執行緒重用不延續上一題的搜尋狀態。

- 單一解算法可只維護一個當前解；種群算法維護多個解。當前、下一代及最佳結果可以有不同儲存，但不能讓後續更新覆寫已保留的結果。
- 二元、實數、路線與固定欄位混合編碼保留其語意，不強制扁平化或全部轉成浮點數。多目標保留各項數值與方向，不以加權和或語言內建排序偷偷選出單一最佳值。
- 搜尋罰分、排序分數等不冒充真實目標，可放內部或外部結構。最佳解或結果集合可放外部結構，仍由算法維護，不能靠歷史紀錄代替。
- `isSim` 等提交控制不決定算法必要狀態是否更新。依單元 6，外部保存整場一個開關；關閉只省略外部快照，文字標籤、編碼、真實目標與可行性仍全部保存，外部空值不補造、既存歷史不隨後續修改。正式欄位與快照格式歸單元 10。

概念流程為：取得已準備題目及已檢查參數，C++ 先保存實際輸入與 task 關聯 → 初始化 task 私有狀態與 RNG → 檢查初始化後停止條件 → 依算法原規則完成整輪操作、維護評分及最佳結果 → 在既定檢查點判斷停止 → 求解任務最終驗證 → 交 C++ 獨立輸出功能同步保存結果／歷史 → 完成相關使用及清理後接下一 task，不等待 Python 確認。算法仍可用主執行函數組織多個輔助函數；不要求對外逐步操作 API，也不把搜尋歷史 I/O 放入算法。

## 三 evaluate、增量更新與計數

問題評估一個完整候選解，提供真實目標值及是否可行；多目標提供各項目標，不先合併成單一分數。算法將結果維護在對應解狀態中。數學上可評分但違反限制的解可以有原始目標值；不能將格式損壞、計算例外或未定義目標硬填零分當正常結果。

算法可以透過完整評估或正確增量操作取得評分。例如背包移除物品時，同步更新選取編碼、扣除價值、更新受影響的負載及可行性，不必再掃完整編碼。操作策略由算法決定，數學結果須符合問題規則；不要求所有問題都提供通用增量介面。

**計數對象是完成候選解評分的事件，不是函數名稱、算術步驟或歷史提交。** 一次完整評估後，三次移除各自完成評分更新，搜尋評估計四次。多目標的一個候選解完成各項評分，仍是一次，不按目標數量各算一次；批次評估則按實際完成的候選解數計。

| 行為 | 計數要求 |
| --- | --- |
| 初始化時完成候選解評分 | 納入搜尋評估；初始化不計迭代，不表示初始化評估不計。 |
| 完整計算或增量更新，完成一個候選解的評分 | 搜尋評估加一；不因未採用該解或它不可行就取消。 |
| 僅完成增量操作的一部分 | 不能把每次扣值、加值或限制比較都各計一次完整評分。 |
| `addAct`、複製已知分數、選取最佳結果或檢查停止 | 不增加搜尋評估，不額外 evaluate。 |
| 求解結束後的驗證 | 與搜尋評估分開記錄，不回灌搜尋次數。單元 6 已定保存內容，具體欄位歸單元 10。 |

這種次數不表示各評估耗時或成本相等。計數不授權新增原算法沒有的計算或改變 RNG 次序，也不以舊程式的理論次數公式冒充實際完成次數。

`addAct` 只保存當時狀態，不修復、不補分、不訓練、不抽亂數；允許算法自訂提交時點，不新增「未評估」標記來代替開發上的對齊責任。完整小操作完成時，編碼、目標及相關狀態應同步；分階段 legacy 操作的界線在移植時核對，不插入額外評估改變搜尋。初始化檢查與開發測試驗證一致性，不要求實驗管理逐次掃描重算。

## 四 結果與停止判斷

多目標返回算法自身維護的最終集合，對各解保留編碼、各項真實目標與可行性。這不是全程找到過的所有非支配解，也不授權輸出器自行改造、裁切或任選代表解。單元 6 已定結果 JSON 與歷史 JSONL 分檔，由 C++ 同步保存；正式欄位歸單元 10，報告歸單元 9。每次實際提交仍完整保留，外部資料依整場開關，不能以最終集合取代歷史。

正常無候選解、存在但不可行、以及算法執行出錯是三種不同情況。前兩者可以如實返回；算法例外仍依既定整場停止政策處理，不能吞掉例外改報空集合。無候選解不填假分數，單元 6 保留這些區別；正式表示歸單元 10，統計歸單元 9。

單目標沿用已確認的迭代、計時及提早停止規則：初始化不計迭代；零次迭代完成原本初始化後返回；完整一輪才增加一次。初始化後及整輪完成後檢查，讀既有分數與可行性，不額外評估。計時包含算法緩存、初始化及搜尋，不含題目準備、最終驗證、結果轉換或寫檔；時間上限允許完成當前初始化或整輪後才停止。

單目標達標以可行解原始目標值依方向比較，不新增容許差或使用搜尋罰分代替。無改善仍依算法嚴格改善歷史最佳結果的規則計數，同分換解或單純重啟不歸零；不因本輪評估次數改變這些規則。

多目標首版只使用迭代或時間主要上限。共用停止設定若啟用達標或無改善，而本場含不支援的多目標算法，全部預檢失敗、不先跑單目標子集；不擅自替多目標關閉該欄位。這不縮減真正多目標搜尋及結果集合的首版要求。

例如完成第 1,000 輪時同時達到迭代上限與已知最佳值，記錄兩項原因；只記同一檢查點已啟用且成立的條件，不在停止後補跑來找更多原因。不指定原因優先序，單元 6 已確認全部保存，正式欄位與表示歸單元 10。

## 五 RNG 與必要模組的移植要求

各 task 使用自己的 seed、RNG 狀態與抽取進度，不共用可變全域亂數來源，也不以執行緒號或先前 task 的進度改變輸入 seed。執行緒可以重用，算法狀態不可串到下一題。

使用者要求在 C++ 重現目前系統所需的 RNG 及其他必要模組。這是相容性要求，不是無差別重寫整個 Python 專案；須逐算法列出會影響搜尋的依賴並核對：

- seed 初始化、亂數序列、整數／實數的抽樣轉換、上下界及抽取順序；有多個來源或重新設 seed 時也須明列，不能只換成同名產生器。
- 初始化、排序與同分處理、轉換函數、修復、增量評估、內部索引及數值計算順序等；浮點差異不能只憑 RNG 相同就宣稱不存在。
- exp 產生候選 seed 與算法持 seed 抽亂數是不同責任。固定補找起點、來源順序、避重及 repeat 計數保留，不借重現算法 RNG 重寫收集政策；本輪已盤點目前產生器及不同入口的值域，見下表；這不是統一新 seed 範圍的決議，耗盡專用機制仍排除。

問題評估也可能有隨機性，不能假設所有 objective 都不抽亂數。記錄不重抽樣；最終驗證須對應問題規則與評估上下文，不能任意再訓練／抽樣一次後要求分數相等。AI 專用上下文及隔離接線歸單元 8，不在本輪暗改既有算法的亂數分工。

| [CDELS](../../../solver/CDELS.py)、[CDELS_2](../../../solver/CDELS_2.py)、[MSVC 工具](../../../rng/msvc_legacy.py) | 兩個 adapter 丟棄外部 NumPy RNG，自建 MSVC 相容 RNG。其更新式為 uint32 狀態乘 214013 加 2531011，輸出 15 bits；mod 與除以 32767 的轉換均明列。 | 不能改成標準庫同 seed 就稱相容；低階 seed mask 與 adapter 接受範圍分開核對。Numba／packed／CVRP 變體亦不能由同一公式推定全軌跡相同。 |
| [目前 native oracle](../../../solver/native/scvrp_legacy/compat_rng.cpp) | state 與 draw_count 是程序內 static 全域值，原 oracle 以獨立執行程序隔離。 | 不能直接搬進多 task 執行緒共用；應保留單 task 序列、將狀態依既定要求隔離。這是新執行核心的移植要求，不是要求變更目前 oracle。 |

目前 seed 值域須分層解讀：一般明列入口主要拒絕負數；派生公式的輸出範圍是上述區間；CDELS／CDELS_2 adapter 明確接受 **1–4,294,967,295**，低階 MSVC 工具則可將整數 mask 成 uint32。後者不授權 adapter 接受零、負數或超界值。保留所選算法的輸入與支援檢查，不自行新增全系統統一上限、截斷或重映射；派生可能產生零而某算法不接受零的交集問題須在該收集組合接入前核對，不能視為已證明永不發生。本次首版 MKP 收集與尚未選定的 SCVRP 移植版本不可混為同一路徑。

必要模組也不只 RNG：

- MKP 的 item ranking 使用 LP／HiGHS 結果、bucket／效率／item ID 排序及失敗 fallback；相關來源在 [HSMSCA](../../../solver/HSMSCA.py)。更換 LP 數值結果或同分規則可能改變後續選物與修復。
- 種群同分排序、持續個體 ID、CTF、repair／restart、local search／path relinking 須按所選版本核對；不能只移植主更新公式。[轉換函數](../../../tools/continuous_to_binary.py)與 [Numba 轉換](../../../tools/ctf_numba.py)是現有依賴的一部分。
- 現存 BSMA／BSCA 直接匯入 HSMSCA 的共用函式；舊 `_mkp_numba_common.py` 已非現存原始檔，不以殘存 bytecode 作正式移植來源。
- 三個 MKP adapter 目前的正迭代限制、隱藏達標返回及理論評估計數，與本章已核准規則不同。初始化／整輪檢查、零次迭代及實際完成評分計數要另驗證，不能一律列為移植失敗。

### 1:1 比對原則與後續交接

「1:1 可比」要求固定且可追查的參考實作、版本、參數及操作規則，再對齊實際題目、編碼、seed／RNG 與數值環境。不能只比較最終分數，也不能以同 seed 代替下面的過程證據：

- 依相同操作邊界核對初始化、亂數抽樣轉換與順序、親本選擇、交叉／突變、修復、排序／同分與保留規則；逐輪對應編碼、各項真實目標、可行性及最終解或解集合。
- 問題公式、手算向量及解析性質作為獨立核對 evaluator 的依據，不能代替 reference 與 C++ 的搜尋過程對照。
- 已核准的停止檢查點、評估計數與結果表示差異另列驗收，先明確對應共同執行部分；不能將其當成放寬其他差異的理由。reference 的代數／額度與本平台輪數須明列映射。
- 在相同固定迭代及其餘已對齊條件下，單獨、並行、執行緒重用與 `addAct` 開關不得改變搜尋過程和結果；歷史提交量及時間、PID、路徑等非搜尋資訊分開核對。時間上限模式不要求完成相同輪數。
- 單元 10 須在實作前定稿精確版本與環境、參數清單、浮點核對規則及逐批測試計畫，再按計畫建立／執行 reference 與 C++ 對照。浮點規則須說明哪些值精確相等、哪些按何種數值標準核對，以及差異如何影響排序、選擇與逐輪狀態；不承諾所有平台 bit-for-bit 一致，不由實作者臨時猜測或放寬容許差。

### 小型手算核對，不要求隨機搜尋恰好命中

混合範例使用 `b`（二元）、`x`（nothing／multiply 類別）、`y`（整數）、`z`（實數）。令 m＝(b 為 true 時 100，否則 1) × (x 為 multiply 時 10，否則 1)：

- 混合單目標：y∈{0,1,2}、z∈[0,5]，最小化 m(y＋z)。
- 混合雙目標：y∈{−2,−1,0,1,2}、z∈[−5,5]，同時最小化 (z²＋y², m((z＋2)²＋(y−1)²))。
- ZDT1：x∈[0,1]³⁰；f₁＝x₁，g＝1＋(9／29)Σᵢ₌₂³⁰xᵢ，f₂＝g(1−√(f₁／g))，兩項都最小化。

以下數值是按上述來源公式推導的設計核對向量，不是已執行的求解測試：

| 核對 | 輸入與應得結果 | 避免的盲點 |
| --- | --- | --- |
| 混合單目標型別效果 | 固定 y＝1、z＝0.5，依 b／x 的四種組合應得 1.5、15、150、1500。 | 只測最優零分會掩蓋二元／類別轉換錯誤；還要檢查 y 保持整數、z 可帶小數與類別意義。 |
| 混合雙目標的集合比較 | b＝false、x＝nothing 時，(y,z)＝(0,0)、(0,−1)、(1,−2) 分別得 (0,5)、(1,2)、(5,0)，彼此不支配；(2,2) 得 (8,17)，被前三者支配。 | 這只是所列候選之間的關係，不稱為完整或全域 Pareto front；不能任選一個最佳分數。 |
| 混合雙目標的類別效果 | 固定 (y,z)＝(0,−1)，四種 b／x 組合得 (1,2)、(1,20)、(1,200)、(1,2000)。 | 不是只存兩欄數值；須確定哪一項目標受到哪個欄位影響。 |
| ZDT1 解析核對 | 尾端 29 個實數全為 0，首項為 0、0.25、1 時，目標依序為 (0,1)、(0.25,0.5)、(1,0)；首項 0 而尾端全 1 時為 (0,10)。 | 前三點在解析 front，最後一點被 (0,1) 支配；解析值可核對 evaluator，但不證明搜尋軌跡或收斂。 |

ZDT1 的 front 為 f₂＝1−√f₁，對應尾端變數為零；混合範例沒有在本輪推導完整 front。這三例沒有額外的一般限制式，不能冒充已驗證受約束多目標的比較策略；現有 MKP 案例繼續覆蓋正常不可行、限制與增量更新，不為這份代表清單新增問題。錯誤類別／型別不是正常不可行解。

正式驗收還須對固定小群體核對排序、同分處理、親本／子代／保留結果及全部欄位。保留算法最終集合與已提交歷史，不強迫搜尋保留全程非支配集合，也不要求有限輪數恰好命中手算點。官方範例的評估額度與 n_gen 不直接等同本平台的「初始化後完成輪數」；沿用本平台停止規則並明列映射，不新增評估次數上限。
