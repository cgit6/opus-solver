### 本次實驗名稱與併發數

一般 `run` 與 `exp` 都在各自實驗 YAML 明寫 `worker_count`，必須是正整數；缺少報錯，不補預設。它表示最多同時求解幾個 task，不是 Python 程序數。每場一個 C++ 程序、場內重用工作執行緒，同一工作鏈本機保存、相關使用及清理完成才接新 task，不等待 Python 逐 task 確認；具體配置接線歸單元 10。

實驗名稱使用本次 YAML 的 `experiment_name`。例如來源摘要屬於 `test_A`，本次 YAML 填 `test_B`，本次實驗就叫 `test_B`；原摘要名稱只作來源資訊，不覆蓋本次名稱。單元 6 另定每場新識別加入檔名，同名、同設定也不覆蓋前場；撞名不得覆寫，命名不消耗算法 RNG。具體檔名及位置歸單元 10。

外部狀態保存亦採整場統一開關，由 Python 隨本場安排提供。關閉只省略外部快照，標籤、編碼、真實目標與可行性仍完整保存，不影響算法必要更新；正式欄位名稱歸單元 10，不在本章新增別名或預設值。

以下是兩個入口各自 YAML 可使用的共用欄位片段，不是完整設定，也不是目前讀取器已支援的新功能：

```yaml
experiment_name: collect_reuse_001
worker_count: 8
```

這裡的 8 是示例，不是預設值或固定的程序／執行緒數。

### Python 管安排，C++ 讀參數並控制收集

2026-10-27 依單元 5 最新決議修正：算法 YAML 保留種群大小與其他專用值，只移出整次求解停止設定。每算法一份、歸 C++ 模組內部讀取，不要求規格與各組值分檔。這取代先前「種群由 Python 提供且整場固定」的安排，不改其他設定、配對或收集政策；正式檔案與讀取器尚未搬移。

| 設定 | 放置位置與內容 | 責任界線 |
| --- | --- | --- |
| 算法 YAML | 每算法一份，放在 C++ 模組內，保存支援的問題、編碼、目標數量、參數名稱／型別／合法範圍，以及各組算法專用實際值。 | C++ 自行讀取並依規格檢查；Python 不開檔或另維護相同專用規則。不要求另拆規格檔與數值檔，也不在 C++ 程式碼硬寫另一份相同規格來源。 |
| 實驗 YAML | `cli/run/run_cfg.yaml`／`cli/exp/exp_cfg.yaml` 保存名稱、選題、算法／組號、算法 YAML 來源路徑、seeds、併發數、收集需求及整場停止條件。 | Python 讀取安排與停止設定交 C++，不讀算法 YAML 或提供種群等專用值；不是只啟動 C++、連實驗安排也全部代讀。 |
| 算法各組實際值 | 適用的種群大小、`a`、`z`、轉換函數等保留在上述算法 YAML，不另設必須存在的獨立實際參數檔。 | 實驗人員維護數值；C++ 讀取本次選中組別，必要值完整明寫、不補預設，Python 選組不需讀值。 |
| 種群大小 | 保留在算法 YAML 的各參數組，由 C++ 讀取、檢查與記錄，各組可不同。 | Python 不讀取或提供種群數值；單一解不強加種群，依題目決定種群的算法不覆寫公式。 |
| 停止條件 | 兩入口都在各自實驗 YAML 明寫一份整場設定，由 Python 提供、C++ 檢查支援並執行。 | 每 task 分別套用，不按組／算法／題目覆寫；缺值不從算法檔或歷史補入。 |
| 收集流程 | Python 提供本次收集需求；C++ 獨立收集功能負責比較、seed 收錄、補找與追加工作。 | Python 不逐批判斷收錄，不為此讀取算法參數值；收集策略不塞進算法或問題目標函數。 |

本輪選擇的 A，指「Python 讀懂實驗安排，再交給 C++」，不是「Python 只交整份實驗設定路徑、其餘全部由 C++ 讀」的 B。這與舊派工 A／B 無關；安排一次交付、C++ 自行記錄／保存及 Python 接整場交付由單元 4、6 定案，不逐 task 登記或回報，正式訊息歸單元 10。

實驗 YAML 以明寫的檔案路徑指定 C++ 模組內的算法 YAML，不採只寫設定名稱、由 C++ 另維護名稱對照表的選項。Python 仍明列算法名稱與要用的參數組編號；不是檔內列了哪些就全部執行。每個算法的參數組依該檔內排列，從 0 開始編號；例如選 BSCA 的 0、2 組，交接、結果與報告仍是 0、2，不因只選兩組或並行完成先後重編。組號是否存在由 C++ 查檔檢查，不要求 Python 先讀值。具體子目錄、路徑解析及正式欄位仍待議，未在本輪創建名稱映射或指定新路徑。

各組所需的算法專用參數（含適用的種群大小）完整明寫，不新增「共用算法參數加各組差異」的合併規則，也不補預設。停止條件另由實驗 YAML 完整提供、整場一致；參數組不提供第二份停止額度。種群等正式欄位名稱與接線仍由單元 10 整合。

算法參數可多組比較。例如同場最多更新 5,000 輪，BSCA 可選種群 20、40 及不同 `a`、轉換函數的參數組；由 C++ 讀實際值，Python 只選原組號。保留目前 BSMA 9 組、BSCA 9 組、HSMSCA 27 組需求，不自動產生額外組別。數值與現有參數名只是說明，不是預設或正式 YAML 格式。

Python 檢查一般實驗安排與停止設定，不讀算法 YAML 或維護專用規則；C++ 讀該 YAML，檢查選中組別的必要值、型別、範圍、未知參數與支援能力，包括適用的種群參數及本次停止方式。不先轉型、補預設或忽略欄位來放行。合法研究數值由實驗人員決定；算法內部常數及依題目決定的緩存尺寸不因此變成必填實驗參數。全部必要預檢及題目準備成功才開始求解；啟動 C++ 做檢查不等於已開始搜尋。

實際執行的參數值、種群大小、停止條件及其他必要輸入仍須記錄。C++ 在算法開始前將實際題目／算法輸入及 task 關聯存成本場可追查紀錄，不只保留程序內 RAM、來源路徑或組號，也不事後重讀來源冒充當次內容。Python 保存安排與收到的整場交付，不讀參數值或即時批准 task。保存責任依單元 6，正式格式歸 10、錯誤歸 7；不增加硬體災難保證。試用舊 seed 或人工重跑仍讀本次指定設定，不自動改用歷史數值，題庫不因本輪搬移。

算法 YAML 子目錄、路徑解析、正式欄位及完整設定格式在單元 10 整合；單元 4、6 已定安排及整場交付粒度，正式訊息仍歸 10。不重問每算法同檔或種群讀取責任，不套用 replay 路徑限制。單元 5 已確認種群歸算法、多目標首版僅迭代／時間停止，三案例與 1:1 比對原則亦已接受；主要 RNG 路徑已有靜態盤點，reference、精確版本環境及正式相容性測試仍歸單元 10，不擅改原公式。

### 實驗額度與算法內部控制的界線

從算法 YAML 移出的是整次求解的實驗設定，不是把名稱含「迭代」或「停止」的欄位一律刪除：

| 類別 | 現有欄位例子 | 新設計的處理 |
| --- | --- | --- |
| 算法種群大小 | `pop_size`、`population_size` 的實際值。 | 留在算法 YAML 各組，由 C++ 讀取；不強制所有算法都有此參數。現有名稱不代表已選定正式欄位或別名。 |
| 整次求解額度 | `stop_condition` 內的迭代／時間上限與提早停止設定。 | 實驗 YAML 整場一份，各 task 分別套用，由 C++ 檢查支援並執行。 |
| 算法內部控制 | `repair_passes`、`restart_window`、`iterations_per_temperature`。 | 保留在算法 YAML；修復幾輪、何時重啟或每個溫度執行幾輪，不等於整次求解何時結束。 |
| 與舊適配器耦合的欄位 | 例如 CDELS 的 `termination_mode`。 | 正式遷移時按實際作用核對與停止接線，不只憑名稱刪除或把它當成第二份實驗停止值；本輪不改算法規則。 |

移出整次求解停止值，不表示 C++ 放棄算法對種群大小或停止方式的要求；不支援仍須在求解前拒絕。算法 YAML 的規格與數值雖同檔，維護支援規則與填寫研究數值仍是不同責任，Python 不需讀取其中任何一部分。現有註冊／適配器欄位的逐項遷移與相容接線留單元 10，不由本輪猜測映射或批次刪除。

### 入口與模式

摘要路徑仍設在 `cli/exp/exp_cfg.yaml` 的 `replay` 欄位，不是一般 `cli/run` 設定。`replay` 的值是摘要檔案路徑，不是布林開關。其用途已釐清為加速本次 seed 收集，兩種分支都要按本次收集條件判斷：

| 設定意圖 | 應執行的流程 | 不做的事 |
| --- | --- | --- |
| 未指定摘要路徑 | 從頭收集 seed，依本次條件判定是否收錄及是否繼續安排工作。 | 不自行尋找或套用舊摘要。 |
| 指定有效摘要路徑 | 對本次選中的題目先試用摘要內對應的舊 seed，重新求解與判斷；合格數不足再補找新 seed。 | 不直接採用歷史分數、歷史合格判定或全部原任務配對；不是故障自動重試或中途續算。 |

即使本次收集條件已改變，仍先試舊 seed，再用本次條件判斷；不新增自動比對歷史條件、版本鎖定或改回舊條件的流程。沒有對應舊 seed 的已選題目從頭收集，摘要中未被本次選取的題目不執行。

一般 `cli/run` 的用途不因此改變。其一般實驗與人工指定配對仍依原有設定原則討論；不因本章而增加一條「一般入口直接讀 seed-bank」的路徑。

### replay 欄位與路徑規則

| `replay` 設定 | 應執行的流程 |
| --- | --- |
| 省略欄位或填 YAML 的 `null` | 表示未指定摘要，執行 seed 收集。 |
| 空字串 `""` 或只有空白的字串 | 同樣表示未指定摘要，執行 seed 收集，不因這種空值報錯。 |
| 非空白字串 | 原樣作為摘要路徑，取得對應題目的候選 seed 加速本次收集；不得自動去除前後空白。 |
| 其他型別，例如布林、數字、清單或物件 | 報設定錯誤，不開始收集或求解，不先轉成字串繼續。 |

指定路徑時，還須遵守以下規則：

- 只接受相對路徑，以專案根目錄為起點，不以 `cli/exp/` 或其他啟動位置作為找檔起點。
- 實際指向的摘要必須位於專案內。絕對路徑即使指向專案內也不接受；相對路徑若經 `..` 或符號連結指向專案外，同樣報錯。
- 不一律禁止路徑含 `..`；判斷的是實際目標是否仍在專案內，不能只看文字沒有以 `/` 開頭就放行。
- 非空白路徑原樣查找。例如 `" output/example/summary.json "` 不得默改成 `output/example/summary.json`；若原樣找不到檔案就報錯。只有整串空白才依上表走收集。
- 檔案不存在、無法讀取、指向的不是摘要檔案或內容不合法時，指出問題，不開始求解，也不退回全新收集。依單元 6，新摘要直接保存可對應題目的有序正式收錄 seed，不能只憑平均值或執行次數推算；正式欄位及舊格式相容歸單元 10。

「有效摘要沒有某個已選題目的舊 seed」與「指定摘要本身無效」不同：前者對該題從頭收集，後者報錯，不偷偷略過來源錯誤。

這是摘要入口的路徑限制，不是對整個專案所有檔案讀取增加一套規則。摘要所連結明細的路徑規則、正式交接及可用性仍待後續單元確認，不能直接套用本節限制。

以下只示範新設計中的 `replay` 欄位，不是完整可執行的 exp 設定；現有讀取器尚不支援此欄位，本輪也不修改正式 YAML。

```yaml
# 新設計示例：執行 seed 收集；省略欄位、空字串或只有空白也相同。
replay: null
```

```yaml
# 新設計示例：從專案根目錄讀摘要，先試用對應題目的舊 seed。
replay: output/example/summary.json
```

指定有效摘要仍不代表完整實驗設定已通過：本次名稱、`worker_count`、頂層 `stop_condition` 與完整收集設定等仍須通過必要預檢；完整設定與正式介面仍待議。

### exp 統一停止條件與選填原組別

新設計由 `cli/exp/exp_cfg.yaml` 明寫一份頂層 `stop_condition`，從頭收集、試用舊 seed 及不足後補找所產生的每個 task 都使用它。每個 task 各自套用同一份停止設定，不是整場共用一個迭代或時間額度；例如設最多 5,000 輪，是每個 task 各自最多 5,000 輪，不是將 5,000 輪分給所有 task。

- 不以算法檔或歷史摘要中的停止值為來源，不提供按算法、題目或原組別覆寫，也不在本次設定缺漏時回退到這些值。
- 沿用已確認的 `stop_condition` 欄位、型別與單目標語意，見 [既有停止欄位與語意來源](../system_redesign/18_experiment_configuration_and_task_expansion.md)。本章更新的是設定來源與整場適用範圍，不改迭代計數、計時、零次初始化及提早停止的既定規則；舊文件的 run 分組停止安排不反過來覆蓋本輪決議。
- exp 的兩種模式都必須明寫停止設定及其中必要值。缺少必要值、型別錯誤、欄位互相衝突，或任一所選算法不支援時，啟動前報錯，不補預設、不先跑合法子集。
- Python 檢查實驗安排、提供並記錄本次停止額度；C++ 依既定責任檢查支援能力並執行停止判斷。這不讓 Python 另讀算法參數值；依單元 5，多目標首版只支援迭代／時間上限，啟用不支援的達標或無改善停止就整場拒絕；同一檢查點的所有成立停止原因均記錄，不額外評估。
- 這份設定只管一次求解的停止，不取代 `collects` 的合格數量目標或 `repeat` 的新 seed 嘗試上限。每題試用舊 seed 不占 repeat，補找真正嘗試的新 seed 無論合格與否都計次；跳過重複值不計次。不按單一算法 task 扣額度，也不將 repeat 當成算法迭代上限。

以下是新設計的局部示例，不是現有讀取器可執行的完整設定，5,000 也不是自動補入的預設值：

```yaml
replay: null
stop_condition:
  type: max_iterations
  max_iterations: 5000
  max_seconds: null
  stop_on_best_known: false
  max_no_improvement_iterations: null
```

這個示例表示收集時每筆 task 最多更新 5,000 整輪，不啟用達標或無改善提早停止。將 `replay` 改成有效摘要路徑時，先利用舊 seed 加速收集；試用及補找產生的 task 都使用這次同一份 `stop_condition`，不恢復歷史或算法檔的停止值。新讀取器與正式執行接線尚未實作。

摘要中的原組別資料仍為選填：有則保留，沒有也不阻擋試用舊 seed、不猜測補齊。它不決定本次選題、算法或停止條件，因此不需要為此建立原組別停止對應表，或強制新增組名、編號。選填組別的正式保存表示歸單元 10，報告用途歸 9。

本節維持取代 exp 先前「各原分組分別明寫停止條件」及「原組別資訊必填」的安排。一般 `cli/run` 也整場使用一份停止條件，不沿用按組停止。Python 從實驗 YAML 提供停止額度，C++ 檢查支援並執行，不改既有單目標語意。摘要須提供可對應題目的候選 seed；本次算法與組號由實驗 YAML 選取，實際值則由 C++ 讀指定參數檔，不還原全部原任務配對。

### 完整收集設定、預檢與實際篩選

有無摘要都必須完整提供 `collects`、`repeat`、`solvers`、`dataset_settings` 及其必要子設定，不能全部省略或只提供部分。這些欄位不只是保留來檢查，而是本次收集真正使用的設定。

這套設定須通過完整啟動前檢查，包括必要欄位、型別、合法值、引用資源及支援配對。例如本次 YAML 指定的算法、參數組、題目或比較條件已不存在，即使摘要沒有列到它，也要指出並拒絕啟動。問題及算法的專用規則仍由對應模組提供，不在 Python 另外維護一份。

檢查與執行的界線如下：

- 預檢先確認比較條件存在且設定合法，不在預檢中執行算法或拿舊結果決定收錄。正式求解後，由 C++ 獨立收集功能實際執行本次比較與收錄判斷；舊 seed 的新結果也不例外，不再回傳給 Python 逐批決定。
- 本次 YAML 決定題目、算法、參數組、收集條件及收集數量。摘要提供候選 seed，不覆寫這些選取；合格數不足時要補找，不保證嘗試一次就能收錄一個。
- 摘要與本次選取可以不同。對應題目的舊 seed 配合本次算法／參數組求解；本次新增的題目從頭收集，摘要多出的未選題目不執行。不能把不同題目的 seeds 任意互相套用。
- 摘要來源及本次共用 `stop_condition` 仍須通過必要預檢。收集設定合法不能掩蓋來源內容或停止設定錯誤，也不以歷史值修補本次缺少的設定。
- 本次 `dataset_settings` 中的組別欄位按收集規則檢查，例如必要的 `experiment-id` 不能省略；摘要原組別仍選填，缺少不能反過來以收集設定補造或要求必填。

前面的示例都是局部片段，不表示可以省略完整收集設定。順序、收滿停止追加、repeat 計數與兩種重複處理依下節已確認規則執行；具體預檢 API、通訊格式、預檢接線及資料準備方式仍待細化，不因規則已確認就視為正式介面已完成。

### 舊 seed 順序、收集上限與避重

以下為 2026-10-27 逐題確認的有效規則，適用於每題的收集流程；不是對算法內部 RNG 或候選解搜尋策略的修改。

| 項目 | 已確認規則 |
| --- | --- |
| 舊 seed 判斷順序 | 保留摘要順序，例如 `[7, 3, 9]` 就依 7、3、9 試用及判斷。依單元 4，同題 seed 7 輪次判斷完才安排 seed 3，不存在同題後輪先算完再搶先收錄的合法排程；輪內及不同題仍可並行。 |
| 收滿停止追加 | 達到本次 collects 後不再安排後續候選，不要求試完全部舊 seed。單元 4 已定同題前輪結果判斷完才安排下一輪，不提前派出後續 seed；輪內與不同題仍可並行。異常在途停止與清理歸單元 7。 |
| repeat 額度 | 只限制本題補找時真正嘗試的新 seed。舊 seed 不占額度，新 seed 合格或不合格都計一次；一個 seed 輪次內的多個算法／參數組 task 不各扣一次。 |
| 摘要候選重複 | 同一題的候選清單含重複 seed，啟動前報錯、不啟動，不自動去重；不同題使用相同 seed 不算重複。 |
| 補找撞重複 | 若產生的 seed 本題已試過，不重新求解、不扣 repeat，繼續產生下一個；已試的舊 seed、新 seed、合格與不合格者均在避重範圍內。 |
| 補找起點 | 沿用固定產生規則，從該題固定起點重新往後產生；不要求摘要保存或接續舊搜尋位置。生成位置會因跳過重複而前進，不等於實際新 seed 嘗試數。 |
| 額度用完仍不足 | 保留已得到的結果，明示該題實際收集數量與未收滿，繼續其他題目；不再替本題追加求解，不當成算法錯誤，也不冒充已收滿。 |

例如每題 `repeat: 100`，已試用 20 個舊 seed 但尚未收滿，仍可再真正嘗試最多 100 個新 seed。這是最多 120 個不同 seed 的求解輪次，不是最多 100 個，也不是 120 個單一算法 task；若先收滿就提早停止追加。從頭收集、沒有舊 seed 的題目，全部真正嘗試的 seed 都屬新 seed，受 repeat 限制。

必須分開三件事：摘要候選資料重複是輸入錯誤；補找產生碰撞是跳過與計數問題；一般 task 判重仍遵守既有規則。同一輪中各算法都使用 seed 7，不代表候選清單列了多次 7，不應誤報候選重複；正式來源格式與 task 表示仍由後續介面設計處理。

「未收滿」是預期的收集結束，不是非預期算法錯誤。原有算法錯誤停止整場、正常不可行照實回報、保存與交付錯誤分別處理的政策不變；普通收集不足不能擴大成忽略這些錯誤。

正式 seed 產生器及合法值域依單元 5 的分層盤點，由單元 10 落實驗證；seed 空間耗盡不納入本版，不列必要待決、不新增機制或補選停止政策，也不證明耗盡不可能或產生器必然終止。合法值、固定起點、避重及 repeat 計數保留。同題逐輪與跨題並行已由單元 4 定案；異常在途處置、保存及報告歸單元 6、7、9，規則模型不代替正式驗證。

| --- | --- |
| 題目範圍 | 以本次 YAML 選題為準。摘要內未被本次選取的題目不執行，本次選中的題目缺舊 seed 就從頭收集。 |

| 評分與收錄 | C++ 完整求解、最終驗證，獨立收集功能按本次條件比較並決定收錄及追加；不採歷史分數／判定。條件已變仍可試舊 seed，不自動比對歷史條件，Python 不逐批判斷。 |
| 停止條件 | Python 讀本次 exp 頂層一份 `stop_condition` 作實驗額度，交 C++ 檢查支援並執行；所有 task 各自套用，不採算法檔／歷史值，不分組覆寫。 |
| 收集設定 | collects、repeat、solvers、dataset_settings 及必要子設定完整必填、預檢且生效；repeat 只計真正嘗試的新 seed，舊 seed 與跳過重複不占額度，額度用完不足則記錄並繼續其他題目。 |

| 執行說明 | 明示這次利用舊 seed 加速收集，仍會重新求解與篩選，不是直接讀取歷史合格結果；具體顯示與紀錄格式後續細化。 |
| 輸入紀錄與重現 | C++ 在算法前保存本次實際題目／算法值與 task 關聯，seed、停止及收集安排仍須可追查；Python 保存本場安排及整場交付，不等 task ACK。內容一致由人維護，不因同一摘要就宣稱重現原結果。 |

目前收集的一輪，是同一題、同一個 seed，讓所選算法／參數組各求解一次，再將這一輪結果交給收集判斷；它可能參考已收集結果，而不是每個 task 各自算一個收錄 seed。原始碼依據見第三節。一個 seed 若對應 45 組算法參數，就可能需要 45 個 task；收集數量不等於 task 數量。新架構的正式判斷接線及規則表示仍待對應單元細化，不能由本輪另加一套比較公式。

例如摘要提供下列題目與候選 seed；舊算法與原組別只是來源資訊，不控制本次選取：

| 原組別（選填） | 題目 | 算法／參數組 | 起始 seed |
| --- | --- | --- | --- |
| 原組 A | MKP／SENT／sent02 | BSCA／0 | 3 |
| 原組 B | MKP／WEING／weing5 | HSMSCA／2 | 7 |

若本次 YAML 仍選這兩題，改選 BSCA／0 與 HSMSCA／2 兩組參數，就分別用 sent02 的 seed 3、weing5 的 seed 7 跑本次兩組，每個 seed 的新結果交給本次條件判斷；不是只執行來源中的兩筆原 task，也不把 seed 7 自動套給 sent02。若本次只選 sent02，再新增另一題 P，則 weing5 不執行，P 從頭收集；精確題目對應與來源明細格式仍待正式資料契約收斂。

## 二 責任流程與預檢邊界

以下是已確認責任流程。單元 4、6 已定一次交付本場安排、C++ 開始前自行保存實際輸入／關聯、同步保存清理後自主接題，Python 只接整場交付；不逐 task 登記／確認／通知。正式 API、訊息、預檢內部先後及執行緒接線仍由單元 10 整合。C++ 展開 task 不等於自行選題，也不等於算法已開始搜尋。

### 一般 run：指定範圍展開為逐筆 task

沿用已確認的選取與配對規則：一組一種問題，可選多個題庫，各題庫使用 all 或明列題目；一般實驗明列 seeds，不自動派生。群組指定 seeds 時取代整場清單，不合併。組內題目、算法參數組與有效 seeds 全部配對，不同組不交叉配對。停止條件仍是整場固定，不能由群組覆寫；種群大小歸所選算法參數組，不由實驗群組另填。

1. Python 讀取並檢查實驗安排，啟動新的 C++ 程序，一次提供本場選題、算法名稱、算法 YAML 來源、原組號、seeds、併發及整場額度；不開算法 YAML，也不另外生成執行用逐筆 task 清單。
2. C++ 解析本次選取、讀算法 YAML，依既定規則展開逐筆 task。各組完整配對後，對整場工作判重：同一問題類型／題庫／題目、算法、原參數組與 seed 重複，指出來源並拒絕，不合併或重複執行。Python 不另維護相同的完整 task 判重流程。
3. C++ 完成參數、支援組合、算法種群及實驗停止適用性等必要預檢，問題模組完成全部選中題目的檢查與準備。任一必要項目失敗都不開始搜尋，不先執行合法子集；混合編碼與目標數量的組合支援也必須檢查。
4. C++ 在算法開始前保存實際題目／算法輸入及 task 與本場安排的關聯，足以追查題目、算法／原組號、seed、額度及實際內容，不只留 RAM 或可變來源路徑；不逐 task 向 Python 登記或等確認，不把專用值回傳給管理端。
5. C++ 執行各 task，使用私有 RNG 與工作狀態，完成搜尋與最終驗證，再由獨立輸出功能同步保存結果 JSON 及完整歷史 JSONL。完成相關使用及清理後接下一題，不等待 Python；題庫與仍被引用結果不提前釋放。
6. Python 監督程序，接收整場終結摘要、紀錄位置及可取得錯誤，記錄並彙整；不即時接各 task 階段、不重算數學結果。缺整場回報不掃檔或依退出碼補登成功，不自動恢復歷史輸入。

例如一組選 2 題、共 3 組算法參數及 2 個 seeds，C++ 展開 2 × 3 × 2＝12 個 task。另一組獨立展開，不把兩組的選取再交叉組合。只想重跑「P／seed 3」及「Q／seed 7」時，以各自選取的組表示，不把 P、Q 與 seeds 3、7 放成同一組而多跑兩筆；選中算法／參數組仍照本次安排配對。這沿用人工精確配對能力，不新增摘要驅動的一般 run 模式。

### exp：從頭收集或利用舊 seed 加速

1. Python 讀本次 exp YAML 的名稱、併發、選題、算法／組號、算法 YAML 路徑、停止及完整收集需求，按 replay 規則提供來源安排；啟動本場 C++ 程序並一次交付，不開算法 YAML。
2. 有摘要時，啟動前須確認可對應題目的有序候選 seed 及可用來源資訊，同題候選重複報錯、不去重。C++ 收集流程只使用本次選中題目的候選，缺少就對該題從頭收集，不執行未選題目、不推算未記錄 seed；摘要的具體讀取／交接方式仍隨正式格式細化。
3. Python 檢查一般安排並協調完整預檢；C++ 讀指定算法 YAML 的規格與專用實際值，檢查算法／組號、參數合法性及支援配對，檢查各組種群等參數與本次停止額度的適用性；問題模組完成題目檢查與準備。全部通過後才允許任何 task 搜尋，不因已啟動 C++ 做檢查就算已開始求解，也不先跑合法子集。
4. C++ 收集功能建立候選 seed 輪次及 task，算法開始前保存實際輸入與原組號等 task 關聯，不只留 RAM 或來源路徑、不等 Python ACK。每題目前輪次全部所選結果完成判斷才安排下一 seed，輪內及不同題仍可並行；不要求事前列完所有未來 task。正式留存及訊息歸單元 10，故障歸 7。
5. C++ 按本次安排執行舊 seed 或新 seed 的各算法／參數組 task，使用 C++ 讀取的各組算法參數，分別套用 Python 提供的整場停止設定；完整求解、最終驗證，同步保存結果 JSON 與完整歷史 JSONL，相關使用及清理後才重用工作鏈。未收錄嘗試也完整保存。
6. C++ 獨立收集功能按摘要順序比較舊 seed 的本次結果、決定收錄，每輪判斷與必要保存後更新本場有序正式收錄清單，不等 Python。不同題更新不得互相覆蓋已收錄資料；不足從固定起點補找，跳過已試 seed 不扣 repeat，真正新嘗試合格與否都計次。收滿不再追加；額度用完不足則保留結果、明示數量並繼續其他題目，不是算法錯誤。
7. Python 監督程序，依實際收到的整場終結摘要、位置及可取得錯誤記錄並彙整，不讀算法參數重做收集判斷。C++ 本機保存與 Python 已收到整場交付不同；正式通訊及錯誤處置歸單元 7、10，不以取消逐 task 通知省略追查紀錄。

一般 task 判重不取消，也不與候選清單檢查混用：摘要同題候選重複拒絕，補找撞已試 seed 跳過、不求解、不計新嘗試。Python 檢查一般安排，C++ 負責實際工作展開與判重；預檢通過及工作階段為內部事實，單元 4、6 只要求整場對外交付，正式訊息與完整設定格式於單元 10 整合核對。

這是本次實驗主動試用舊 seed，不是故障自動重試、只補失敗 task、自動跳過成功或中途續算。歷史合格標記不能代替本次判斷；正常不可行仍按原則保存，不冒充算法錯誤。單元 6 已定候選摘要只存正式收錄 seed 並逐輪更新，部分清單不等於整場完成；中斷後有效性與故障處置歸單元 7，呈現歸 9，不宣稱已有恢復能力。

## 三 摘要的必要能力與目前實作

### 必要能力

依單元 6，新候選摘要直接保存可對應題目的有序正式收錄 seed，不能只保存統計平均值或次數，也不必讀完整歷史才取得候選清單。必要能力是「知道 seed 對應哪個題目」，不是沿原算法／參數組重建全部歷史 task；算法與參數組仍由本次 YAML 指定。正式欄位、明細關聯及路徑歸單元 10，報告歸 9。

若來源無法確定候選 seed 或其題目對應，不能只因檔名是 `summary.json` 就視為可用，也不能從平均值、次數或檔名猜測補齊。這與來源有效但不含本次新增題目的 seed 不同：後者可對新增題目從頭收集，不是摘要解析失敗後的偷偷退回。

摘要原組別仍選填、有則保留，歷史算法、分數及合格標記不控制本次選取或接受。每個 seed 輪次完成判斷及必要保存後，由 C++ 更新本場候選摘要；同題、同 seed 的全部所選算法／參數組構成一輪，不是算法的一代。未收錄嘗試的 task 結果及完整歷史仍全留；已保存部分候選清單不代表整場成功或可自動續算。中斷可用性歸單元 7，不把候選來源當完整求解紀錄，也不要求 Python 重算數學結果。

| 算法規格與專用實際值必須拆成兩份，或將專用值直接寫入 Python 讀取的實驗 YAML。 | 均不採用：每算法一份 YAML 在 C++ 模組內同存規格及各組值，含適用的種群大小，由 C++ 讀取。Python 只提供算法／組號、來源與實驗停止設定。 |
| Python 逐批比較結果、決定收錄及追加求解。 | 已取代：C++ 獨立收集功能負責比較、收錄、補找及追加，Python 提供需求並監督、彙整；不是把收集判斷加入算法或目標函數。 |
| Python 只交整份實驗設定路徑，由 C++ 讀懂全部實驗安排。 | 不採用這個設定責任 B；採 A，由 Python 讀選題、算法／組號、seeds、併發、收集需求及停止條件，再交給 C++。不與舊派工 A／B 名稱混用。 |
| 只給參數設定名稱，或自動執行參數檔內全部算法／參數組。 | 不採用；實驗 YAML 明寫來源路徑，並明列要用的算法及組號；C++ 查檔檢查存在性。 |
| 各組自行命名，或以共用參數加各組差異合併。 | 不採用；各算法依排列從 0 編號，部分選取不重編號；各組所需值完整明寫，不新增合併或缺漏補預設。 |
| 種群大小與整次求解停止值同放實驗 YAML，或兩者都交 C++ 自行讀檔。 | 兩種綁定均不採用：依單元 5，種群歸算法 YAML、C++ 讀；停止仍由 Python 讀實驗 YAML 提供、整場一致。算法內部控制不刪除。 |
| 算法能力與參數規則改為只寫在 C++ 程式碼內。 | 不採用；使用者要求仍由算法 YAML 維護，C++ 使用規格執行專用檢查，Python 不另維護相同規則。 |
| 禁止同一場比較種群大小 20、40，或每個算法只能有一組參數。 | 均不採用：種群改回算法參數，可選不同種群的合法組別，其他多組比較及三算法、45 組需求保留；停止仍整場一致。單一解不強加種群，算法原公式不覆寫。 |
| 先前 exp 依各原分組分別明寫停止，run 也可按組提供不同停止設定。 | 已取代：run、exp 都各自整場一份停止條件，不讀算法檔或歷史停止值，不提供分組覆寫；exp 的原組別仍選填。 |
| 原組別必填，或必須先決定新組名／編號。 | 仍為選填，有則保留，沒有不阻擋、不補造；它不控制本次選取或停止。正式保存表示歸單元 10，呈現歸 9。 |
| 不篩選、不補收集，原任務全部重跑。 | 本輪取代：舊 seed 重新求解，按本次條件篩選；合格數不足再補找，條件改變也可以先試舊 seed。歷史合格標記不能代替本次判斷。 |
| 有摘要時，收集設定只檢查、不參與執行，或可省略。 | 完整提供、完整預檢，而且參與本次選題、求解安排與篩選；不能全部或部分省略。 |
| 條件或數值改變就自動比對歷史、阻擋或改回舊值。 | 不採用；本次設定由人維護，舊 seed 按本次資料重新求解與判斷，不承諾重現原結果。 |
| 沿用寫死的併發數、缺少時補預設，或從摘要恢復名稱／併發數。 | 不採用；兩個入口 YAML 必填正整數 `worker_count`，本次名稱使用 YAML 的 `experiment_name`，歷史資訊不覆蓋。 |
| 欄位必填且只允許 `null` 表示收集，或遇空字串就報錯。 | 使用者選擇省略、`null`、空字串與只有空白都表示未指定摘要，走 seed 收集。 |
| 路徑以 exp YAML 所在資料夾為起點，或允許絕對路徑及專案外摘要。 | 使用者選擇專案根目錄為相對路徑起點，且實際摘要必須位於專案內；絕對路徑不接受。 |
| 自動去除非空路徑前後空白再找檔。 | 使用者選擇原樣查找；不得把不存在的原樣路徑改成另一個檔名。 |
| 把舊 seed 按數值排序，或誰先完成就先判斷。 | 不採用；舊 seed 按摘要順序逐輪推進，同題不提前派出後輪。輪內及不同題可並行，不把整場工作強制序列化。 |
| 收滿後仍要求試完全部舊 seed。 | 不採用；達標不再安排後續候選。同題逐輪、不提前派出下一 seed 已於單元 4 定案，異常在途收尾歸單元 7。 |
| 舊 seed 與新 seed 共用 repeat 額度。 | 不採用；repeat 只計真正嘗試的新 seed，舊 seed 試用不占額度。 |
| 摘要同題 seed 重複時保留第一次、自動去重。 | 不採用；屬啟動前輸入錯誤，不啟動。不是把各算法使用相同 seed 的 task 誤判成重複候選。 |
| 補找遇重複也扣一次 repeat。 | 不採用；本題已試 seed 跳過、不求解、不計次，繼續產生下一個。 |
| 補找接續原實驗最後搜尋位置。 | 不採用；從固定起點產生並避開本次已試 seed，不要求來源提供歷史搜尋位置。 |
| 新 seed 上限用完未收滿就停止整場。 | 不採用；保留結果、明示本題不足並繼續其他題目，不改算法錯誤停止整場的政策。 |

選擇這個方向，是先利用過去耗時找到的 seed，減少本次從頭搜尋的工作，但要收錄的 seed 仍須重新求解並通過本次條件。它不保證一定加速、舊 seed 一定合格或補找一次就成功，也不承諾輸入已變時重現原結果。

本輪分開的是實驗用設定與算法專用設定，而非強制規格與數值分檔：Python 決定工作範圍與停止額度，仍不需讀懂種群大小、`a`、`z` 等算法參數。C++ 讀取所指定算法 YAML 的規格及各組值，完成檢查並控制收集。明寫來源與原組號足以選取工作，實際輸入由 C++ 留存；Python 不靠讀算法 YAML 追查或比較。這是責任選擇，不是速度排名，也不改其他參數多組比較的原則。
