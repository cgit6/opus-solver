# Python 實驗管理與 C++ 執行核心設計

建立日期：2026-10-25。更新日期：2026-10-26。進度：單元 1 已確認並寫入，單元 2 尚未開始。

最新討論方向是 Python 管理實驗，C++ 提供完整執行核心，Python AI 問題模組提供資料準備、訓練與評分。C++ 執行核心不只是一個算法函數：它負責傳統問題解析與評估、有型別題庫、執行緒安排、搜尋、最終驗證、狀態紀錄與完整結果保存。

本目錄是這個新方案的討論入口。[完整討論計畫](discussion_plan.md)已進入逐單元討論；[單元 1：需求範圍與責任邊界](01_scope_and_responsibilities.md)保存本輪確認與架構評估。目前只整理設計文件，不實作正式程式。

## 首版範圍與目前進度

- MKP 接入 BSMA、BSCA、HSMSCA，以及目前三算法、45 組參數的 seed 收集與 seed-bank 重跑。SCVRP、單目標連續問題各接代表算法，具體版本後續確認。
- 上述三類的全部合法題目列入相容範圍；不合法資料明列原因，不猜測、修補或默默跳過。其他問題與算法分批接入，舊實作保留作比對依據。
- 首版支援固定欄位數的混合編碼，包含 0／1、整數、實數、類別；正式支援多目標搜尋與結果集合，且必須跑通同一題同時具有混合編碼與多目標。不能只分別支援或多存幾個分數。
- AI 跑通小型特徵篩選案例，不建立完整 AI 平台。混合排列、可變長度及條件式欄位不在本次混合編碼範圍內；不取消 SCVRP 既有路線與 transfer 狀態。

混合編碼與多目標需要調整編碼、算法能力、評估／停止、結果集合與報告等內部契約；本輪沒有證據要求推翻下述語言責任分工。正式 C++ 型別、通訊格式及新增代表算法仍待對應單元確認，不宣稱功能已完成。

本輪停止於單元 1 文件更新與核對。下一單元是「實驗設定與 task 規則」，尚未開始；沒有執行算法或大型測試。

## 設計起點

| 部分 | 已接受的責任方向 |
| --- | --- |
| Python 實驗管理 | 實驗設定、工作範圍與清單、執行監督、實際輸入與異常追查、結果摘要彙整及統計報告；seed 收集條件與是否繼續安排工作也由此負責，不重新計算解的數學結果。 |

| Python AI 問題模組 | 問題所需資料、編碼解讀、訓練與評分、最終模型相關處理；不另外管理整場實驗。 |

## 與前兩套方案的關係

- [原 system_redesign](../system_redesign/README.md)保留舊 Python 派工、共享記憶體交接及研究證據，供追查功能來源。

- 本方案不是回到原 Python 多 worker 接線，也不自動繼承完整 C++ 平台的管理、統計或入口安排。

既有 task、設定、停止、evaluate、addAct、全量歷史、最終驗證及錯誤語意的沿用對照，見 [單元 1](01_scope_and_responsibilities.md)。不能因重新整理架構就默默取消已確認功能，也不能把舊語言或程序機制直接套成新決策。新增多目標的停止、改善及解集合規則仍待細化，不能直接套用單目標比較。

本單元只更新本目錄三份設計文件，原始碼、題庫、算法、舊設計與研究證據保持原樣。後續每個單元確認後，在本目錄寫入主題結論並更新討論進度；正式修改與入口切換須等分步計畫另行核准。
