## 單元 2 企劃定案：設定、任務與收集

六項範圍為實驗入口與範圍、設定責任、任務形成、收集行為、啟動前檢查、追查資訊。以下為已定內容，不是需要重新確認的清單。

- run、exp 各自 YAML 必填正整數 `worker_count`，不補預設，表示最多同時求解幾個 task，不直接代表 Python 程序數。實驗名稱使用本次 YAML 的 `experiment_name`，不被歷史名稱覆蓋；單元 6 已定每場新識別、不覆蓋前場，具體命名及執行接線歸單元 10。
- 一般 run 由 C++ 按 Python 提供的範圍及既定配對規則展開逐筆 task、整場判重並保存工作關聯；Python 保存安排與收到的整場交付，不另外建立執行清單或逐題確認。組內全部配對、組間不交叉，C++ 不自行擴大範圍；例如 2 題 × 3 組算法參數 × 2 seeds＝12 個 task。
- 算法 YAML 每算法一份、放 C++ 模組內，同存支援的問題／編碼／目標數量、參數規則及各組 `a`、`z`、轉換函數等專用實際值。不再要求規格與數值分檔；由 C++ 自行讀取及專用檢查，Python 不讀內容或另維護相同規則。
- Python 在實驗 YAML 明寫算法 YAML 來源路徑，選算法及原組號，另讀取停止設定交給 C++，不開算法 YAML。C++ 查組號、讀專用值並檢查；不是只給設定名稱，也不是檔內組別一律全跑。
- 各算法從 0 依組別排列編號，部分選取不重編號；各組專用值完整明寫，不新增共用算法參數合併或缺漏補預設。依單元 5 修訂，種群大小也屬算法 YAML 的各組實際值，可隨參數組不同；單一解算法不強制增加種群參數。三算法、45 組需求保留。
- 摘要路徑設在 `cli/exp/exp_cfg.yaml` 的 `replay`，不是布林開關。省略、`null`、空字串或只有空白都從頭收集；有效摘要則先試用對應舊 seed，重新求解並按本次條件判斷，不足再補找。一般 `cli/run` 用途不變，不增加直接讀 seed-bank 的模式。
- `replay` 只接受以專案根目錄為起點、實際摘要位於專案內的相對路徑；絕對路徑及經 `..`／符號連結越界均拒絕。非空白路徑原樣查找，不去除前後空白。檔案不存在、不可讀或內容不合法時報錯，不偷偷退回全新收集；有效來源缺某個已選題目的 seed 則可對該題從頭收集。
- 本次實驗 YAML 決定題目、算法／組號、參數來源與收集需求；題目讀本次指定題庫，算法值由 C++ 讀指定參數檔。來源只有 A／B、本次選 A／B／C，就用舊 seed 重新跑本次三算法；來源有 P／Q、本次選 P／R，P 試舊 seed、R 從頭收集、Q 不執行。不是全部原任務原配對重跑。
- 條件已改變仍可先試舊 seed，不直接採用歷史分數或合格標記，不自動比對歷史條件或還原歷史數值。原組別仍選填，有則保留，不猜測補齊或覆蓋本次選取。
- run、exp 各自實驗 YAML 明寫一份整次求解停止設定，包括迭代／時間上限與提早停止條件。由 Python 提供、C++ 檢查適用性並執行，各 task 分別套用，不從算法 YAML 或歷史補值、不按組／算法／題目覆寫。缺必要值或不支援時，任何 task 都不得開始。
- 移出實驗額度不等於刪除算法內部控制：`repair_passes`、`restart_window`、`iterations_per_temperature` 仍留算法 YAML，不依名稱含輪次／停止就移除或改寫算法。
- 收集比較、seed 收錄、補找與追加改由 C++ 獨立收集功能控制，Python 提供需求並監督、彙整，不讀參數值作逐批判斷；這些策略不放進算法或問題目標函數。
- `collects`、`repeat`、`solvers`、`dataset_settings` 及必要子設定完整必填、完整預檢，而且實際參與本次收集。資料來源、本次設定及支援配對均須合法；預檢檢查條件是否合法，求解後再實際執行收集判斷。收集設定自身的必要組別欄位與摘要原組別選填不可混同。
- 舊 seed 按摘要順序判斷；同題前一輪所選算法／參數組結果完成判斷後，才安排下一 seed。輪內及不同題可並行；收滿不再追加，不提前派出同題後續輪次。異常在途工作處置歸單元 7，不承諾立即安全中止。
- 每題 repeat 只計真正嘗試的新 seed，不計舊 seed 試用；新 seed 合格與否都計次，不按算法 task 數扣額度。舊 20 個試完仍不足、repeat 為 100，仍可再嘗試最多 100 個新 seed。
- 摘要同題候選 seed 重複就啟動前報錯、不自動去重；不同題同 seed 不算重複。補找從固定起點開始，不接續歷史位置；撞到本題已試 seed 就跳過、不求解、不扣 repeat。候選資料與一般 task 判重分開，不把各算法共用同 seed 誤報為候選重複。
- 新 seed 額度用完未收滿，保留結果、明示數量與不足，繼續其他題目，不再替本題追加；不當成算法錯誤，也不改變真正算法錯誤停止整場的政策。
- seed 空間耗盡不納入本版處理，不新增專用機制或補定停止政策，不再列必要待議；合法值檢查、避重及 repeat 計數仍有效，不宣稱已證明耗盡不會發生。
- exp 名單直接列各題有序正式收錄 seed，由 C++ 逐輪判斷後更新；收錄／未收錄嘗試都不輸出 task 詳細檔。名單保存失敗停整場並留因。已存好且完整可讀的部分名單允許下次人工 replay 後重新測試，不自動接續或採歷史分數；正式表示歸 10、呈現歸 9。
- run 由 C++ 在算法開始前將實際題目／算法輸入及 task 關聯寫入可追查保存紀錄，不只留 RAM、來源路徑或事後重讀；exp 是否同樣正常逐 task 留存，待交接 P7-A。Python 保存本場安排及收到的整場摘要／位置／可取得錯誤，不保證即時 task 清單；全部必要檢查及題目準備通過前不得求解，也不先跑合法子集。

## 單元 3 企劃定案：問題準備與有型別題庫

- Python 提供選題及題庫來源，不解析傳統題目數值；C++ 問題模組直接讀檔、檢查、解析及預處理。同場同題的相同固定資料只準備一次，全部選中題目及其他必要預檢通過才求解；失敗不先跑合法子集。
- 題庫由本場 C++ 執行環境持有，task 唯讀共用固定資料，編碼、已用容量、搜尋路線、RNG 及算法工作緩存私有。全部工作結束且求解、輸出等使用者都不再引用後，統一釋放，不逐題提早回收或新增跨場快取。
- run 由 C++ 在算法開始前保存本次真正讀入的題目資料與 task 關聯，不只留 RAM 或路徑；exp 的正常事前留存待 P7-A。距離表等可重新計算的衍生資料不另外保存；run 完整提交歷史不變，exp 的 RAM 歷史策略待 P7-B。重跑仍讀本次指定設定，不自動恢復歷史數值。
- 混合欄位的型別、合法值、類別意義及各目標方向須保留，不強迫同一容器或全部浮點化。AI 專用資料與模型仍歸 Python AI 問題模組，可變訓練狀態不是傳統共用唯讀題庫。

## 單元 4 企劃定案：程序與工作交接

- Python 每場啟動一個獨立 C++ 程序，一次交付本場安排；C++ 場內重用工作執行緒，整場工作、保存及清理完成後關閉，不維護跨場常駐程序。
- 全部必要預檢與題目準備通過才求解；C++ 自選工作，空閒執行緒接下一個 task，不綁定題目。同一工作鏈完成本機保存、相關資料使用與清理才接新工作，不等待 Python 確認。

- 用程序間訊息交付本場安排及整場終結摘要／紀錄位置／可取得錯誤，不反覆掃檔判斷進度；題庫與完整歷史不往返搬給 Python，也不逐次傳送 addAct。管理端不保證即時知道在途 task 或原生崩潰肇因。
- 收集同題逐 seed 輪次推進，輪內 task 及不同題可並行；保留順序、額度、避重及不足政策。
- 完成交付前確認 Python 退出或通訊中斷，停止整個 C++ 求解程序，不再開始新 task、不等待在途正常算完；接受未保存資料可能遺失，不新增無訊息超時。正常結束後關閉通道不算異常。
- C++ 本機保存不因後續退出撤銷，但不等於 Python 已收到整場交付；缺完整回報只保留已知事實，不掃檔或依退出碼補登、不自動重跑。多 task 崩潰不能從未完成名單猜肇因；管理／通訊中斷不冒充算法錯誤。

## 單元 5 企劃定案：算法結構、評估與比對基準

- 種群大小改歸 C++ 讀取的算法 YAML，各參數組可不同；Python 不讀取或傳入該數值，單一解算法不強制新增種群參數。這取代單元 2 原先整場固定種群的規則，停止條件仍留實驗 YAML，整場統一、逐 task 套用。
- 主／內／外結構皆為 task 私有，題目資料唯讀引用。編碼、各項真實目標與可行性對應，搜尋罰分另存；允許正確增量更新，`addAct` 只保存不可變快照，不更新、評估或消耗 RNG。外部整場開關只省略外部快照，不影響基本歷史或算法必要更新。
- 多目標返回算法自身維護的最終解集合，不要求額外保存全程非支配集合；run 完整提交歷史不變，exp 的 RAM 歷史策略待 P7-B。首版多目標只支援迭代／時間上限，啟用不支援的達標或無改善停止時整場預檢拒絕。
- 每次完成候選解評分計一次，完整計算及增量更新都適用；一次完整評估加三次完成的移除更新共四次。最終驗證另計，記錄或複製既有分數不計。
- 正常結束可回報沒有候選解，不編造編碼或分數；與有解但不可行、算法例外分開。同一停止檢查點記錄所有已啟用且成立的條件，不另做評估。
- 移植必須核對 seed 初始化、亂數序列、抽樣轉換與抽取順序，以及初始化、排序／同分、轉換、修復和增量評估等搜尋依賴；相同 seed 不足以證明相容。各 task RNG 與工作狀態獨立。
- 在對齊條件下核對亂數、初始化及逐步搜尋；已核准的新停止檢查點、計數與結果表示另外驗證，不承諾所有舊輸出無條件相同，也不把實際移植差異一概歸因於新規則。

## 單元 6 已確認基線與本輪修訂：狀態紀錄與結果保存
