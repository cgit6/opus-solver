## 首版範圍與目前進度

- MKP 接入 BSMA、BSCA、HSMSCA，保留目前三算法、45 組參數的 seed 收集功能；exp 可由摘要先試用舊 seed、重新篩選、不足再補找，以加速本次收集。SCVRP、單目標連續問題各接代表算法，具體版本後續確認。
- 上述三類的全部合法題目列入相容範圍；不合法資料明列原因，不猜測、修補或默默跳過。其他問題與算法分批接入，舊實作保留作比對依據。
- 首版支援固定欄位數的混合編碼，包含 0／1、整數、實數、類別；正式支援多目標搜尋與結果集合，且必須跑通同一題同時具有混合編碼與多目標。不能只分別支援或多存幾個分數。
- AI 跑通小型特徵篩選案例，不建立完整 AI 平台。混合排列、可變長度及條件式欄位不在本次混合編碼範圍內；不取消 SCVRP 既有路線與 transfer 狀態。

混合編碼與多目標需要調整編碼、算法能力、評估／停止、結果集合與報告等內部契約；本輪沒有證據要求推翻下述語言責任分工。正式 C++ 型別、通訊格式及新增代表算法仍待對應單元確認，不宣稱功能已完成。

## 單元 2 已確認：舊 seed 加速收集與共用設定

- run、exp 各自 YAML 必填正整數 `worker_count`，不補預設，表示最多同時求解幾個 task，不直接代表 Python 程序數。實驗名稱使用本次 YAML 的 `experiment_name`，不被歷史名稱覆蓋；具體執行配置與同名輸出留對應單元。
- 摘要路徑設在 `cli/exp/exp_cfg.yaml` 的 `replay`，不是布林開關。省略、`null`、空字串或只有空白都從頭收集；有效摘要則先試用對應舊 seed，重新求解並按本次條件判斷，不足再補找。一般 `cli/run` 用途不變，不增加直接讀 seed-bank 的模式。
- `replay` 只接受以專案根目錄為起點、實際摘要位於專案內的相對路徑；絕對路徑及經 `..`／符號連結越界均拒絕。非空白路徑原樣查找，不去除前後空白。檔案不存在、不可讀或內容不合法時報錯，不偷偷退回全新收集；有效來源缺某個已選題目的 seed 則可對該題從頭收集。
- 本次 YAML 決定題目、算法、參數組及收集條件；題目與算法數值讀目前指定檔案。來源只有 A／B、本次選 A／B／C，就用舊 seed 重新跑本次三算法。來源有 P／Q、本次選 P／R，P 先試舊 seed，R 從頭收集，Q 不執行。不是全部原任務原配對的重跑。
- 條件已改變仍可先試舊 seed，不直接採用歷史分數或合格標記，不自動比對歷史條件或還原歷史數值。原組別仍選填，有則保留，不猜測補齊或覆蓋本次選取。
- exp 頂層明寫一份 `stop_condition`，從頭收集、試用及補找的各 task 都各自套用，不是整場共用額度。不讀算法檔或歷史停止值，不提供分組覆寫；必要值缺少或不支援時報錯、不補預設。一般 `cli/run` 分組停止不變。
- `collects`、`repeat`、`solvers`、`dataset_settings` 及必要子設定完整必填、完整預檢，而且實際參與本次收集。資料來源、本次設定及支援配對均須合法；預檢檢查條件是否合法，求解後再實際執行收集判斷。收集設定自身的必要組別欄位與摘要原組別選填不可混同。
- 舊 seed 按摘要順序判斷，不隨並行完成先後改變；收滿就不再安排後續候選，不要求試完全部來源。已派工作的收尾歸單元 4、7，不承諾立即中止或沒有在途多算。
- 每題 repeat 只計真正嘗試的新 seed，不計舊 seed 試用；新 seed 合格與否都計次，不按算法 task 數扣額度。舊 20 個試完仍不足、repeat 為 100，仍可再嘗試最多 100 個新 seed。
- 摘要同題候選 seed 重複就啟動前報錯、不自動去重；不同題同 seed 不算重複。補找從固定起點開始，不接續歷史位置；撞到本題已試 seed 就跳過、不求解、不扣 repeat。候選資料與一般 task 判重分開，不把各算法共用同 seed 誤報為候選重複。
- 新 seed 額度用完未收滿，保留結果、明示數量與不足，繼續其他題目，不再替本題追加；不當成算法錯誤，也不改變真正算法錯誤停止整場的政策。
- 摘要須能提供或明確連到可對應題目的候選 seed，不從平均值或執行次數推算。本次完整 task 紀錄仍須保存，候選來源不代替求解紀錄；正式摘要格式、選填組別、明細路徑、保存時點及中斷可用性留單元 6、7、9，入口路徑限制不自動擴及明細。
