## 二 責任分工

「問題、算法、任務、紀錄、輸出」是責任，不要求各自成為程序或服務。語言分工也不決定通訊方式。

| 責任 | 負責的工作 | 不負責的工作 |

| C++ 狀態紀錄子模組 | 透過 `addAct` 保存當時的狀態快照，維持解、評分與外部狀態對齊。 | 不評估、不修復、不訓練、不消耗 RNG，不替算法補算過期分數。 |

一個 task 仍是一個問題實例、一個算法、一組算法參數、一個 seed 的一次完整求解。多目標的一項分數、算法中的一個候選解、AI 的一次訓練或一折交叉驗證，都不因此變成另一個外層 task。

固定題目資料共用；各 task 的編碼、真實目標值、可行性、RNG、工作緩存、最佳結果及歷史獨立。管理與求解分程序、傳統求解程序內多執行緒的方向保留；具體呼叫、AI 所在程序與資料所有權在後續單元收斂。

## 三 責任流程

以下是誰處理什麼的流程，不是已定案的呼叫 API、通知順序或程序圖。原始檔由誰讀取哪些內容、如何留下實際輸入，於單元 2 至 4 細化；不能由這些箭頭推定 Python 已讀好全部題目陣列。

### 傳統問題：一題 MKP

1. Python 根據實驗設定選取題目、算法、參數組及 seed，安排工作範圍；開始執行前須留下實際輸入及執行關聯，具體來源與保存方式於單元 2 至 4 收斂。
2. Python 檢查實驗安排；C++ 問題模組與算法分別檢查專用題目輸入及參數。全部選中題目準備成功、必要預檢通過後，才開始任何 task 的算法搜尋。
3. C++ 共用固定題目資料；每個 task 建立自己的算法工作狀態與 RNG，不深複製整份題庫來代表隔離。
4. 算法搜尋，使用 C++ 問題評估或正確的增量更新；需要紀錄時呼叫純紀錄的 `addAct`。
5. 求解任務依問題規則驗證最終編碼、目標值與可行性。最終不可行可以正常完成，照實標示。
6. 結果與全部實際提交歷史一次交給 C++ 獨立輸出功能同步保存；不是要求完整歷史先搬回 Python。仍在使用的資料不得提前回收。
7. Python 接收摘要、位置與實際取得的完成／異常事實，再彙整報告。同一工作鏈保存、交接與清理完才接下一題，不要求其他健康工作鏈一起等待。

準備失敗時不先執行其餘題目。算法錯誤停止整場，涵蓋其他算法與在途 task，已成功保存結果保留、不自動重跑；普通不可行、保存錯誤及未知退出須分開處理，不能只因都由 C++ 回報就歸成算法錯誤。安全停止與原因留存細節歸單元 7。

### AI 問題：小型特徵篩選

1. Python 實驗管理選取特徵篩選題目設定、可支援的算法、參數及 seed。
2. Python AI 問題模組準備固定資料、特徵意義、編碼規則與評分方式，提供開始搜尋所需的資訊。資料切分、前處理與評估隨機性在單元 8 細化。
3. C++ 算法建立候選解，例如一組表示選取哪些特徵的 0／1 編碼。
4. Python AI 問題模組解讀候選解，按該題規則訓練或評分，將結果交回 C++；算法據此繼續搜尋。
5. 求解任務依 AI 問題規則完成最終驗證及必要產物處理。不是任意重訓一次後要求分數與先前完全相同。
6. C++ 獨立輸出功能保存求解結果與完整歷史；AI 模型的必要處理由 AI 問題模組提供，模型檔案與結果的具體交接、位置及所有權歸單元 6、8。
7. Python 實驗管理接收摘要與位置，彙整報告。

這裡不選擇嵌入 Python、獨立評估程序或每候選解啟動腳本；也不將每次訓練誤當另一場外層實驗。AI 案例的目的是實際驗證交接，不是只在文件預留一個空介面。

### seed 收集：三算法與 45 組參數

Python 安排一批候選 seed 的求解工作，逐筆附上本次 exp 同一份停止設定 → C++ 各自執行、驗證、保存各 task 並提供結果摘要 → Python 比較各組結果及目前收集狀態 → 決定是否收錄 seed、是否需要下一批 → 持續到收集流程的停止條件成立。

這與一般實驗明列 seeds 的用途不同：一般實驗不因此恢復自動派生 seed；收集工具也不能被一般入口的固定 seed 清單規則取消。收集工具可能依前批結果追加工作，所以單元 4 不能假定整場所有 task 一開始就已全部確定；這仍不等於已選逐題派工。exp 共用停止設定只管每筆求解，各 task 各自計數或計時，不是整場共用額度，也不取代收集數量與嘗試上限。

目前舊 seed-bank 重跑工具會讀保存的算法設定，這只是舊程式現況。新方案已於單元 2 改為下述 exp 利用舊 seed 加速收集；一般 `cli/run` 的實驗與人工指定配對用途不變，也不因此自動採用歷史數值。舊工具保留，正式相容與遷移歸單元 10。

### exp 利用舊 seed 加速收集

Python 讀取本次 exp YAML 與可選來源 → 完整預檢，摘要同題候選重複報錯，全部選中題目準備成功 → 對有來源的題目先試對應舊 seed，沒有的題目從頭收集 → C++ 依本次停止設定完整求解、最終驗證與保存 → Python 按摘要順序判斷舊 seed，合格才收錄，不足從固定起點補找 → 收滿不再追加，或新 seed 額度用完記錄不足並繼續其他題目 → 彙整實際結果與來源。這是責任流程，不預先選定預檢 API、派工或在途收尾接線。

`replay` 是路徑而非布林開關；省略、`null`、空字串與只有空白都走收集。指定時只接受以專案根目錄為起點、實際摘要位於專案內的相對路徑；非空白路徑原樣查找，其他型別、絕對路徑、越界、無法讀取或摘要資訊不足時報錯，不退回收集。

摘要提供可對應題目的候選 seed，不是本次全部原任務配對的執行指令。本次 YAML 的算法與參數組可以不同；例如來源為 A／B，本次選 A／B／C，就用舊 seed 重新求解本次三算法。若來源有 P／Q、本次選 P／R，P 先試舊 seed，R 從頭收集，Q 不執行。原組別仍選填，有則保留，不補造、不覆寫本次選取或停止設定。

有無摘要都完整提供 `collects`、`repeat`、`solvers`、`dataset_settings` 及必要子設定，完整預檢後實際用於本次收集；本次選取有錯即拒絕啟動，不因來源沒有列到該資源而忽略。舊 seed 重新求解與篩選，條件改變也先試用，不新增歷史條件自動比對；歷史分數或合格標記不能代替本次判斷。合格數不足要補找，不代表每次嘗試都合格。

舊 seed 保留摘要順序判斷，不隨求解完成先後變動；這不要求求解必須序列執行。每題 repeat 只計真正嘗試的新 seed，不計舊 seed 試用或補找碰撞的跳過；新 seed 合格與否都計次，不按算法 task 數扣額度。例如舊 20 個試完仍不足、repeat 為 100，最多仍有新 100 次。收滿停止追加，不要求試完全部舊 seed，已派出工作的收尾歸單元 4、7。

同題摘要候選重複屬啟動前錯誤、不自動去重；不同題使用同一 seed 不算重複。補找從固定起點產生，不接續歷史搜尋位置；撞到本題已試 seed 就跳過、不求解、不計次。這與一般 task 判重分開，也不將同一輪不同算法使用同一 seed 當成候選重複。

新 seed 額度用完未收滿，保留結果、明示數量與不足，繼續其他題目，不把它當成算法錯誤或冒充滿額。非預期算法錯誤停止整場、正常不可行及保存／交付錯誤的既有分類不變。

本次收集設定自身的必要組別欄位仍按收集規則檢查；摘要原組別選填不變，不能混用。預檢檢查比較條件存在且合法，正式求解後再實際呼叫本次收集判斷；Python 不因此重新計算候選解的目標函數。有效來源缺某題舊 seed 可對該題從頭收集，但指定來源無效仍報錯，不偷偷退回。

run 與 exp 都由各自 YAML 必填正整數 `worker_count`，不補預設，表示最多同時求解幾個 task，而不是 Python 程序數。實驗名稱取本次 YAML 的 `experiment_name`；摘要原名稱只作來源，不覆蓋本次名稱。實際程序／執行緒配置歸單元 4，同名輸出政策歸單元 6、9。

新 exp 在頂層明寫一份 `stop_condition`，收集及重跑都讓每筆 task 各自套用。不以算法檔或歷史摘要中的停止值為來源，不提供按算法、題目或原組別覆寫；沿用已確認的停止欄位與單目標語意，必要值缺少或算法不支援時，啟動前報錯、不補預設。這取代 exp 先前的原分組停止安排；一般 `cli/run` 的分組停止設計不受影響。

本節七項規則已確認；正式 seed 產生器、合法值域及耗盡邊界、並行在途收尾與報告格式仍待對應單元細化。單元 2 下一小節回到完整設定格式與算法支援／預檢查詢；摘要格式、原組別表示、明細路徑及中斷可用性留單元 6、7、9，入口限制不自動擴及明細。現況尚無新摘要試用流程，exp 併發數寫死 11、run 由命令列指定，exp 停止值仍取算法 YAML。主題文件保存 12 項已通過的同步規則模型，不代表正式程式、產生器或並行派工已驗收。

## 四 混合編碼與多目標為何會影響設計

混合編碼描述「解包含哪些型別的值」；多目標描述「每個解有幾項評分」。兩者是不同維度，首版也須驗證它們能同時出現。

例如同一個解含「備援啟用＝1、機器數量＝3、壓力＝1.7、材料＝鋼」，評分同時有「成本、產量」。這只是交接示意，不是已選定的測試題或數學公式。材料種類不能被默認成具有大小距離意義的連續數字；類別若採編號表示，也要保留其定義。

### 現有程式的靜態依據

## 六 選擇理由及未採用安排

- 首版不等所有既有算法都移植後才切換，而先完成已選題類；但 MKP 必須保留 seed 收集真正依賴的三算法，不能以一個代表算法取代既有比較需求。
- 題庫範圍不只取少量展示題，而涵蓋上述三類全部合法題目；逐題與逐批驗證安排歸單元 10，不代表本輪開始跑全部題庫。
- AI 不只停留在紙面介面，也不立即建完整平台：以小型特徵篩選實際接線檢查共同邊界。
- 混合編碼不是延後功能；多目標也不是只在 metadata 多存幾個數字。兩者都須真正求解，並以組合案例檢查相容。
- 不要求每個既有算法都支援所有編碼與目標數量；不支援時明確拒絕，不強制轉型或偷偷把多個目標合成單一分數。
- 不以新需求直接選定模板、繼承、`std::variant`、通用浮點精度或特定演算法；邏輯契約與熱路徑布局需在對應單元比較。
