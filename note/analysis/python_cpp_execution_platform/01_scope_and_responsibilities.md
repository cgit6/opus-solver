## 三 責任流程

以下是已定案的責任流程；程序圖與整場交接見單元 4，保存與交付粒度依單元 6，正式通訊工具與訊息表示仍歸單元 10。題庫及算法專用值由 C++ 直接讀取，停止設定由 Python 提供。C++ 在算法開始前，將實際輸入及 task 關聯存成本場可追查紀錄，不能只留程序內 RAM 或路徑，不事後重讀、不另存可重建衍生表；正式格式歸單元 10，失敗交付歸 7，不新增硬體保存保證，也不能由箭頭推定 Python 已讀好數值。

設定責任保留 A：Python 讀懂實驗安排，不是只交整份實驗 YAML 路徑讓 C++ 全部代讀；算法專用值與規格同存於 C++ 模組內每算法一份 YAML，由 C++ 自行讀取。種群大小保留在算法 YAML、由 C++ 讀取，各參數組可以不同；整次求解停止設定由 Python 提供。A 與舊派工選項無關；本場安排一次交付的決議另見單元 4。各組專用值完整明寫、按原排列從 0 編號，部分選取不重編號，不新增共用算法參數合併或預設。

### 傳統問題：一題 MKP

1. Python 根據實驗 YAML 的選題、來源、算法／組號、seeds、併發及整場停止設定安排本場，啟動新的 C++ 程序並一次交付；不讀算法 YAML 或傳統題目數值。run、exp 各自整場固定停止條件，正式欄位及訊息表示歸單元 10。
2. C++ 讀指定算法 YAML 的規格與專用值，依 Python 選取展開一般 run 的逐筆 task 並判重，檢查算法／組號、參數及支援組合，確認各組算法參數合法且支援本次停止額度；問題模組直接讀取、檢查、解析並預處理全部選中題目。全部通過才求解，不先跑合法子集。組內配對、組間不交叉，不因展開責任移動而擴大實驗範圍。
3. 準備完成為 C++ 內部階段，本場題庫持有固定資料、task 唯讀使用。C++ 選取工作，先留存實際輸入與 task 關聯再開始，不向 Python 逐 task 登記或通知；各 task 建立私有算法狀態與 RNG，不深複製整份題庫來代表隔離。
4. 算法搜尋，使用 C++ 問題評估或正確的增量更新；需要紀錄時呼叫純紀錄的 `addAct`。
5. 求解任務依問題規則驗證最終編碼、目標值與可行性；內部求解完成不等於保存完成。最終不可行或正常無候選可以如實完成，不造編碼或分數；算法例外不能改報無候選。
6. 結果與全部實際提交歷史一次交給 C++ 獨立輸出功能同步保存為 JSON／JSONL，不搬回 Python；仍在使用的資料不得提前回收。
7. 同一工作鏈完成本機保存、相關使用與 task 私有資料清理後即接下一題，不等待 Python 確認、不要求其他工作鏈一起等待，也不在此回收共用題庫。
8. 整場工作、保存及清理完成，所有使用者不再引用後，C++ 統一釋放本場題庫，向 Python 交付整場終結摘要、位置及可取得錯誤，正常關閉程序；Python 記錄收到的交付並彙整，不逐題回收或跨場常駐。

準備失敗不先執行其餘題目，記錄可取得的輸入與錯誤，清理本次資源；致命退出的具體偵測、終止與交付歸單元 7、10，不保證取得完整原因。算法錯誤停止整場，已保存結果保留、不自動重跑；正常不可行、保存錯誤、管理／通訊中斷及未知退出分開處理。完成交付前確認管理退出或斷線時停止整個 C++ 程序，不等在途正常算完；接受未保存結果可能遺失，不新增無訊息超時。本機保存與 Python 已收到整場交付不同；缺完整回報不掃檔或依退出碼補登成功。Python 不保證知道當下 task 清單，不從任何未完成紀錄推定崩潰肇因。

### AI 問題：小型特徵篩選

1. Python 實驗管理選取特徵篩選題目設定、算法／組號、算法 YAML 來源及 seed，提供整場停止設定；算法專用值由 C++ 讀取。這不將 Python AI 問題模組準備資料的責任移給管理端。
2. Python AI 問題模組準備固定資料、特徵意義、編碼規則與評分方式，提供開始搜尋所需的資訊。資料切分、前處理與評估隨機性在單元 8 細化。
3. C++ 算法建立候選解，例如一組表示選取哪些特徵的 0／1 編碼。
4. Python AI 問題模組解讀候選解，按該題規則訓練或評分，將結果交回 C++；算法據此繼續搜尋。
5. 求解任務依 AI 問題規則完成最終驗證及必要產物處理。不是任意重訓一次後要求分數與先前完全相同。
6. C++ 獨立輸出功能依單元 6 保存求解結果與完整歷史；AI 模型的必要處理由 AI 問題模組提供，模型檔案與結果的具體交接、位置及所有權歸單元 8、10。
7. Python 實驗管理接收整場終結摘要、位置及可取得錯誤，彙整報告；AI 評分呼叫不是外層逐 task 進度通知。

這裡不選擇嵌入 Python、獨立評估程序或每候選解啟動腳本；也不將每次訓練誤當另一場外層實驗。AI 案例的目的是實際驗證交接，不是只在文件預留一個空介面。

### seed 收集：三算法與 45 組參數

Python 提供選題、算法／組號、算法 YAML 路徑、收集需求及本次停止設定 → C++ 讀同檔規格與專用值，完成全部預檢與題目準備 → C++ 先留各 task 實際輸入及關聯，再求解、驗證及保存 → 收集流程比較、決定收錄，每輪必要保存後更新本場候選摘要，再依政策補找與追加 → 收滿或新 seed 額度用完 → Python 接收整場終結摘要與位置，記錄並彙整。

這與一般實驗明列 seeds 不同：一般實驗不恢復自動派生，收集也不被固定 seed 清單規則取消。Python 一次交付本場安排，C++ 按各題前輪判斷追加工作，每個新增 task 同樣先留實際輸入與關聯再開始、不等 Python；不能要求開始時列完所有未來候選。exp 停止額度只管各 task，不取代收集數量或新 seed 嘗試上限。

目前舊 seed-bank 重跑工具會讀保存的算法設定，這只是舊程式現況。新方案已於單元 2 改為下述 exp 利用舊 seed 加速收集；一般 `cli/run` 的實驗與人工指定配對用途不變，也不因此自動採用歷史數值。舊工具保留，正式相容與遷移歸單元 10。

### exp 利用舊 seed 加速收集

Python 讀本次 exp 安排與 replay 來源選擇，一次交付本場 C++ 程序 → 完整預檢及題目準備，摘要同題候選重複拒絕 → 各題先試舊 seed，沒有來源的從頭收集 → C++ 先留 task 實際輸入與關聯，再求解、最終驗證與同步保存 → 收集功能依摘要順序完成本題本輪判斷及必要保存，更新本場候選摘要，仍不足才安排下一輪 → 收滿不追加，或新額度用完記錄不足，其他題仍可繼續 → Python 接收整場終結摘要、位置及可取得錯誤，彙整報告。正式來源表示與訊息歸單元 10，異常在途收尾歸 7。

`replay` 是路徑而非布林開關；省略、`null`、空字串與只有空白都走收集。指定時只接受以專案根目錄為起點、實際摘要位於專案內的相對路徑；非空白路徑原樣查找，其他型別、絕對路徑、越界、無法讀取或摘要資訊不足時報錯，不退回收集。

摘要提供可對應題目的候選 seed，不是本次全部原任務配對的執行指令。本次 YAML 的算法與參數組可以不同；例如來源為 A／B，本次選 A／B／C，就用舊 seed 重新求解本次三算法。若來源有 P／Q、本次選 P／R，P 先試舊 seed，R 從頭收集，Q 不執行。原組別仍選填，有則保留，不補造、不覆寫本次選取或停止設定。

有無摘要都完整提供 `collects`、`repeat`、`solvers`、`dataset_settings` 及必要子設定，完整預檢後實際用於本次收集；本次選取有錯即拒絕啟動，不因來源沒有列到該資源而忽略。舊 seed 重新求解與篩選，條件改變也先試用，不新增歷史條件自動比對；歷史分數或合格標記不能代替本次判斷。合格數不足要補找，不代表每次嘗試都合格。

舊 seed 保留摘要順序判斷；同題逐輪，輪內 task 與不同題可並行，不把整場改為序列求解。repeat 只計本題真正嘗試的新 seed，不計舊 seed 或補找碰撞，新 seed 合格與否都計次，不按算法 task 數扣額度。舊 20 個試完仍不足、repeat 為 100，仍可再試最多新 100 次。收滿不再追加、不要求試完全部來源，也不提前派出同題後續輪次；異常在途工作處置歸單元 7。

同題摘要候選重複屬啟動前錯誤、不自動去重；不同題使用同一 seed 不算重複。補找從固定起點產生，不接續歷史搜尋位置；撞到本題已試 seed 就跳過、不求解、不計次。這與一般 task 判重分開，也不將同一輪不同算法使用同一 seed 當成候選重複。

新 seed 額度用完未收滿，保留結果、明示數量與不足，繼續其他題目，不把它當成算法錯誤或冒充滿額。非預期算法錯誤停止整場、正常不可行及保存／交付錯誤的既有分類不變。

本次收集設定自身的必要組別欄位仍按收集規則檢查；摘要原組別選填不變。預檢須確認比較條件存在且合法，正式求解後由 C++ 收集功能實際判斷，不將它放進算法或目標函數；Python 不讀算法參數比較，也不重算數學結果。有效來源缺某題可從頭收集，指定來源無效則報錯、不偷偷退回。

run 與 exp 都由各自 YAML 必填正整數 `worker_count`，不補預設，表示最多同時求解幾個 task，而不是 Python 程序數。名稱取本次 `experiment_name`，不被歷史名稱覆蓋。單元 6 另定每場新識別加入檔名，同名、同設定也不覆蓋前場，撞名不得覆寫且命名不消耗算法 RNG。單元 4 已定每場 C++ 程序與可重用工作鏈；具體命名及執行緒接線歸單元 10。

run、exp 現在都由各自實驗 YAML 提供一份整場停止條件，各 task 分別套用額度，不提供按分組、算法或題目覆寫。exp 沿用頂層 `stop_condition`，收集、試用與補找共用本次設定；不讀算法檔或歷史停止值。既有停止欄位與單目標語意保留，必要值缺少或算法不支援時，啟動前報錯、不補預設；這也取代先前一般 `cli/run` 按組停止的安排。

算法 YAML 每算法一份、放 C++ 模組內，保留能力規格及各組實際值（含適用的種群大小），不再要求分檔；Python 只指定來源與原組號，不開檔。整次求解停止設定放實驗 YAML，由 Python 提供；種群大小依單元 5 改回算法參數，各組可不同。修復輪次、重啟窗口與每溫度輪次仍是算法內部參數，不依名稱刪除。三算法 45 組需求保留；單一解不強加種群，依題目決定種群的算法不覆寫原公式。

上述設定責任及組號規則已定；單元 4、6 已定安排一次交付、C++ 自行記錄及保存、Python 只接整場交付，不逐 task 登記或通知。exp 候選摘要直接列各題有序正式收錄 seed，未收錄嘗試仍全量保存；部分候選清單不代表整場成功。算法 YAML 子目錄、正式欄位／訊息、序列化及完整設定於單元 10 整合；產生器、異常收尾及報告由對應單元處理。正式 YAML 未搬移，新 C++ 機制未實作，文件案例不是正式驗收。

## 四 混合編碼與多目標為何會影響設計

混合編碼描述「解包含哪些型別的值」；多目標描述「每個解有幾項評分」。兩者是不同維度，首版也須驗證它們能同時出現。

例如同一個解含「備援啟用＝1、機器數量＝3、壓力＝1.7、材料＝鋼」，評分同時有「成本、產量」。這只是交接示意，不是已選定的測試題或數學公式。材料種類不能被默認成具有大小距離意義的連續數字；類別若採編號表示，也要保留其定義。

## 六 選擇理由及未採用安排

- 首版不等所有既有算法都移植後才切換，而先完成已選題類；但 MKP 必須保留 seed 收集真正依賴的三算法，不能以一個代表算法取代既有比較需求。
- 題庫範圍不只取少量展示題，而涵蓋上述三類全部合法題目；逐題與逐批驗證安排歸單元 10，不代表本輪開始跑全部題庫。
- AI 不只停留在紙面介面，也不立即建完整平台：以小型特徵篩選實際接線檢查共同邊界。
- 混合編碼不是延後功能；多目標也不是只在 metadata 多存幾個數字。兩者都須真正求解，並以組合案例檢查相容。
- 不要求每個既有算法都支援所有編碼與目標數量；不支援時明確拒絕，不強制轉型或偷偷把多個目標合成單一分數。
- 不以新需求直接選定模板、繼承、`std::variant`、通用浮點精度或特定演算法；邏輯契約與熱路徑布局需在對應單元比較。
