## 二 從選題到釋放的責任流程

1. **Python 提供安排。** 根據實驗設定提供本場選題範圍與題庫來源；不開啟傳統題目檔解析其數值。算法名稱、原參數組、算法 YAML 來源及實驗額度仍依單元 2 交付。
2. **C++ 找題並檢查。** 依安排找出選中的題目，交給對應問題模組讀取、檢查及解析；不能擴大選取範圍，也不能略過選中但讀取失敗的題目。
3. **問題模組準備資料。** 建立符合該題型意義的資料物件，計算固定衍生資料。同場同題的相同固定資料只準備一次，不因多個 seed、算法或參數組重做同一份準備。
4. **C++ 題庫持有，等待全部備妥。** 全部選中題目與其他必要預檢均通過，才開始任何求解。啟動 C++ 讀檔、檢查或準備，不等於已開始算法搜尋；也不是要求載入專案內所有未選題目。
5. **先留下可追查輸入，再由各 task 唯讀使用。** C++ 在算法開始前，將本次實際輸入與 task 關聯留下本場可追查的保存紀錄，不能只留在程序記憶體中。各 task 取得對應題目的唯讀資料，建立自己的編碼、RNG、搜尋狀態及工作緩存；不藉共用題庫共享可變搜尋狀態，也不等待 Python 逐題確認。
6. **整場結束後統一釋放。** 求解、需要題庫的本機結果／歷史保存與其他使用及清理全部完成，所有使用者都不再引用後，才釋放本場題庫。單 task 完成相關使用與清理後可接下一題，不等待 Python 收到整場交付；單 task 的工作緩存清理，與整場題庫回收是兩件事。

本流程確定準備與搜尋的先後閘門、責任方及持有範圍，不指定函式簽章、通知格式、準備工作的執行緒配置或底層容器。舊方案的隔離預處理 worker、先算再搬共享記憶體與 Python 持有共享區，不作本方案的必要接線。

### 沿用輸入檢查規則

- 必要欄位須齊全；選中題目含問題模組不認識的欄位時報錯，不先刪欄位或忽略後繼續。
- 問題模組檢查數值型別、尺寸及該題型的合法輸入規則。例如宣告 3 件物品卻只有 2 個價值，不能當成合法題目。
- 要求整數的欄位只接受整數，不把小數、字串或布林值先轉成整數。浮點欄位接受浮點輸入及能精確表示於目標型別的整數，不接受字串或布林值；整數轉換會失真或超出欄位範圍時拒絕，不在本章指定統一精度。
- 不能先轉型掩蓋不合法的原始輸入再宣稱通過。合法研究數值不由系統擅自修正。

這是題目輸入合法性的檢查，不是候選解的可行性判定，也不保證人填的研究數值符合其原意。算法參數（含適用的種群大小）、能力組合、實驗停止適用性及重複 task 的預檢仍依單元 2、5 執行，不因題目準備通過而省略。

### 準備失敗

任一選中題目讀取、檢查、解析或預處理失敗，不執行合法子集。記錄出問題的題目、可取得的實際輸入及錯誤資訊，清理本次準備資源；檔案根本未能讀入時，不能假裝已取得完整內容。

[單元 4](04_processes_and_work_handoff.md)與單元 6 已確認每場新建 C++ 程序、由 C++ 內部完成準備及工作流程，僅向 Python 交付整場終結資訊；管理／通訊中斷停止整個求解程序。程序致命退出的偵測、終止方式及錯誤交付細節歸單元 7、10。以上是應有處置，不宣稱致命退出時一定能執行清理函式、留下完整輸入或取得根本原因；Python 不保證有即時 task 清單，只記錄實際取得的事實，不靠掃檔或退出碼補登成功。正常不可行解不是題庫準備失敗，求解與保存錯誤的分類也不因此合併。

## 三 共用固定資料與 task 私有資料

| 情境 | 題庫可共用的固定資料 | task 私有資料 |
| --- | --- | --- |
| MKP | 物品價值、重量、容量及題目維度等定義。 | 選取編碼、目前分數、已用容量、修復過程、搜尋最佳解與 RNG。 |
| SCVRP | 座標、需求、題目規定的固定路線與容量，以及依題目規則建立的固定距離表等。 | 搜尋中的路線、transfer 選擇、目前剩餘容量、局部搜尋緩存及 RNG。題目固定路線不等於算法正在改動的搜尋路線。 |
| 連續問題 | 維度、各維範圍、目標／限制定義及方向等固定資訊。 | 候選向量、運算子狀態、搜尋分數、評估隨機狀態及工作緩存；不假設所有評估皆無隨機性。 |
| 固定欄位混合編碼、多目標 | 各欄型別、合法值、類別意義，各項目標的定義、數量及方向。 | 混合候選解、各解的目標值與可行性、算法維護的結果集合及比較工作資料。 |

同一題被多個算法、參數組或 seed 使用，不改變固定題目資料的意義。**依算法參數或搜尋進度產生的工作緩存仍歸 task 私有**，例如算法為加速抽選而建立的權重查表；不能只因它叫「緩存」，或某次執行中不再修改，就放入共用題庫。

準備一次的對象是同題的相同固定資料，不是不同題只要名稱相似就合併，也不是自動建立跨場快取。如何查找題目、表示引用及落實所有權，是後續技術工作，不能改變上述界線。

### 有型別不等於所有資料放同一個容器

混合編碼須保留 0／1、整數、實數及類別各自的合法值與意義。類別若採編號表示，也須知道編號代表什麼，不能將編號間的數值距離默認成問題意義。多目標須保留每項目標及其方向，不把它們偷偷合成一個分數。

這些是題目語意要求；本章不指定 C++ 型別名稱、模板、繼承、陣列布局或統一浮點精度，也不強迫所有題型使用同一容器。單元 5 已確認返回算法自身維護的最終解集合、多目標首版僅迭代／時間停止，以及三類代表案例、操作與比較規則；reference 與正式支援驗證歸單元 10，不用題庫型別代替算法支援。

### 唯讀與有效期間

算法不得修改共用題目資料；需要更新的容量、路線或其他狀態應在自己的工作資料中維護。介面、底層存取及引用生命週期必須共同落實這項要求，不以 `const`、`struct` 或「唯讀」名稱宣稱安全性已驗收。

即使所有求解都完成，只要輸出等使用者仍引用題庫，也不能釋放。反之，某題暫時沒有使用者，但整場尚未結束，也不依本版政策逐題提前回收。這接受整場期間保留全部已準備題目所需的記憶體，不自動加入淘汰、重載或背景搬運機制。

## 四 保存實際輸入，不另存衍生表

| 資料 | 執行期用途 | 留存政策 |
| --- | --- | --- |
| 本次真正讀入的題目資料 | 依問題規則檢查、解析並建立題目物件。 | 由 C++ 在算法開始前保存實際內容與 task 關聯，不能只有可變動的檔案路徑或程序記憶體。正式表示歸單元 10，失敗交付細節歸單元 7。 |
| 距離表等可重新計算的固定衍生資料 | 在本場題庫中供多 task 共用。 | 不另外保存這些衍生表；後續實驗依當次輸入與問題實作重新準備。 |
| 算法輸入、求解結果及完整提交歷史 | 設定求解、追查搜尋與呈現結果。 | 實際算法輸入同樣先保存；搜尋及最終驗證完成後，由 C++ 同步保存結果 JSON 與歷史 JSONL。基本提交資料全留，外部資料依整場開關；不因衍生表不另存而抽樣或刪減歷史。 |

例如 SCVRP 由讀入的座標計算距離表：座標等實際題目輸入須在算法開始前留下保存紀錄，執行期距離表不再另外輸出一份。紀錄必須對應本次真正讀取的內容，不能僅在事後重讀同一路徑就當作原輸入；單元 6 已確認留存責任及時點，正式輸入序列化歸單元 10，不在此指定原始文字格式或新增硬體保存保證。

輸入、結果與歷史須能關聯本場識別碼及 task；同名、同設定再次執行也建立新檔，不覆蓋前場。輸出須保留混合型別、類別意義、路線與多目標資料，不藉 JSON／JSONL 名稱假定可以全轉成浮點數。詳細命名、欄位與引用格式歸單元 10；題庫仍須等輸出等使用者釋放引用後才回收。

分類依實際來源，而非欄位名稱：若某題原始輸入本身就是距離表，該表仍屬必須保留的實際輸入；不另存的是由輸入重新計算出來的衍生表。

「不另存衍生資料」是避免另外落檔可重建的題目準備資料，**不是刪除算法已提交的歷史內容**，也不新增 `addAct` 自動過濾欄位的行為。

重跑仍讀取本次指定設定，由實驗人員維護內容一致，不自動套用歷史副本、比對版本或改回舊值。保存實際輸入供追查或人工重建，不等於提供自動恢復；僅保存輸入也不承諾不同實作或不同執行條件下必然重現。

## 五 AI 邊界

本章的 C++ 直接讀題庫，針對傳統優化問題。AI 專用資料、模型建立與評分仍由 Python AI 問題模組處理，不轉交 Python 實驗管理，也不要求 C++ 用傳統題庫讀取器載入圖片或訓練模型。

可變訓練狀態不能當作共用唯讀題庫；固定資料是否及如何共用、編碼規則如何交給 C++、模型產物與 RNG 的隔離及生命週期，留單元 8 接線。既定的小型特徵篩選範圍不變，不由本章擴成完整 AI 平台。

## 八 理由、影響與後續技術歸屬
