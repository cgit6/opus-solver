## 一 討論範圍與完成目標

### 本次必須討論

- Python 實驗管理、C++ 完整執行核心、Python AI 問題模組的責任與交接。
- 傳統離散與連續問題的設定、解析、預處理、有型別題庫及共用生命週期。
- 固定欄位數的混合編碼、多目標搜尋與結果集合，以及同一題同時使用兩種能力的完整流程。
- 多問題、多題庫、多算法參數組與明列 seeds 的實驗安排、能力檢查及精確配對重跑。
- exp 從頭收集與利用摘要舊 seed 加速收集、題目對應與實際 task 紀錄、選填原組別資料；不從統計值推算 seed，不以缺少選填資料阻擋。
- 程序與執行緒、派工、通訊、輸入與結果所有權、啟動與關閉。
- 算法共同結構、工作緩存、evaluate、增量更新、RNG、停止與 addAct。
- 完整歷史、結果保存、異常原因、已知事實、交付確認、統計與報告。
- AI 問題的最小可用交接，以及它對共同架構的限制。
- 建置、測試、維護、相容範圍與逐步遷移的驗收計畫。

設計階段結束時，應能從一份實驗設定，逐步說明「誰讀取、誰檢查、誰準備、資料在哪裡、誰執行、誰驗證、誰保存、出錯後留下什麼」，並交給實作者落實。不能把尚未解決的跨模組責任交由實作者臨時猜測。

### 本輪不執行

不修改算法、註冊、正式入口、設定讀取器或建置環境，不大量搬動目錄，不重跑完整題庫。需要原型時另定小型試驗的範圍與停止點。

不順便優化算法、修改 legacy bug，或用修正搜尋行為代替移植一致性驗證。歷史串流、背景 writer、Redis、中途 checkpoint、自動歷史恢復、遠端叢集及硬體備援，不因新方案而自動加入。

[單元 1](01_scope_and_responsibilities.md)已確認：MKP 的 BSMA／BSCA／HSMSCA 與目前 45 組參數的 seed 收集及舊 seed 試用、SCVRP 與單目標連續問題的代表算法、這三類全部合法題目，均納入首版。混合編碼包含固定欄位數的 0／1、整數、實數與類別；多目標及混合編碼多目標的組合都必須真正求解並驗證。AI 以跑通小型特徵篩選為目標，不建置完整訓練平台。

收集及使用過去搜尋成果的功能保留，依 [單元 2](02_experiment_configuration_and_tasks.md)釐清為：未指定摘要時從頭收集，指定有效摘要時先試對應舊 seed、重新求解並按本次條件判斷，不足再補找。這取代先前原配對全部重跑、不篩選、不補收集的安排；不增加一般入口直接讀 seed-bank 的模式，不改一般 `cli/run` 用途，不刪舊工具或改寫研究證據。

混合排列、可變長度及條件式欄位不在本次混合編碼範圍內，不取消 SCVRP 原有路線與 transfer 狀態。其他問題、算法與工具的擴充依明列範圍分批接入，不自行刪除舊實作。本輪不執行上述新增能力或全題庫驗證；它們是後續實作與驗收要求。

## 二 已有起點與尚未決定的事

### 已接受並保留的起點

1. Python 管理實驗，C++ 提供完整執行核心，Python AI 問題模組只負責問題所需的準備、訓練與評分。
2. 管理與求解分程序；傳統求解以單一求解程序內多執行緒共用題庫為方向。更換管理語言不把這兩項說成從未確認，但仍須驗證整體組合。
3. 題目準備與算法初始化是不同階段；本次選中題目全部備妥後才開始任何 task 的算法搜尋，準備失敗不先跑其餘題目。
4. 固定題目資料共用，各 task 的可變狀態與 RNG 獨立；資料仍被使用時不得提前釋放。
5. 問題負責判定、算法負責搜尋、求解任務負責最終驗證、實驗管理負責安排與記錄。最終不可行可以正常完成，不冒充執行錯誤。
6. addAct 純紀錄，不評估、不修復、不訓練、不影響 RNG；保存每個 task 的全部實際提交，不以切換系統語言暗中縮減。
7. 非預期算法錯誤停止整場，已保存結果保留，不自動重跑；保存錯誤須留實際原因，不能只寫失敗。未知退出不猜根因。
8. 混合編碼、多目標及其組合屬首版要求，但不是每個算法都必須支援全部組合；能力不符明確拒絕，不強制轉型、偷偷合併目標或改造原有單目標算法。seed 收集條件及是否繼續安排工作由 Python 實驗管理負責，有無來源摘要都按本次條件判斷。
9. exp 的 `replay` 提供對應題目的候選 seed，加速本次收集，不是原任務原配對的全部重跑。本次 YAML 決定題目、算法及參數組；讀目前檔案數值，先試舊 seed、重新篩選、不足再補找，條件改變也可先試，不採用歷史分數／合格標記或自動比對歷史條件。已選題目缺舊 seed 則從頭收集，摘要中未選題目不執行；原組別選填，有則保留、不補造。
10. `replay` 是路徑而非布林開關：省略、`null`、空字串或只有空白均走收集，其他型別報錯。非空白字串只接受以專案根目錄為起點的相對路徑，實際摘要須在專案內；絕對路徑或經 `..`／符號連結指向專案外均拒絕。非空白路徑原樣查找，不去除前後空白；檔案不存在、無法讀取或內容不足時報錯，不退回收集。這是已確認設計，不是現有讀取器的功能。
11. exp 在頂層明寫一份 `stop_condition`，從頭收集、試用舊 seed 及補找所產生的每筆 task 各自套用，不是整場共用額度。不讀算法檔或歷史停止值，不提供分組覆寫；必要值缺少或不支援時，啟動前報錯、不補預設。既有停止欄位及單目標語意、一般 `cli/run` 分組停止不變；目前程式尚未支援新 exp 停止來源。
12. 有無摘要都完整提供 collects、repeat、solvers、dataset_settings 及必要子設定，完整預檢且實際參與本次安排與篩選。來源與本次設定都須合法，不從歷史值修補；本次必要組別欄位不等於摘要原組別必填。repeat 只計本題真正嘗試的新 seed，不計舊 seed 或補找重複跳過；新 seed 合格與否都計次，一輪多個算法 task 不各扣一次。
13. run、exp 各自 YAML 必填正整數 `worker_count`，缺少報錯、不補預設；表示最多同時求解幾個 task，不直接代表 Python 程序數。名稱使用本次 YAML 的 `experiment_name`，歷史資料不覆蓋名稱或併發數；實際程序／執行緒配置與同名保存政策歸後續單元。
14. 舊 seed 依摘要順序判斷，不隨並行完成先後改變；達到本次收集數量就不再安排後續候選，不要求試完全部舊 seed。在途工作收尾歸單元 4、7，不承諾立即安全中止或沒有多算。
15. 摘要同題候選 seed 重複，啟動前報錯、不自動去重；跨題同 seed 不算重複。補找從固定起點產生，不接續歷史搜尋位置；撞到本題已試 seed 則跳過、不求解、不計次。來源重複、產生碰撞及一般 task 判重分開，也不把各算法使用同 seed 誤認成重複候選。
16. 新 seed 額度用完仍不足，保留已得結果、明示本題實際收集數量及不足，繼續其他題目，不再替該題追加。這不是算法錯誤，不改非預期算法錯誤停止整場、正常不可行及保存錯誤的既有政策。

原有一般實驗明列 seeds、參數不補預設、停止、型別、預檢、追查與人工重跑原則，已於單元 1 整理，單元 2 繼續細化。一般實驗／排錯的精確重跑，與 exp 試用候選 seed 加速收集不同；摘要不自動恢復歷史數值。單目標比較不直接套用多目標，不將舊 Python worker、SHM 或入口機制視為必須沿用的實作。

## 三 固定的討論方法

每個單元使用同一流程，一次只確認一個會影響設計的問題：

1. **說明範圍**：列出本單元要解決什麼、不解決什麼，引用已確認前提，不重新問已回答的問題。
2. **查目前實作**：能從原始碼、測試或先前證據查得的事先查明；區分現況、研究原型與新方案。
3. **走具體例子**：先看一題如何從輸入走到輸出，再看並行及一個故障例子。必要時使用簡單流程圖，避免只堆抽象名詞。
4. **比較可行選項**：說明選項對責任、正確性、所有權、效能及維護的實際影響，提出有理由的建議，不用未量測速度替方案背書。
5. **補必要證據**：若不做原型便無法判斷，先定輸入、比較基準、指標、通過條件與停止點；小步驗證後才討論取捨。
6. **使用者確認**：把建議、已確認事項與仍未決事項分開。用白話問題確認，不把理解確認當成採用方案。
7. **寫回文件**：本單元完成就同步主題結論、決策來源、待議與受影響文件；未解的阻擋問題不能藏在實作細節中。
8. **檢查依賴後前進**：確認本單元不與前面結論矛盾，列出下一單元。需要重開已完成項目時，依擴充規則處理。

單元的順序是主線，不是十次固定長度會議。一個單元可以分多次對話，不能因聊過或跑過一個小測試就標成完成。

### 單元 2 實驗設定與 task 規則

- 核對完整收集設定必填、完整預檢且生效，試用結果也交本次條件判斷；預檢不先跑比較求解，也不拿歷史分數決定接受。收集設定自身組別欄位與摘要選填原組別分開。
- 本次 YAML 決定題目及算法／參數組，先試對應舊 seed、不足再補找；讀目前數值，各 task 使用本次共用停止設定。本次選題無舊 seed 就從頭收集，摘要未選題目不執行；不採用歷史分數、合格標記或條件自動比對。
- 按已確認規則核對：舊 seed 依摘要順序、收滿不再追加、repeat 只計本題真正嘗試的新 seed、摘要同題重複報錯而產生碰撞跳過不計次；補找從固定起點、不接續歷史位置，未收滿記錄後繼續其他題目。這不取消一般 task 判重，也不把各算法共用同 seed 誤報成候選重複。
- 細化正式 seed 產生器、值域及耗盡邊界與對應單元的交接；不要把人工有限候選序列當成已驗證正式產生器終止性。
- 核對本次 YAML 名稱及必填正整數 worker_count，不補預設、不被來源覆蓋；實際執行配置留單元 4，不用名稱推定同名輸出行為。
- 核對一般 `cli/run` 分組與 exp 頂層提供停止設定的不同範圍，沿用停止欄位與合法值、零次迭代、達標及無改善選項；完整實際參數如何成為 task 輸入及追查紀錄。
- 單目標停止功能保留其原有適用範圍；多目標的達標／改善設定須與單元 5 配合收斂，未確認前不自選比較規則。

完成條件：一般實驗能展開完整 task 清單；exp 能以本次 YAML 用對應舊 seed 重新求解、按已確認順序判斷與補找，正確分開舊／新額度、來源重複與產生碰撞，達標不追加、額度用完不足則明示並繼續其他題目。來源、本次設定、停止與支援配對均預檢，缺原組別不阻擋，名稱與併發數不被歷史覆蓋。正式設定、支援／預檢介面及 seed 交接仍須收斂；12 項規則模型不等於本單元已完成或正式機制已驗收。

完成條件：MKP、路線題、連續題與混合編碼多目標案例走完準備，型別、類別意義及目標定義不失真；同題多 task、準備失敗、誤寫、仍在使用與程序退出都有明確處理。AI 資料與可變模型狀態須能放入相同責任分類，但不要求相同儲存格式。

- 確認通知順序、重複或截斷、退出交錯、通道關閉及等待機制；不靠推測填補未收到的事實，也不自動增加卡住超時。

完成條件：有程序圖、正常事件序列與通訊故障案例；能辨識每個 task 而不只知道程序 PID。通訊格式只傳必要資料，不把題庫或全部歷史無理由往返搬運。

### 單元 5 算法結構與評估

- 確認主結構、內部與外部結構、當前解／種群、各項真實目標、可行性、歷史最佳解或結果集合，以及搜尋罰分的型別與持有關係。
- 以二元解、實數解、完整路線及固定欄位混合編碼檢查表示與合法操作；不強迫所有算法或 SCVRP 狀態塞進相同平面陣列。
- 確認純實數多目標、混合編碼單目標及兩者組合的代表問題與算法；原有單目標算法不自動改造，具體移植版本及批次於單元 10 落實。
- 確認 evaluate、增量操作、初始化與工作緩存責任；小操作完成時狀態應同步，不靠紀錄函數補算。
- 確認每 task RNG、seed 入口、抽取順序、並行與重用隔離，以及算法內部索引與對外迭代計數的關係。接收單元 2 的固定補找起點與避重原則，細化正式產生器、合法值域及耗盡邊界；不把候選位置、真正新 seed 嘗試數與算法迭代數混為一談。
- 將既有主要上限、達標、無改善與計時規則接入算法；定義評估計數、同時符合多種停止條件與無候選解時的必要語意。
- 明確區分單目標與多目標的搜尋比較、結果集合、改善／達標及無改善判定；不默用加權合併、逐項理想值或語言內建排序代替未定規則。

完成條件：單一解與種群算法各有可讀的結構及執行例子；混合編碼、多目標及其組合有明確算法與操作／比較規則；增量對完整評估、固定迭代的順序與並行對照均有驗證方法。隨機／AI 評估的上下文也必須能表達，不先假定目標函數皆為純確定性函數。

### 單元 6 狀態紀錄與結果保存

- 細化 addAct 的文字標籤、編碼與對應分數、外部空值、isSim 控制、提交來源與快照不可變性，不加入隱藏 evaluate。
- 定義最終解或結果集合、每個解的各項真實目標與可行性、停止、實際迭代與評估數，以及全部實際歷史的結果契約。
- 混合欄位型別、值與類別意義須能保真，解集合與各解目標須可對應；不任選一個代表解冒充完整結果，也不只多存幾個分數。
- 決定 C++ 獨立輸出責任如何接收結果、同步序列化與保存，Python 接收哪些摘要及位置；算法與 addAct 不直接寫檔。
- 確認格式、檔案分工、部分輸出、保存完成與交付確認、資料所有權及回收；管理端不需要接收完整歷史才可完成報告。
- 與單元 9 確認可供 exp 試用的題目與有序候選 seed、實際 task 紀錄及來源關聯，如何內嵌或連到明細、路徑與保存時點；原組別選填、有則保留。候選來源不代替完整求解紀錄，不要求沿歷史算法還原全部原配對，統計值不作 seed 來源；入口限制不自動擴及明細。

完成條件：能完整重建單一解、種群／路線及混合編碼多目標結果，解與各項目標對齊、類別及外部空值保真，後續 task 不覆寫前題紀錄。全量歷史的 RAM 風險明列，不暗中改成抽樣、背景輸出或截斷。

### 單元 7 異常停止與單 task 重跑

- 分開輸入準備錯誤、算法可捕捉例外、原生崩潰、普通不可行、保存錯誤、清理失敗及未知退出。
- 區分預期收集不足與算法錯誤：新 seed 額度用完未收滿，記錄不足、保留結果並繼續其他題目；真正算法錯誤仍停止整場。收滿後已派工作如何收尾及計數，在此與單元 4 細化。
- 細化算法錯誤停止整場時的停止時點、在途 task 的收尾、已保存結果、未開始工作與不可信程序處置，不把接受連帶中止當成恢復方案。
- 定義失敗 task 實際輸入的事前保存，以及軟體保存失敗的原因、task 對應、持久留存時序與二次失敗界線。
- 確認完整最終回報與退出交錯的判定，已交付結果不撤銷；未確認時不自動掃檔補登、重試或冒充成功。
- 核對人工指定設定重跑一個 task 的流程；不自動引用歷史數值、鎖版本、續算或診斷未知原生根因。
- 與單元 6、9 確認中斷後摘要／明細是否可用及已知事實；exp 試用舊 seed 加速本次收集，不等於只補失敗、自動跳過成功、故障重試或中途續算。

完成條件：有逐事件處置表與可重現的最小故障驗證計畫；普通保存錯誤與算法錯誤不誤分類。硬體／資源故障的既有排除不擴大成忽略權限或序列化等軟體錯誤。

### 單元 8 Python AI 問題接線

完成條件：一份特徵篩選交接表、首版必須實際跑通的小型案例及其驗證方法，並用一個 HPO 編碼例子檢查介面不被二元 mask 鎖死；後者不等於首版正式支援完整 HPO。訓練不另成第二套外層實驗管理，本輪不建置完整 AI 平台。

### 單元 9 統計與報告

- 定義正常可行、正常不可行、執行失敗、連帶停止、保存失敗與交付未確認的報告分類。

完成條件：用少量人工單目標與多目標集合結果核算報表，確認比較、分母、排除與顯示規則；統計不替求解任務重新判定數學正確性。
