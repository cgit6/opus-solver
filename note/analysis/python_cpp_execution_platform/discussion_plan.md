# Python 與 C++ 新重構方案討論計畫

建立日期：2026-10-25。更新日期：2026-10-26。狀態：討論計畫已進入逐單元確認，[單元 1](01_scope_and_responsibilities.md)已確認並寫入；單元 2 尚未開始。主方向見 [方案入口](README.md)。

本計畫要把需求、責任、資料交接與故障處置收斂成可實作的設計，再產出小步修改計畫；不是本輪就決定全部介面或開始改程式。整批交付或逐題派工 A／B 問題仍保留未決。

## 一 討論範圍與完成目標

### 本次必須討論

- Python 實驗管理、C++ 完整執行核心、Python AI 問題模組的責任與交接。
- 傳統離散與連續問題的設定、解析、預處理、有型別題庫及共用生命週期。
- 固定欄位數的混合編碼、多目標搜尋與結果集合，以及同一題同時使用兩種能力的完整流程。
- 多問題、多題庫、多算法參數組與明列 seeds 的實驗安排、能力檢查及精確配對重跑。
- 程序與執行緒、派工、通訊、輸入與結果所有權、啟動與關閉。
- 算法共同結構、工作緩存、evaluate、增量更新、RNG、停止與 addAct。
- 完整歷史、結果保存、異常原因、已知事實、交付確認、統計與報告。
- AI 問題的最小可用交接，以及它對共同架構的限制。
- 建置、測試、維護、相容範圍與逐步遷移的驗收計畫。

設計階段結束時，應能從一份實驗設定，逐步說明「誰讀取、誰檢查、誰準備、資料在哪裡、誰執行、誰驗證、誰保存、出錯後留下什麼」，並交給實作者落實。不能把尚未解決的跨模組責任交由實作者臨時猜測。

### 本輪不執行

不修改算法、註冊、正式入口、設定讀取器或建置環境，不大量搬動目錄，不重跑完整題庫。需要原型時另定小型試驗的範圍與停止點。

不順便優化算法、修改 legacy bug，或用修正搜尋行為代替移植一致性驗證。歷史串流、背景 writer、Redis、中途 checkpoint、自動歷史恢復、遠端叢集及硬體備援，不因新方案而自動加入。

[單元 1](01_scope_and_responsibilities.md)已確認：MKP 的 BSMA／BSCA／HSMSCA 與目前 45 組參數的 seed 收集及重跑、SCVRP 與單目標連續問題的代表算法、這三類全部合法題目，均納入首版。混合編碼包含固定欄位數的 0／1、整數、實數與類別；多目標及混合編碼多目標的組合都必須真正求解並驗證。AI 以跑通小型特徵篩選為目標，不建置完整訓練平台。

混合排列、可變長度及條件式欄位不在本次混合編碼範圍內，不取消 SCVRP 原有路線與 transfer 狀態。其他問題、算法與工具的擴充依明列範圍分批接入，不自行刪除舊實作。本輪不執行上述新增能力或全題庫驗證；它們是後續實作與驗收要求。

## 二 已有起點與尚未決定的事

### 已接受並保留的起點

1. Python 管理實驗，C++ 提供完整執行核心，Python AI 問題模組只負責問題所需的準備、訓練與評分。
2. 管理與求解分程序；傳統求解以單一求解程序內多執行緒共用題庫為方向。更換管理語言不把這兩項說成從未確認，但仍須驗證整體組合。
3. 題目準備與算法初始化是不同階段；本次選中題目全部備妥後才開始任何 task 的算法搜尋，準備失敗不先跑其餘題目。
4. 固定題目資料共用，各 task 的可變狀態與 RNG 獨立；資料仍被使用時不得提前釋放。
5. 問題負責判定、算法負責搜尋、求解任務負責最終驗證、實驗管理負責安排與記錄。最終不可行可以正常完成，不冒充執行錯誤。
6. addAct 純紀錄，不評估、不修復、不訓練、不影響 RNG；保存每個 task 的全部實際提交，不以切換系統語言暗中縮減。
7. 非預期算法錯誤停止整場，已保存結果保留，不自動重跑；保存錯誤須留實際原因，不能只寫失敗。未知退出不猜根因。
8. 混合編碼、多目標及其組合屬首版要求，但不是每個算法都必須支援全部組合；能力不符明確拒絕，不強制轉型、偷偷合併目標或改造原有單目標算法。seed 收集條件及是否繼續安排工作由 Python 實驗管理負責。

原有一般實驗明列 seeds、參數不補預設、停止條件、數值型別、預檢、輸入追查與人工重跑等功能原則，已於單元 1 整理沿用關係，單元 2 繼續細化適用範圍與設定。一般實驗與 seed 收集用途分開；單目標停止比較不直接套用多目標。不將舊 Python worker、SHM 或入口路徑視為必須沿用的實作。

### 尚未決定

- Python 整批交付工作清單或逐題派工，以及兩端各有多少執行控制權。
- 管理與求解的正式呼叫、通訊及建置方式，不預設 pybind11、特定序列化格式或某個執行檔布局。
- 題庫由誰讀取哪些原始內容、原始型別如何保留、實際輸入如何留存，以及 C++ 題目物件的具體表示與保護。
- 提交器、結果、外部狀態、AI 評估與各種通知的正式資料結構。
- 混合欄位的具體表示與合法值、多目標結果集合、代表算法、測試題與對應停止／改善／報告規則；不是重新討論首版要不要支援。
- 停止收尾、未知退出、保存與清理失敗的具體處置；不能把「接受停止」當成已能安全立即停止。
- AI 是否同程序嵌入、另開評估程序，以及模型、資料、RNG 與資源如何管理。

## 三 固定的討論方法

每個單元使用同一流程，一次只確認一個會影響設計的問題：

1. **說明範圍**：列出本單元要解決什麼、不解決什麼，引用已確認前提，不重新問已回答的問題。
2. **查目前實作**：能從原始碼、測試或先前證據查得的事先查明；區分現況、研究原型與新方案。
3. **走具體例子**：先看一題如何從輸入走到輸出，再看並行及一個故障例子。必要時使用簡單流程圖，避免只堆抽象名詞。
4. **比較可行選項**：說明選項對責任、正確性、所有權、效能及維護的實際影響，提出有理由的建議，不用未量測速度替方案背書。
5. **補必要證據**：若不做原型便無法判斷，先定輸入、比較基準、指標、通過條件與停止點；小步驗證後才討論取捨。
6. **使用者確認**：把建議、已確認事項與仍未決事項分開。用白話問題確認，不把理解確認當成採用方案。
7. **寫回文件**：本單元完成就同步主題結論、決策來源、待議與受影響文件；未解的阻擋問題不能藏在實作細節中。
8. **檢查依賴後前進**：確認本單元不與前面結論矛盾，列出下一單元。需要重開已完成項目時，依擴充規則處理。

單元的順序是主線，不是十次固定長度會議。一個單元可以分多次對話，不能因聊過或跑過一個小測試就標成完成。

### 單元 1 需求範圍與責任邊界

狀態：已確認，結論及沿用對照見 [單元 1 文件](01_scope_and_responsibilities.md)。以下保留本單元的討論任務，不表示仍待重新確認首版範圍。

- 確認首版必須支援哪些研究情境、現有工具及問題／算法種類；區分正式功能、研發比對工具與延後需求。
- 明確分開實驗範圍的安排、執行期間的排程、題目數學判定、最終驗證及輸出責任。
- 把先前決議分成沿用的功能、新方向已取代的機制，以及確有衝突而需再確認的事項。不是重新對全部舊決議投票。
- 用一題 MKP 與一個特徵篩選 task 走完整責任流程，先標示資料交接與錯誤回報的位置，不選工具。

完成條件：兩個例子的每一步都有明確責任方，需求與首版範圍沒有互相衝突的有效描述。AI 邊界從此單元開始檢查，不等單元 8 才提出。

### 單元 2 實驗設定與 task 規則

- 確認實驗、題目與算法參數設定的維護者、讀取者、固定入口、路徑及完整格式；避免管理端與問題／算法各維護一套相同專用規則。
- 核對多問題、多題庫、參數組、明列 seeds、群組取代、全配對、重複拒絕、不支援拒絕及精確重跑。
- 說清楚 C++ 如何提供算法支援與參數檢查能力，Python 在哪個時點取得結果，未通過預檢不得先開始合法子集。
- 明確查詢及核對編碼欄位型別、目標數量與兩者組合；不能只登記「混合」或「多目標」標籤就視為算法真正支援。
- 分開一般明列 seed 實驗、依結果繼續安排工作的 seed 收集、seed-bank 重跑與一般失敗 task 重跑；確認各自設定及輸入來源，不互相默套規則。
- 核對停止設定的來源與合法值、零次迭代、達標及無改善選項；完整實際參數如何成為 task 輸入及追查紀錄。
- 單目標停止功能保留其原有適用範圍；多目標的達標／改善設定須與單元 5 配合收斂，未確認前不自選比較規則。

完成條件：能列出一份混合題型一般實驗的完整 task 清單，並說明收集工具可能按結果追加工作；用缺參數、未知欄位、錯誤型別、重複及不支援的編碼／目標組合，說明啟動前拒絕的位置。輸入型別不得先被轉換掩蓋。

### 單元 3 問題準備與有型別題庫

- 確認 Python 和 C++ 分別讀哪些檔案或原始內容；題目專用解析、型別／尺寸檢查與衍生計算由問題責任提供。
- 定義固定欄位混合編碼的 0／1、整數、實數、類別合法值及意義，各目標的數量與方向；邏輯契約不強迫所有算法使用同一儲存容器。
- 定義解析後題目、距離表等固定資料與 task 私有工作狀態的界線；同題多 seed 不重算相同固定資料。
- 確認準備發生在哪個程序與階段、全部選中題目備妥的條件、失敗回報與暫存清理。
- 決定有型別題庫的查找、唯讀存取保護、算法引用、持有者及程序退出後的生命週期；不把 const 或 struct 名稱當成全部正確性保證。
- 核對供追查的實際輸入在哪裡留下；是否另存衍生資料須明確決定，不與執行期緩存混為一談。

完成條件：MKP、路線題、連續題與混合編碼多目標案例走完準備，型別、類別意義及目標定義不失真；同題多 task、準備失敗、誤寫、仍在使用與程序退出都有明確處理。AI 資料與可變模型狀態須能放入相同責任分類，但不要求相同儲存格式。

### 單元 4 程序與工作交接

- 在已選的分程序及求解端多執行緒方向下，確認程序由誰建立、如何重用與關閉；AI 放在哪個執行環境先檢查可行性，具體接線於單元 8 收斂。
- 比較 Python 整批交付與逐題派工，定清楚誰決定下一個 task、如何維持工作清單及實際執行關聯；A／B 尚未選定。
- 以 Python 收集器依已完成結果安排下一批為案例，不假定整場 task 開始時全部確定，也不據此提前選定逐題派工。
- 決定呼叫邊界、任務輸入與題庫參照、接收與開始通知、準備完成、求解完成及最終交付回報的正式含義。
- 確認通知順序、重複或截斷、退出交錯、通道關閉及等待機制；不靠推測填補未收到的事實，也不自動增加卡住超時。

完成條件：有程序圖、正常事件序列與通訊故障案例；能辨識每個 task 而不只知道程序 PID。通訊格式只傳必要資料，不把題庫或全部歷史無理由往返搬運。

### 單元 5 算法結構與評估

- 確認主結構、內部與外部結構、當前解／種群、各項真實目標、可行性、歷史最佳解或結果集合，以及搜尋罰分的型別與持有關係。
- 以二元解、實數解、完整路線及固定欄位混合編碼檢查表示與合法操作；不強迫所有算法或 SCVRP 狀態塞進相同平面陣列。
- 確認純實數多目標、混合編碼單目標及兩者組合的代表問題與算法；原有單目標算法不自動改造，具體移植版本及批次於單元 10 落實。
- 確認 evaluate、增量操作、初始化與工作緩存責任；小操作完成時狀態應同步，不靠紀錄函數補算。
- 確認每 task RNG、seed 入口、抽取順序、並行與重用隔離，以及算法內部索引與對外迭代計數的關係。
- 將既有主要上限、達標、無改善與計時規則接入算法；定義評估計數、同時符合多種停止條件與無候選解時的必要語意。
- 明確區分單目標與多目標的搜尋比較、結果集合、改善／達標及無改善判定；不默用加權合併、逐項理想值或語言內建排序代替未定規則。

完成條件：單一解與種群算法各有可讀的結構及執行例子；混合編碼、多目標及其組合有明確算法與操作／比較規則；增量對完整評估、固定迭代的順序與並行對照均有驗證方法。隨機／AI 評估的上下文也必須能表達，不先假定目標函數皆為純確定性函數。

### 單元 6 狀態紀錄與結果保存

- 細化 addAct 的文字標籤、編碼與對應分數、外部空值、isSim 控制、提交來源與快照不可變性，不加入隱藏 evaluate。
- 定義最終解或結果集合、每個解的各項真實目標與可行性、停止、實際迭代與評估數，以及全部實際歷史的結果契約。
- 混合欄位型別、值與類別意義須能保真，解集合與各解目標須可對應；不任選一個代表解冒充完整結果，也不只多存幾個分數。
- 決定 C++ 獨立輸出責任如何接收結果、同步序列化與保存，Python 接收哪些摘要及位置；算法與 addAct 不直接寫檔。
- 確認格式、檔案分工、部分輸出、保存完成與交付確認、資料所有權及回收；管理端不需要接收完整歷史才可完成報告。

完成條件：能完整重建單一解、種群／路線及混合編碼多目標結果，解與各項目標對齊、類別及外部空值保真，後續 task 不覆寫前題紀錄。全量歷史的 RAM 風險明列，不暗中改成抽樣、背景輸出或截斷。

### 單元 7 異常停止與單 task 重跑

- 分開輸入準備錯誤、算法可捕捉例外、原生崩潰、普通不可行、保存錯誤、清理失敗及未知退出。
- 細化算法錯誤停止整場時的停止時點、在途 task 的收尾、已保存結果、未開始工作與不可信程序處置，不把接受連帶中止當成恢復方案。
- 定義失敗 task 實際輸入的事前保存，以及軟體保存失敗的原因、task 對應、持久留存時序與二次失敗界線。
- 確認完整最終回報與退出交錯的判定，已交付結果不撤銷；未確認時不自動掃檔補登、重試或冒充成功。
- 核對人工指定設定重跑一個 task 的流程；不自動引用歷史數值、鎖版本、續算或診斷未知原生根因。

完成條件：有逐事件處置表與可重現的最小故障驗證計畫；普通保存錯誤與算法錯誤不誤分類。硬體／資源故障的既有排除不擴大成忽略權限或序列化等軟體錯誤。

### 單元 8 Python AI 問題接線

- 以特徵篩選逐欄確認設定、資料、特徵順序、切分、前處理、模型建立方式、編碼解讀、評分方向與可行性。
- 在前面程序及資料邊界下，比較同程序呼叫、獨立評估程序等必要選項；不預設每個候選解啟動一次腳本，也不自行加入服務平台。
- 確認評估 RNG、模型與訓練狀態、重複候選解、資料共用及跨 task 隔離；不能未經判定就快取隨機分數。
- 確認搜尋驗證與最終測試的資料使用、模型產物、訓練錯誤與最終驗證；評估結果回傳不表示可以任意重訓後要求同分。
- 檢查 CPU／GPU、訓練內部並行與任務並行的資源安排，明確說明可重現範圍；不把 GIL 或模型訓練當成 Python 管理端必然較快或較慢的證據。

完成條件：一份特徵篩選交接表、首版必須實際跑通的小型案例及其驗證方法，並用一個 HPO 編碼例子檢查介面不被二元 mask 鎖死；後者不等於首版正式支援完整 HPO。訓練不另成第二套外層實驗管理，本輪不建置完整 AI 平台。

### 單元 9 統計與報告

- 定義正常可行、正常不可行、執行失敗、連帶停止、保存失敗與交付未確認的報告分類。
- 確認可行率、完成率、目標值平均與標準差、排名、已知最佳值差距、求解時間與整體時間的樣本及分母。
- 確認不同問題類型、方向、量綱、題庫、參數組與 seeds 的分組，不直接混算不可比較數值。
- 明確定義多目標結果集合的比較、報告及必要指標；不能直接沿用單一最佳值／平均，或任選一個目標當整體優劣。確認 seed 收集需要的摘要，不把問題評估與收集判定混在一起。
- 決定摘要、明細、完整解與模型產物如何連結；全部不可行或整場中斷仍能產生不誤導的報告。

完成條件：用少量人工單目標與多目標集合結果核算報表，確認比較、分母、排除與顯示規則；統計不替求解任務重新判定數學正確性。

### 單元 10 建置與分步實作計畫

- 確認 C++ 標準、編譯與建置工具、依賴、Python 接線、安裝與測試入口，以及修改算法後的開發驗證流程。
- 決定新模組與設定位置、既有算法／題庫／工具的相容與遷移範圍；同步舊設計及治理文件中指向舊方案的有效引用。
- 明定移植比對基準、RNG 與浮點條件、初始化／過程／結果比較，以及 native 併發、所有權、錯誤與安裝驗證；不能用最終分數相同代替過程驗證。
- 驗收矩陣必須包含既有單目標、混合編碼單目標、純實數多目標、混合編碼多目標；另驗證 seed 收集／重跑及小型特徵篩選交接。新增算法或問題的獨立驗證，不能冒充與原本不存在的舊實作逐步一致。
- 明列 MKP、SCVRP、連續問題全部合法題目的相容清單與逐批驗證方法，記錄不合法資料及原因；小型代表案例通過不等於全部題庫已驗收。
- 定義效能比較口徑：冷啟動、準備、純求解、轉換、保存及整批完成分開；記憶體須說明共享資料與抽樣範圍，不把單一合成測試當正式排名。

完成條件：實作者不必自行決定跨模組責任、資料所有權或重大錯誤政策；具體修改計畫有可執行驗收、失敗處理及停止點。此時才提出正式實作，不由本討論計畫直接授權重構。
