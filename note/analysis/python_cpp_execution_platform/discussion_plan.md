## 一 討論範圍與完成目標

### 本次必須討論

- Python 實驗管理、C++ 完整執行核心、Python AI 問題模組的責任與交接。
- 傳統離散與連續問題的設定、解析、預處理、有型別題庫及共用生命週期。
- 固定欄位數的混合編碼、多目標搜尋與結果集合，以及同一題同時使用兩種能力的完整流程。
- 多問題、多題庫、多算法參數組與明列 seeds 的實驗安排、能力檢查及精確配對重跑。
- exp 從頭收集與利用摘要舊 seed 加速收集、題目對應與實際 task 紀錄、選填原組別資料；不從統計值推算 seed，不以缺少選填資料阻擋。
- 程序與執行緒、派工、通訊、輸入與結果所有權、啟動與關閉。
- 算法共同結構、工作緩存、evaluate、增量更新、RNG、停止與 addAct。
- 完整歷史、結果保存、異常原因、已知事實、交付確認、統計與報告。
- AI 問題的最小可用交接，以及它對共同架構的限制。
- 建置、測試、維護、相容範圍與逐步遷移的驗收計畫。

設計階段結束時，應能從一份實驗設定，逐步說明「誰讀取、誰檢查、誰準備、資料在哪裡、誰執行、誰驗證、誰保存、出錯後留下什麼」，並交給實作者落實。不能把尚未解決的跨模組責任交由實作者臨時猜測。

### 本輪不執行

不修改算法、註冊、正式入口、設定讀取器或建置環境，不大量搬動目錄，不重跑完整題庫。需要原型時另定小型試驗的範圍與停止點。

不順便優化算法、修改 legacy bug，或用修正搜尋行為代替移植一致性驗證。歷史串流、背景 writer、Redis、中途 checkpoint、自動歷史恢復、遠端叢集及硬體備援，不因新方案而自動加入。

[單元 1](01_scope_and_responsibilities.md)已確認：MKP 的 BSMA／BSCA／HSMSCA 與目前 45 組參數的 seed 收集及舊 seed 試用、SCVRP 與單目標連續問題的代表算法、這三類全部合法題目，均納入首版。混合編碼包含固定欄位數的 0／1、整數、實數與類別；多目標及混合編碼多目標的組合都必須真正求解並驗證。AI 以跑通小型特徵篩選為目標，不建置完整訓練平台。

收集及使用過去搜尋成果的功能保留，依 [單元 2](02_experiment_configuration_and_tasks.md)釐清為：未指定摘要時從頭收集，指定有效摘要時先試對應舊 seed、重新求解並按本次條件判斷，不足再補找。這取代先前原配對全部重跑、不篩選、不補收集的安排；不增加一般入口直接讀 seed-bank 的模式，不改一般 `cli/run` 用途，不刪舊工具或改寫研究證據。

混合排列、可變長度及條件式欄位不在本次混合編碼範圍內，不取消 SCVRP 原有路線與 transfer 狀態。其他問題、算法與工具的擴充依明列範圍分批接入，不自行刪除舊實作。本輪不執行上述新增能力或全題庫驗證；它們是後續實作與驗收要求。

## 二 已有起點與尚未決定的事

### 已接受並保留的起點

1. Python 管理實驗，C++ 提供完整執行核心，Python AI 問題模組只負責問題所需的準備、訓練與評分。
2. 管理與求解分程序：Python 每場啟動一個獨立 C++ 程序，場內多執行緒共用題庫、重用工作鏈，正常完成工作、保存及清理後關閉；不維護跨場常駐程序。企劃已定不等於正式接線驗收。
3. 題目準備與算法初始化是不同階段；本次選中題目全部備妥後才開始任何 task 的算法搜尋，準備失敗不先跑其餘題目。
4. 固定題目資料共用，各 task 的可變狀態與 RNG 獨立；資料仍被使用時不得提前釋放。
5. 問題負責判定、算法負責搜尋、求解任務負責最終驗證、實驗管理負責安排與記錄。最終不可行或正常沒有候選解可以正常完成，不冒充執行錯誤；空結果不編造數值，也不掩蓋算法例外。
6. addAct 純紀錄，不評估、不修復、不訓練、不影響 RNG；保存每個 task 的全部實際提交，歷史不可被後續修改。整場外部開關關閉只省略外部資料，標籤、編碼、真實目標與可行性仍全留，外部空值不補造；算法必要狀態照常更新。
7. 非預期算法錯誤停止整場，已保存結果保留，不自動重跑；保存錯誤須留實際原因，不能只寫失敗。未知退出不猜根因。
8. 混合編碼、多目標及其組合屬首版要求，但不是每個算法都必須支援全部組合；能力不符明確拒絕，不強制轉型、偷偷合併目標或改造原有單目標算法。Python 提供收集需求；C++ 獨立收集功能負責比較、seed 收錄、補找與追加工作，不放進算法或目標函數。有無來源摘要都按本次條件判斷。
9. exp 的 `replay` 提供對應題目的候選 seed，加速本次收集，不是原任務原配對的全部重跑。Python 實驗 YAML 指定題目、算法名稱、參數組編號與參數檔路徑；題目讀本次指定題庫，算法實際值由 C++ 讀指定參數檔，Python 不開檔解析。C++ 先試舊 seed、重新篩選、不足再補找，條件改變也可先試，不採用歷史分數／合格標記或自動比對歷史條件。已選題目缺舊 seed 則從頭收集，摘要中未選題目不執行；原組別選填，有則保留、不補造。
10. `replay` 是路徑而非布林開關：省略、`null`、空字串或只有空白均走收集，其他型別報錯。非空白字串只接受以專案根目錄為起點的相對路徑，實際摘要須在專案內；絕對路徑或經 `..`／符號連結指向專案外均拒絕。非空白路徑原樣查找，不去除前後空白；檔案不存在、無法讀取或內容不足時報錯，不退回收集。這是已確認設計，不是現有讀取器的功能。
11. run、exp 都在各自實驗 YAML 提供一份整場停止條件，由 Python 讀取並作為實驗額度交給 C++，C++ 檢查支援並執行；exp 沿用頂層 `stop_condition`，收集、試用及補找的各 task 分別套用額度。不讀算法檔或歷史停止值，不提供分組、算法或題目覆寫；必要值缺少或不支援時，啟動前報錯、不補預設。先前 run 按組停止的安排已取代，既有停止欄位與單目標語意不改；目前程式尚未實作新來源及接線。
12. 有無摘要都完整提供 collects、repeat、solvers、dataset_settings 及必要子設定，完整預檢且實際參與本次安排與篩選。來源與本次設定都須合法，不從歷史值修補；本次必要組別欄位不等於摘要原組別必填。repeat 只計本題真正嘗試的新 seed，不計舊 seed 或補找重複跳過；新 seed 合格與否都計次，一輪多個算法 task 不各扣一次。
13. run、exp 各自 YAML 必填正整數 worker_count，缺少報錯、不補預設；表示最多同時求解幾個 task，不是 Python 程序數。名稱取本次 experiment_name，歷史不覆蓋。單元 6 已定每場新識別加入檔名，同名同設定也不覆蓋前場；碰撞不得覆寫、命名不耗算法 RNG，正式命名及執行緒接線歸 10。
14. 舊 seed 依摘要順序；同題前輪所選算法／參數組結果完成判斷才安排下一輪，不提前派後續 seed。輪內及不同題可並行，收滿不追加、不要求試完舊 seed；異常在途停止及清理歸單元 7。
15. 摘要同題候選 seed 重複，啟動前報錯、不自動去重；跨題同 seed 不算重複。補找從固定起點產生，不接續歷史搜尋位置；撞到本題已試 seed 則跳過、不求解、不計次。來源重複、產生碰撞及一般 task 判重分開，也不把各算法使用同 seed 誤認成重複候選。
16. 新 seed 額度用完仍不足，保留已得結果、明示本題實際收集數量及不足，繼續其他題目，不再替該題追加。這不是算法錯誤，不改非預期算法錯誤停止整場、正常不可行及保存錯誤的既有政策。
17. 算法 YAML 每算法一份、放 C++ 模組內，同存支援的問題／編碼／目標數量、參數名稱／型別／範圍，以及各組專用實際值，不再要求規格與數值拆檔。C++ 讀取並執行專用檢查，Python 不讀內容或另維護相同規則；具體子目錄、欄位及查詢介面仍待細化。
18. Python 實驗 YAML 明寫算法 YAML 來源路徑、算法及原組號，C++ 自行開檔；Python 不解析或轉交算法專用值，不自動選取檔內全部組。每算法的組別依原排列從 0 編號、部分選取不重編號；各組專用值完整明寫，不新增共用算法參數合併或預設。
19. 依單元 5 修訂，種群大小屬算法 YAML，由 C++ 讀取、檢查及記錄，各參數組可不同；單一解算法不強制增加種群參數，不改寫依題目決定大小的算法公式。run、exp 仍在各自實驗 YAML 整場明寫一份停止條件，由 Python 提供、各 task 分別套用。三算法 45 組需求保留；修復、重啟與溫度排程等內部參數仍在算法 YAML，不依名稱刪除。
20. 所有必要檢查與全部選中題目準備通過後，才可開始任何求解。C++ 在算法開始前把實際題目／算法輸入及 task 關聯寫入本場可追查保存紀錄，不只留 RAM 或可能變更的來源路徑，不事後重讀冒充當次內容。Python 保存安排及收到的整場交付，不讀參數值建立工作或決定收錄；不自動恢復歷史數值，也不新增硬體保存保證。

21. 一般 run 由 C++ 根據 Python 提供的選取安排，依既定配對規則展開逐筆 task、檢查實際工作重複並保存工作關聯；Python 不另外產生執行清單或逐題確認，C++ 不擴大選取範圍，整場交付提供必要摘要及追查位置。
22. seed 空間耗盡依使用者決定不納入本版處理，不新增專用機制或替使用者選停止政策；合法值檢查、避重及 repeat 計數仍有效，不宣稱耗盡不會發生。
23. Python 提供選題與來源，不解析傳統題目數值；C++ 問題模組直接讀檔、檢查、解析及預處理。同場同題固定資料只準備一次，全部題目與必要預檢通過才求解；準備失敗不跑合法子集，記錄可取得輸入及錯誤，清理資源。準備完成依單元 6 改為內部階段，不對外逐段通知；致命退出及交付機制歸 7、10。
24. 本場 C++ 執行環境持有有型別題庫，全部工作結束且求解、輸出等使用者都不再引用後統一釋放，不逐題提早回收或新增跨場快取。固定資料唯讀共用；依算法參數或搜尋進度建立的工作緩存、編碼、已用容量、搜尋路線及 RNG 均屬 task 私有。
25. 保存本次實際讀入的題目資料，不能只留路徑；距離表等可重建的衍生資料不另外保存，不因此刪減已提交歷史。重跑仍讀本次指定設定，不自動恢復歷史內容。混合欄位及各項目標的型別、意義與方向須保留，不強制同一容器或全轉浮點；AI 專用資料與可變模型仍依單元 8 分工。
26. 本場安排一次交付 C++，其自行選工作並在算法前保存實際輸入與關聯，不向 Python 逐 task 登記或等確認。空閒執行緒不綁題，同一工作鏈完成本機保存、相關使用及清理後自主接下一題。
27. 準備、task 開始、求解及最終驗證、保存仍為 C++ 內部不同階段，不逐項通知。程序間只交本場安排及整場終結摘要、位置與可取得錯誤；題庫與完整歷史不往返 Python，不逐次傳 addAct、不反覆掃檔判進度，也不保證管理端即時掌握在途 task。
28. 完成交付前確認 Python 退出或斷線，停止整個 C++ 程序、不等在途算完，接受未保存資料可能遺失，不新增無訊息超時。正常關閉不算異常，本機已保存資料不撤銷，但不等於 Python 已收到整場交付；缺回報不靠掃檔或退出碼補登成功、不自動重跑，不從未完成清單猜原生崩潰肇因。

29. 主／內／外結構保持 task 私有，題目唯讀引用；編碼、各項真實目標及可行性對應，搜尋罰分另存。正確增量更新允許，addAct 不負責更新或評估。
30. 多目標返回算法自身維護的最終解集合，不要求額外維護全程非支配集合；完整提交歷史不變。首版多目標只支援迭代／時間上限，不支援的達標或無改善停止在整場預檢拒絕。
31. 每次完成候選解評分計一次搜尋評估，完整及增量都計；完整一次再完成三次移除更新共四次。最終驗證另計，記錄或複製分數不計。同一檢查點記錄所有已啟用且成立的停止條件，不任選主要原因、不額外評估。
32. 移植必須對齊原算法所需 RNG 與必要搜尋模組，不能僅憑同 seed 宣稱相容。兼容條件下的亂數、初始化及逐步狀態比對，與新停止檢查點、計數及結果表示等已核准變更分開驗證；各 task 不共用可變 RNG。
33. 三類代表案例與 1:1 比對基準已接受，見單元 5；每案須有固定來源與明寫規則的 reference，對齊輸入、RNG 與數值環境後核對初始化、逐輪狀態及最終結果，手算或同 seed 不代替過程證據。精確版本環境、參數、浮點核對規則及測試計畫由單元 10 在實作前定稿。
34. 搜尋及最終驗證後，C++ 獨立輸出功能同步保存每 task 結果 JSON 與完整歷史 JSONL；保留算法最終解／集合、混合型別／類別／路線、真實目標及可行性、全部停止原因與分開計數。完整歷史 RAM 風險仍接受，不新增搜尋中寫歷史、背景輸出、抽樣或截斷。
35. exp 候選摘要直接列各題有序正式收錄 seed；每個 seed 輪次完成判斷及必要保存後由 C++ 更新，不等 Python。輪次是同題同 seed 的全部所選算法／參數組，不是算法一代。未收錄 task 的結果及歷史仍全留；不同題更新不得遺失已收錄清單，當場摘要更新不覆蓋前場，部分清單不代表整場完成或自動續算。

原有一般實驗明列 seeds、參數不補預設、停止、型別、預檢、追查與人工重跑原則，已於單元 1 整理、單元 2 企劃定案。一般實驗／排錯的精確重跑，與 exp 試用候選 seed 加速收集不同；摘要不自動恢復歷史數值。單目標比較不直接套用多目標，不將舊 Python worker、SHM 或入口機制視為必須沿用的實作。

## 三 固定的討論方法

每個單元依序完成「範圍清單 → 一批決策問題 → 情境核對 → 文件定案」，以企劃設計能自圓其說為顆粒度，不把每個技術子項都拆成一次問答。

1. **先列完整範圍**：說明本單元要回答的責任、輸入、行為與結果，區分已定前提、真正待決事項及範圍外事項；不重新問已確認決策。
2. **先查事實與依賴**：原始碼、文件及證據能回答的先查明，區分現況、原型及新設計；確認沒有把後續技術選擇誤列為當前企劃阻擋。
3. **一次提出決策問題**：同一單元尚需使用者選擇的事項集中列齊，白話說明選項、理由與取捨。不是一題答完再逐次冒出欄位名或目錄問題；下列各單元的細項是核對清單，不是每項都要提問。
4. **用完整情境核對**：回答後一起走正常流程、相關例外及必要的並行／數值情境。需要證據時先限定小型原型與驗收條件，不以未量測速度作理由；有歧義只釐清該項，不藉機擴大範圍。
5. **形成一致文件**：集中寫有效結論、責任流程、來源、案例及後續依賴，再同步相關文件；不讓讀者從多輪對話拼湊政策。
6. **定案後前進**：本單元企劃結論確認並完成文件核對後，進入下一單元。只有具體決策衝突才提出原決議、衝突原因及影響範圍，經使用者確認後重開受影響部分，不反覆重問全部事項。

範圍外事項記入負責單元，不中途跳題。函式簽章、欄位命名、實體目錄與完整序列化格式，不因列入核對清單就優先逐一詢問；單元 4、6 已定內部階段、本機保存及整場交付，異常歸 7、報告歸 9，正式通訊工具／訊息、序列化、設定及目錄接線於 10 整合。未完成技術不能交由實作者自行猜測。

若發現真正阻擋當前責任或行為成立的衝突，先按第六節處理，不用「企劃已定案」掩蓋。除使用者確認的範圍變更或具體衝突外，不因多一個實作選項就重開已定決策。

### 單元 6 狀態紀錄與結果保存

狀態：**企劃設計已定案**，見 [主題文件](06_state_recording_and_result_storage.md)。不重問保存開關層級、輸出責任、交付粒度、同名場次或候選摘要更新時點。

- 搜尋及最終驗證後，由 C++ 獨立輸出功能同步保存每 task 結果 JSON、完整歷史 JSONL。保留單一解或算法最終集合、混合型別與類別／路線意義、各項目標／可行性、全部停止原因、實際迭代及分開計數；正常無候選不造編碼或分數。
- C++ 在算法前將實際題目／算法輸入及 task 關聯寫入本場可追查紀錄，不只留 RAM 或路徑、不事後重讀。已保存內容可供多 task 明確引用，可重建衍生表不另存，不新增硬體保證。

- Python 保存本場安排、監督程序，只收整場終結摘要／位置／可取得錯誤，不保證即時 task 清單或崩潰肇因。本機保存不等於收到整場交付；缺回報不掃檔或依退出碼補登、不自動重跑。

- exp 摘要直接列各題有序正式收錄 seed；同題同 seed 全部所選算法／參數組構成一輪，完成判斷及必要保存後由 C++ 更新，不等 Python。未收錄 task 的結果及歷史仍全留，跨題更新不遺失其他清單；部分清單不代表整場完成或自動續算。

完成條件：主題文件記錄 16 個文件情境，核對完整快照、型別／集合、同步保存及生命週期、新場不覆蓋、收錄與拒收、缺終結回報等政策一致。原單元 4 九項模型保留為歷史證據，不當新流程驗收；本輪不測正式保存、IPC 或故障處理。完整歷史 RAM 風險仍接受，不新增抽樣、截斷、搜尋中寫歷史或背景輸出。

## 八 討論結束前的整體核對

十個單元確認後，再用同一份實驗走完一次端到端設計，核對：

- 正常傳統與 AI 任務、零次初始化、不可行或無候選解結果，以及多問題多 seed 的完整流向。
- 每算法 YAML 在 C++ 模組內同存能力規格與各組專用值，不要求分檔；Python 指定來源／算法／原組號，不開檔。種群大小由 C++ 讀算法 YAML、各組可不同，單一解不強制新增種群參數；只有整次求解停止設定由 Python 讀實驗 YAML 提供，整場統一、逐 task 套用，C++ 檢查支援。所需算法值完整明寫、原組號不重編、多組比較保留，修復／重啟／溫度排程不誤刪，不靠覆寫公式湊設定。
- 既有單目標、混合編碼單目標、純實數多目標及混合編碼多目標的完整流向；seed 收集與重跑不能因一般實驗設定而失去用途。
- exp 未指定摘要時從頭收集，指定有效摘要則試用對應舊 seed、重新求解與篩選、不足再補找；題目、算法／參數組、條件與目前數值依本次 YAML，不採歷史分數／合格標記。已選題目缺來源 seed 從頭收集，來源多出的未選題目不執行；完整設定、來源及停止均預檢，名稱、必填併發數與共用停止不被歷史覆蓋，原組別仍選填。
- 核對舊 seed 摘要順序、收滿不追加、repeat 只計本題新嘗試、來源重複拒絕及碰撞跳過、不接續歷史位置、額度不足正常保留。收集同題逐輪，輪內及不同題可並行、不提前派後續 seed；異常在途處理、正式產生器及報告仍須驗收，模型不代替正式機制。
- 一般 run 由 C++ 展開逐筆 task、依既定鍵判重，不擴大選取範圍；Python 不另外列出執行清單。exp 比較、收錄、補找與追加由 C++ 獨立功能控制，不放入算法、目標函數或 Python 報告。C++ 算法前將實際題目／算法輸入與 task 關聯存成可追查紀錄，不能只留 RAM；Python 留安排及收到的整場資訊，全部必要檢查與準備完成前不跑合法子集。
- `replay` 的省略與空值走收集、錯誤型別拒絕；非空白路徑不自動去空白，只接受實際摘要位於專案內的相對路徑。路徑或摘要錯誤不退回收集，明細的獨立路徑規則不由入口限制補定。
- 題目準備失敗、不支援配對、未知欄位、數值轉換及重複 task 均在正確時點拒絕。
- Python 只提供選題與來源，C++ 直接讀取並準備傳統題目；同題相同固定資料只準備一次，整場及所有引用結束才回收。實際題目輸入須留存、衍生表不另存、歷史不縮減；不能以型別名稱取代唯讀與生命週期驗證。
- 每場新建 C++、安排一次交付；取消逐 task 登記／確認／階段通知，準備完成亦為內部事實。C++ 工作鏈本機保存、相關使用及清理後自主接新 task，不綁定題目；Python 只接整場摘要／位置／可取得錯誤，不逐次傳 addAct 或掃檔取代交付。
- 結果 JSON 與歷史 JSONL 都完整保存才算本機保存完成；外部整場開關只省略外部快照，基本資料全留且歷史不可被後續修改。每場新識別入檔名、不覆蓋前場，命名不耗算法 RNG；正式表示及所有權須驗證。
- exp 候選摘要直接保存有序正式收錄 seed，每輪判斷及必要保存後 C++ 自行更新；未收錄 task 完整輸出仍保留，不同題更新不遺失已有清單，部分摘要不代表整場成功或自動續算。
- 並行不共享 task RNG 或可變狀態，紀錄不額外評估，完整歷史與結果不被後題覆寫；固定且對齊條件下逐步比對，不以同 seed 宣稱相容。完整／增量評分均計次、最終驗證另計；算法最終集合、正常無候選解及全部成立停止原因依單元 5 保存，正式表示另驗證。
- 算法錯誤全場停止；管理／通訊中斷停止整個 C++ 程序、不等算完，兩者不誤分類。保存錯誤與未知退出分開記錄，本機保存不撤銷也不等於 Python 已收整場交付；缺回報不掃檔或依退出碼補登、不自動重跑。沒有即時 task 清單保證，不猜原生肇因，實際輸入及已知事實可追查。
- 文件間的責任、型別、通知、計時、保存及相容規則一致；沒有使用者未決但實作者必須自行猜的重大選擇。
