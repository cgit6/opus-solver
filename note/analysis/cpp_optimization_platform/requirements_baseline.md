# C++ 優化算法模擬平台的需求基線

整理日期：2026-10-25。

新方案以 C++ 建立完整優化算法模擬平台，Python 作為 AI 問題模組的實作環境。本文件保留先前已確認、與語言無關的研究需求；不把舊的 Python 派工與資料交接方式當成新平台的必要架構。

## 平台要完成的工作

研究者透過實驗設定選擇問題、題庫、算法、參數組、seed 與停止條件。平台檢查設定、展開 task、準備題目、安排並行求解，保存結果與提交歷史，最後統計分析。

一個 task 是「一個問題實例、一個算法、一組算法參數、一個 seed 的一次完整求解」。task 不是程序或執行緒；AI 問題內的一次訓練或一折交叉驗證，也不因此成為另一個外層 task。

## 責任分工

| 責任 | 負責的工作 | 不負責的工作 |
| --- | --- | --- |
| 實驗管理 | 讀取實驗設定、展開與分派 task、保存實際輸入及已知執行事實、協調保存與統計。 | 不重新計算候選解的目標值或限制式。 |
| 問題模組 | 解的意義、題目解析與準備、目標函數、限制式、問題相關的驗證。 | 不替算法決定搜尋策略。 |
| 算法 | 初始化、搜尋、運算子、增量更新、最佳解、停止判斷與提交時點。 | 不擅改問題規則，不直接做檔案輸出。 |
| 求解任務 | 組裝問題與算法、執行完整搜尋、依問題規則最終驗證並交付結果。 | 不管理整場實驗。 |
| 狀態紀錄與輸出 | 紀錄子模組保存提交快照；獨立輸出責任保存任務結果與歷史。 | 不透過紀錄函數重新評估、訓練或更新搜尋狀態。 |

這些是業務分工，不代表必須建立相同數量的程序、服務或抽象基底類別。傳統問題的上述工作以 C++ 實作；AI 問題的資料準備、訓練與評分由 Python AI 問題模組提供。

## 實驗設定與 task 展開

- 使用固定的實驗 YAML，不以命令列覆寫實驗參數；仍要求從專案根目錄啟動。新 C++ 啟動命令與實驗設定的具體位置另定，不直接沿用 Python 命令。
- 明列起始 seeds，不在展開 task 時自動派生，不另設 repeat。群組可取代整場 seed 清單，不合併兩份清單。
- 一組一種問題，可選多個題庫的全部或指定題目；同組題目、算法參數組與有效 seeds 全部配對，不跨組配對。精確重跑的少數配對可分組表達。
- 算法參數另存設定；可設定參數必須明寫，不補預設值。算法內部常數與依題目計算的緩存尺寸不必全部外露。
- 不支援的組合、必要欄位缺少、題目或算法參數中的未知欄位、型別或尺寸錯誤，在啟動前指出並拒絕整場，不自行略過、猜測或修正。
- 同問題類型、題庫、題名、算法、參數組與 seed 重複時拒絕啟動；停止條件不同也不繞過此規則。不跨歷史實驗阻擋人工重跑。
- 外部輸入要求整數就檢查原始型別，不把小數、字串或布林值轉成整數後繼續；整數轉浮點須符合目標型別的精確表示與範圍要求。

題庫數值與研究參數是否符合研究意圖，由研究者負責。問題模組檢查問題輸入，算法檢查自身參數，實驗管理檢查實驗安排；不因統一使用 C++ 就把專用規則複製到管理模組。

原有 `configs/problems/`、`configs/solvers/` 是既有資料來源，本輪不搬動。新平台完整設定布局及既有格式的相容範圍仍須確認。

## 停止與可重現性

- 停止條件由實驗群組提供，算法執行。主要上限選迭代數或求解秒數，另明列是否達到已知最佳值提早停止，以及連續無改善輪數或 `null`。
- 初始化不計迭代；完成一整輪算法更新才加一。允許零次迭代，表示做完原本初始化、最終驗證及交付，不偷偷改成一次更新。
- 達標與時間檢查在初始化後及整輪完成後進行。達標只讀既有分數與可行性，不額外 evaluate；達標以可行解的原始目標值按最大化或最小化方向比較，不加入容許差或搜尋罰分。
- 無改善依算法自身歷史最佳解的嚴格比較判定；每輪有改善就歸零，否則加一。同分換解或單純重啟不能歸零。
- 求解計時包含算法工作空間、初始解建立與搜尋，不含題目預處理、最終驗證、結果轉換與輸出。時間上限允許因完成當前初始化或一輪而超過設定值。
- 固定實際輸入、seed 與迭代數，在適當確定性條件下驗證初始化、過程與結果；開關紀錄不得改變搜尋 RNG、搜尋狀態或結果。時間停止不承諾同樣結果，AI 的評估隨機性與執行非確定性須另行驗證。

已確認的停止欄位與各值合法範圍，沿用 [舊設定討論的功能規則](../system_redesign/18_experiment_configuration_and_task_expansion.md#已確認的群組停止欄位)，不是沿用其 Python 入口。多個停止條件同時成立時的結果表示仍待定。

## 算法狀態與完整紀錄

- 每個 task 私有自己的編碼、真實適應值、RNG、工作緩存、最佳解與歷史。主結構、內部結構、外部結構的概念保留，具體 C++ 型別另定。
- evaluate 的概念責任是接收一個個體的完整編碼，回傳真實目標值與可行性；正式 C++ 介面與多目標表示另定，不因改語言而改變問題規則。
- 真實目標值與搜尋罰分分開；允許正確的增量更新，不要求每次移除物品或交換點位都完整重算。
- `addAct(文字狀態, 編碼, 外部結構或空值)` 是既有概念介面，只保存狀態。算法自行安排提交時點；不透過 addAct 補算分數、修復、訓練或消耗 RNG，也不自動加「未評估」標記。
- 單一解或整批個體的編碼、對應真實適應值與外部狀態須對齊；保存的快照不得被後續工作緩存覆寫。這是開發與測試契約，不要求管理模組逐筆重新評分。
- 所有 task 的每次實際提交都保留，外部空值照實保存；不暗中改成抽樣、截斷或只保留最佳解。
- 每個 task 完整求解與最終驗證後，一次交付最終結果及全部實際歷史，再同步保存、交接與清理；同一工作鏈完成後才接下一題，不要求其他健康工作鏈一起停等。新方案的交付與輸出在 C++ 責任內設計，不再要求完整歷史先返回 Python。
- 仍被任務、結果或輸出器使用的資料，不得提前釋放。重用健康程序不代表延續前題的 RNG 或可變算法狀態。

完整單 task 歷史可能耗盡 RAM 的已知風險仍保留，不因改成 C++ 就視為已解決。歷史分批交付、背景 writer、Redis、中途 checkpoint 與恢復算法進度，不自動加入新方案。

## 結果與錯誤

- 最終最佳解不可行，仍可正常完成並如實標示不可行；不等於執行錯誤。真實目標值、搜尋分數與可行性不能混用。
- 求解任務負責最終驗證；實驗管理只接受與記錄結果，不重做數學驗證。隨機或 AI 評估的最終驗證不能擅自重新抽樣訓練後要求分數相同。
- 非預期算法錯誤，包括可捕捉例外與原生致命崩潰，停止整場實驗及新派工，涵蓋其他算法與在途 task；保留已保存結果，不自動重跑。安全停止方式仍待程序架構細化。
- 開始執行前須留下 task 的實際輸入及執行關聯，以便出錯後人工單獨重跑。保留可取得的事實，不要求管理模組判斷原生崩潰的精確根因，也不把未知退出直接說成某題算法錯誤。
- 保存失敗要保留實際原因與 task 對應，不因輸出改用 C++ 就降低此需求；普通保存錯誤不一律等同算法錯誤。清理成功且環境可信才可重用，不可信環境不得繼續使用。若必須關閉承載多題的求解程序，已接受其中其他未完成 task 連帶中止；是否重建程序、何時繼續未開始工作仍待細化，不自動重跑中止題目。
- 求解完成、保存完成與管理端確認交付是不同事實。已確認交付不因之後程序退出而撤銷；缺少完整回報時保留已知事實與現有檔案，不自動掃檔補登成功或重跑。
- 重跑讀指定設定，內容一致由研究者維護；保留實際輸入供追查或人工重建，不自動套用、比對或鎖定歷史數值。

首版仍以 Linux／WSL 為範圍。不新增卡住後自動超時中止或內建單 task 人工停止命令；硬體／資源層異常的專用恢復與另一儲存媒介備援不在本版範圍。這不排除路徑、權限、序列化等軟體保存錯誤。
