# 07｜完整歷史、一次回傳與保存責任

狀態：每 task 完整結果與歷史一次交付、同步保存完才接下一題、主程序只收摘要／路徑的要求保留。D18–D19、D34 當時選定返回 Python 並用 Python 輸出器保存，仍是有效舊保存基線；輸出器實作語言及候選的交付邊界差異依下節比較，未選替代方案。D35 的拓撲重新評估見 [14](14_python_cpp_invocation_and_failure_replay.md#架構狀態與比較維度)；D36–D40 派工、通知及異常政策保留，正式表示、通訊／監督與所有權仍待細化，大型記憶體風險延後解決。對應 D17–D20、D24–D29、D34–D40、D79–D80、P07、P10。

本章「保存完才接下一題」約束同一條邏輯工作鏈，不是同 host 所有 threads 的全體停等；舊基線一個 worker 對應一個程序與工作鏈，不能無條件套到候選。task／邏輯單元／host 的名詞與 D40 替換影響見 [14 單一對照](14_python_cpp_invocation_and_failure_replay.md#執行名詞與替換範圍)，不預設工作鏈永久綁某個 thread 或程序。

## 已確認交付需求與保存基線

| 層次 | 已確認要求或舊保存基線 | 待比較與確認的邊界 |
| --- | --- | --- |
| 不變責任 | 保存屬實驗／輸出責任；算法與 addAct 不做文件 I/O。 | 用 C++ 實作獨立輸出元件不等於讓算法負責文件；必須保留責任分離。 |
| 不變交付與節奏 | 每 task 完整計算與最終驗證後，一次交付結果及全部實際歷史；同一邏輯工作鏈同步保存／交接及清理後才接下一題，主程序只收摘要／路徑。 | 不要求同 host 其他健康鏈等它保存，也不准同鏈提前接題；不重開主程序收全量保存，不加入分批、背景 writer、Redis、自動掃檔或重試。 |
| 舊保存基線與實作選擇 | D18–D19、D34 曾選 C++ 將完整結果／歷史返回 Python，由 task 所在 worker 呼叫 Python 輸出器同步保存；沿用仍有效。 | Python-only 與 C++ 獨立輸出已有 [19 的候選控制對照](19_architecture_candidate_experiments.md)，實作選擇與邊界仍待確認；測過不等於採用，也不把原 Python 選擇說成從未定案。 |

候選若改由 C++ 側序列化／保存、避免把完整歷史轉成 Python 物件，或不再把完整歷史交給 Python 接收，須明列相對 D18「完整返回 Python」及 D19／D34 的差異：完整資料在哪裡交給輸出器、Python 實際收到什麼、誰持有結果與歷史、何時可釋放。這些差異須待使用者確認，不能默默取消 D18；沿用基線時也不預設必須深轉成 Python list。候選的資料所有權及正式保存機制尚未驗收，D38–D40 的現行通知／錯誤政策不因本項自動更改。

錯誤依實際業務階段區分。C++ 獨立輸出元件拋出例外，不能只因來源語言是 C++ 就分類為算法錯誤、觸發整場停止；候選的保存錯誤回報如何映射 D25／D40，須列差異待確認。本項不自動改動現行 Python 保存錯誤政策，也未選定新的恢復策略。

舊保存基線中，每個求解任務由 C++ 完整執行與最終驗證後，一次返回 Python：

1. 該任務的最終結果。
2. 該任務全部實際 addAct 提交紀錄。

Python 實驗模組在舊保存基線中接收完整資料並呼叫 Python 輸出器。保存責任仍屬實驗／輸出側，算法與 addAct 不自行寫檔；不能把這項責任界線擴大成所有 C++ 語言元件一律不得輸出。

D34 的同步 task 保存位置及主程序只收摘要／路徑不變；輸出器語言與 D18 的完整返回邊界依上表比較。D35 當時選定 worker 內同程序擴充模組，現在重新評估，不能由保存決議推定呼叫邊界或並行拓撲已定；詳見 [14 的比較維度](14_python_cpp_invocation_and_failure_replay.md#架構狀態與比較維度)、[15](15_task_failures_and_result_storage.md)。

## 全部保留的範圍

使用者明確選擇：例如 100 題、每題 10 個 seed，這 1,000 次求解都保留每次實際提交的編碼、對應真實適應值與外部快照。

- 不只保存某些 seed。
- 不改成隔若干代抽樣。
- 不只保留最佳解或統計摘要。
- 不以環形緩存覆蓋舊紀錄。
- 若某次外部參數原本就是 nil，保留這個事實，不要求補造外部資料。

全量保留是「每次實際呼叫 addAct 的內容均保留」，不代表系統自動在每條語句後插入提交。提交頻率與文字標籤仍由算法作者定義。

## 任務生命週期

下列沿用 D18–D19、D34 舊保存基線與 D35 比較基線描述資料路徑；候選改輸出器語言或完整返回 Python 的邊界時，須依 [上表](#已確認交付需求與保存基線) 列差異待確認。不以這張流程選定新的排程語言、程序／執行緒或呼叫邊界。

```text
Python 分派一個任務
  → C++ 初始化題目、算法、工作空間與紀錄容器
  → 算法搜尋，addAct 將快照累積於本任務記憶體
  → 到達停止條件，求解任務完成最終驗證
  → 一次交回最終結果及全部提交紀錄
  → 該 Python worker 同步保存本題
  → 主程序只接收摘要與檔案位置，後續彙整分析
```

每個任務完成時各自回傳，不是整場 1,000 個任務都算完才第一次交付。D37–D38 已確認階段及最終回報的判定政策；正式保存格式與通訊實作仍須細化，不預設新增完成標記或自動文件核對。不能宣稱目前一般 CLI 已做到任務級即時保存。

既有方案的 Python worker 在保存、交接與清理後，僅整場未停止時接下一個新 task；不是讓整場歷史永久堆在該程序內。但「一次返回」不等於立刻釋放所有 C++ 結果記憶體：Python 輸出器仍使用的資料，必須有有效持有者，不能提前釋放或被下一題覆寫。具體移交／持有方式與是否複製仍待 [08](08_cpp_invocation_and_shared_memory.md) 決定；上述路徑不等於正式回收及通知協議。

清理不能刪掉尚未交付的歷史，也不能把完整歷史改成逐代寫檔。程序重用的控制實驗見 [16](16_process_lifecycle_experiment.md)，不代表正式保存流程的記憶體風險已解決。

## 已選 worker 保存，主程序保存為未採用的比較

| 路徑 | 舊保存基線中 C++ 返回後的工作 | 主程序接收的內容 |
| --- | --- | --- |
| 主程序保存（本版不採用） | worker 將完整結果與歷史交給主程序，由主程序呼叫輸出器。 | 完整結果與歷史。 |
| worker 保存（D34） | worker 同步呼叫同一套 Python 輸出器，完成該 task 的文件後回報。 | 統計所需摘要及檔案位置，不必再傳完整歷史。 |

這是同機器、輸出位置可見的比較；D34 已選 worker 同步保存，隔離 Python worker 的配置沿用 D35 比較基線。共用的是輸出程式，不是讓所有 worker 同時修改同一個檔案。獨立 task 檔案、摘要與完成確認的具體格式仍待定。

worker 保存避免把完整歷史再交主程序；使用者接受同一邏輯鏈保存時不接新題，以免前題未存又產生大結果。同 host 其他健康鏈不因這題保存而一律停等，但須滿足環境可信、整場未停止條件；並行保存仍可能競爭磁碟。主程序保存也能限制待存結果數，不能宣稱必定 OOM。D34 不解決單題 RAM，也不保證零複製或更快；當時控制證據見 [17](17_invocation_comparison_experiment.md)。

## 軟體異常時的保存責任

求解完成、結果保存及管理端確認交付是不同事實。D25 另要求範圍內 Python 軟體保存失敗的實際原因與 task 事後可查，不只記「失敗」；產生原因、通知及持久保存也不是同一時點，通知成功不自動達標。正式留因時序／責任方／位置／完成判定及二次失敗／退出界線依 [15](15_task_failures_and_result_storage.md#保存錯誤原因的留存界線) 待確認，不降成最佳努力或默選 worker-first artifact。

沒完成通知不能反推求解失敗；錯誤 artifact 存在也不等於結果交付，D38 不自動讀檔補登／重試。原型只測特定 TypeError 加通知截斷，不保證任意 kill、錯誤紀錄再發生軟體錯誤或任意原生損壞；這些待確認範圍不自動列入 D26，亦不改 D40。

算法錯誤依 D79–D80 停止整場，包含可捕捉錯誤、致命崩潰及其他算法正在求解的 task；不再啟動新 task，不自動重跑，已保存結果保留。原生求解異常只要求保留實際輸入，不要求 Python 診斷 C++ 根因；正常不可行結果不是此處的執行錯誤。

Python 保存錯誤依 D40，不一律改為算法錯誤全場停；不加自動超時或內建單 task 人工停止。管理端先保留輸入與實際 task 執行關聯，再指派及等待事件。實體 host 退出時，先處理各題已交付通知、逐 task 判定完整回報；已交付不撤銷，缺完整回報者記未確認、保留文件與事實，不自動核對／補登／重跑。清理成功且環境可信才重用，否則不再重用該不可信環境；舊基線替換程序，新拓撲的範圍／時機依 [14](14_python_cpp_invocation_and_failure_replay.md#執行名詞與替換範圍) 待確認，不默選退休提案。安全收尾、未知退出、通訊／監督及格式仍待細化。

磁碟滿、磁碟故障等硬體／資源層異常已明確排除，不為此增加獨立磁碟、另一台機器或錯誤保存服務。此範圍不變更完整歷史的既有 RAM 風險；完整規則見 [15](15_task_failures_and_result_storage.md)。

## 此版明確接受的限制

單個任務的全部歷史至少必須在求解期間保留於記憶體。基本估算為：

```text
歷史大小 ≈ 提交次數 × 每次保存的編碼、適應值、外部狀態大小
```

種群越大、編碼越長、提交越頻繁，成長越快。緩存重用能減少重新配置工作記憶體，但不能讓已保留的所有不同歷史免費存在。

多 worker 同時求解、C++ 轉 Python 與保存前暫存仍可能增加尖峰。D34 不再讓完整歷史預設從 worker 傳給主程序，但這不保證 bounded memory、零複製或超大題不會 OOM。

這是使用者選擇延後處理的已知風險，不可暗中改成截斷、抽樣、只記錄摘要或增加背景服務。

若任務在回傳前崩潰，記憶體內尚未交付的歷史可能一起失去。此版也不承諾每次 addAct 都已落盤或斷電不丟；完整求解歷史的中途 durable 保存不在目前設計內。

但失敗 task 的實際起始輸入必須能保留，讓研究者事後從頭單獨重跑。這是實驗側任務邊界的輸入保存與異常追蹤，不是 addAct 分批輸出，也不依賴崩潰程序正常返回。需求與未定機制見 [14](14_python_cpp_invocation_and_failure_replay.md)。

## 討論過但本版不採用的方案

| 方案 | 原本想解決什麼 | 本次不採用的原因／狀態 |
| --- | --- | --- |
| 求解／addAct 期間自行分批寫檔 | 限制歷史累積。 | 增加算法或狀態紀錄的文件 I/O，未獲接受；不同於完整交付後的獨立輸出元件候選。 |
| C++ 同步分批交 Python | 保持保存責任在實驗側。 | 會暫停求解等待保存；本輪改選全部完成一次交付。 |
| 背景 writer | 嘗試讓 I/O 與搜尋重疊。 | 使用者認為增加複雜度，先擱置。 |
| Redis | 嘗試減少寫入等待。 | 未實測；不能當成解決完整歷史 RAM 問題的保證。 |
| 大量實驗只留摘要 | 降低紀錄量。 | 與使用者全部任務完整保留的決定不符。 |

以上不是另一組待實作選項，除非使用者重新開啟此議題。

## Problab 提供的參考及限制

Problab 大量模擬每局更新統計，下一局重用工作緩存；詳細開發入口則累積有限局數，算完一次返回。它支持「計算與輸出分開」的責任概念。

它也將內部結果轉為對外 DTO，再由 HTTP 入口輸出 JSON。DTO 是交付資料，不是 Web 專用；本系統可借用此分層，外層改成文本輸出，但不代表已決定 DTO 型別、格式或輸出器語言。D34 的同步 task 保存位置與主程序只收摘要／路徑已定，不因這個參考重開。

但它不是替數千次大型求解保留全部歷史而仍固定記憶體的證據，也不能把一次優化迭代當一局清空舊 addAct 來假裝滿足本需求。來源見 [12](12_prior_work_and_references.md)。

## 後續實作必須驗證

依 [14 的比較維度](14_python_cpp_invocation_and_failure_replay.md#架構狀態與比較維度) 與 [19 的候選證據](19_architecture_candidate_experiments.md) 確認組合，並按 [本章對照](#已確認交付需求與保存基線) 列出輸出器語言、完整返回 Python 及所有權差異；沒有因測過就替換舊基線。cleanup 退休及 worker-first 錯誤 artifact 尚未定案，不據此改 D40 或正式留因時序。停止期間仍須維持結果與共享資料有效，不因收到停止要求就提前釋放。

- 每筆紀錄順序與內容完整，nil 不被誤轉成其他狀態。
- 返回後資料仍有效，不因釋放 C++ 工作空間而懸空。
- 健康程序接下一題後，前題已交付但仍被使用的歷史不會被清理或覆寫；不讓不應保留的本題資料跨任務累積。
- Python 保存失敗要清楚回報，不能把回傳成功當成磁碟保存成功。
- 保存原因與 task 關聯可查，按 [14 的層級與 D40 範圍](14_python_cpp_invocation_and_failure_replay.md#執行名詞與替換範圍) 驗證可信環境重用／不可信環境不再使用及候選連帶影響；僅健康且整場未停止時同鏈才接新題。host 退出按 [事件案例](15_task_failures_and_result_storage.md#十個事件案例) 逐 task 判定，不撤銷已交付結果。
- 每個任務各自回傳，不隱含要求整場批次一起留在 C++。
- 保存格式及壓縮策略尚未決定；不要把「一次回傳」誤解成只能建一個巨大 JSON 字串。
