## 狀態用語

- **已確認**：使用者已明確接受的需求或責任，不因整理文件而重新變成建議。
- **待討論**：提出過或有合理方向，但尚未接受具體方案；範例不是正式 schema。
- **延後處理**：知道有需求或風險，現在明確不納入實作。
- **現況核對**：2026-10-21 查閱程式／既有文件所見，不代表目標設計已實作，也不代表重新跑過測試。

細節文件可以同時包含不同狀態；以各節標示為準。不能因為某份文件標題出現某個技術，就認定它已被選用。

先前 D27–D29：其他正常 task 不取消、不重跑；本版不加入自動超時；重用健康程序，每題狀態獨立、正確交接後清理。結果仍被使用時不得提前釋放，不以舊核心未整理好的記憶體增長選型。

先前 D30–D35：首版 Linux／WSL、不內建單 task 停止命令、Python 只需完整求解 API、Python 命令可單獨重跑、worker 同步保存並只回摘要／位置，以及同程序 C++ 擴充模組。

本單元新增 D36–D40：主程序先保留輸入及 worker／task 對應再指派，等待訊息與退出事件；worker 回報已接收及 C++ 正常返回。退出時先處理已交付通知，缺少完整最終回報則保留現況，不自動核對／補登／重跑。非預期 C++ 錯誤替換該 worker；Python 保存錯誤依清理結果決定重用或替換。task 結果與 worker 健康分開，不因退出推翻完整回報。

十案例只核對規則一致性，不代表正式 IPC 或故障恢復通過；正式通訊／監督、狀態保存格式及資料所有權仍待細化。文件更新完成後停止，下一單元預定討論固定問題數值如何交付與共享（Q3.2）。
