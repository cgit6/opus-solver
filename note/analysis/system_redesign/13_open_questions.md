# 13｜待議清單與下一步

整理日期：2026-10-22。用途是讓討論有限收斂，不把所有已確認事項反覆重開。

## 先不要重開的事項

- 問題判定、算法搜尋、求解任務最終驗證、實驗管理安排與記錄。
- 真實目標與搜尋罰分分開，允許正確增量更新。
- addAct 只記錄、不評估、不消耗 RNG；算法作者維護完整小操作的同步。
- 所有任務每次實際提交全量保留，外部為 nil 則照實保存。
- C++ 每個任務完成、驗證後一次返回；Python 保存。
- 此版接受單任務完整歷史可能耗盡 RAM，記憶體改善後議。
- task 發生非預期情況時，實驗側保存其實際輸入與已知異常資訊，供日後單獨從頭重跑；不要求 Python 診斷 C++ 根因。
- 單一 task 系統軟體流程異常後留下紀錄、必要時替換 worker，再處理下一個新 task，不中斷整場，不默認重試原 task。
- Python 寫檔異常須保存原因；不處理磁碟滿／磁碟故障等硬體／資源層情境，不增加獨立保存媒介或服務。
- D27：一個 task 出錯，不取消、不重跑其他正常 task，固定 seed／迭代下的過程與結果仍須驗證不變。
- D28：本版不加入卡住後自動超時中止；一直未完成但沒有明確錯誤／終止的工作暫由研究者人工處理。
- D29：重用健康的求解程序，每題狀態獨立、交付後正確清理；只替換出問題的單元。結果仍被使用時不得提前釋放或覆寫。
- D30–D33：首版 Linux／WSL；不內建單 task 停止命令；Python 只需完整求解 API；失敗 task 可透過 Python 命令從頭單獨重跑即可，不要求 Python-free 入口。
- D34：worker 同步保存該題，主程序只收摘要與檔案位置；保存完才接下一題。
- D35：Python worker 內同程序 C++ 擴充模組；原生崩潰時只替換該 worker，其他正常工作繼續。
- D36：主程序先保留實際輸入與 worker／task 對應，再逐題指派；等待訊息及退出事件，不反覆掃描。
- D37：worker 通知已接收任務及 C++ 已正常返回；只記收到的事實，兩者不代替完整最終回報。
- D38：退出時先處理已交付通知；缺少完整最終回報就保留輸入、現有文件及最後已知事實，不自動核對、補登或重跑。完整回報不因後續退出被改寫。
- D39：非預期 C++ 錯誤即使已捕捉也替換該 worker；不含正常不可行或已知輸入錯誤。
- D40：Python 保存錯誤保留實際原因與 task 對應；清理成功且狀態可信可重用，否則替換，不自動重求解或重試保存。

除非遇到具體衝突或使用者要求，以上不再當成尚未決定的選項。

## 下一個先討論：第三項尚缺部分

### Q3.1｜政策已確認：task 對應、異常與 worker 恢復

- D35–D40 已確認呼叫、派工、兩種階段通知、交付未確認及替換政策；不再重選 A／B、不自動核對文件補登成功，也不自動重跑。
- [十個事件案例](15_task_failures_and_result_storage.md#十個事件案例) 已核對管理端知道什麼、記錄什麼、如何處置。已收到完整成功回報後 worker 再退出，不得把該題改記失敗；觀察退出時先處理已交付通知。
- 尚待細化的是正式通訊格式、事件等待／監督實作、狀態保存格式，以及訊息完整性與退出交錯的整合測試；不是政策再次待選。
- 正式函式簽章、binding／建置、Python 重跑命令與完整結果所有權亦待後續細化；本次不直接實作求解模組。
- 停止點：本單元文件更新後停止；案例推演不算正式 IPC 或故障恢復驗收，第三項與 G2 也未因此全部完成。
- 來源：[14](14_python_cpp_invocation_and_failure_replay.md)、[15](15_task_failures_and_result_storage.md)、[17](17_invocation_comparison_experiment.md)。

### Q3.3｜設定讀取與位置最後收斂

- 算法預設值由誰提供，如何保存本次有效參數？

- 停止點：用 MKP／SCVRP／連續題各一例走完，不必搬目錄才算討論完成。
- 來源：[02](02_problem_data_and_configuration.md)。

### Q3.4｜已選 worker 保存後的 DTO 與交付確認

- D34 已確認 worker 同步呼叫共用 Python 輸出器，主程序只收摘要與位置，不再比較保存位置。
- 結果 DTO、摘要、錯誤原因與 task 對應如何表示？同一套輸出程式不代表共用可變 writer 或同寫一個檔案。
- D38 已確認退出且缺少完整最終回報時的交付未確認政策；不自動核對文件、補登成功或重跑。完整回報的表示、部分文件與正式輸出格式仍待定。
- D40 已確認保存錯誤保留實際原因、依清理結果重用或替換；具體記錄與實作待定，不另討論硬體／資源層故障備援。
- 停止點：依已確認政策細化正式 DTO、摘要、輸出格式與所有權，再用通知／退出交錯及清理案例驗證可追查、已交付結果不被撤銷、後續新 task 正常執行。
- 來源：[07](07_history_return_and_storage.md)、[15](15_task_failures_and_result_storage.md)、[17](17_invocation_comparison_experiment.md)。

## 延後區：不是這次實作待辦

- 歷史分批交付、背景 writer、Redis、容量上限與壓縮／差分策略。
- 算法中途 checkpoint／RNG 恢復；完整觀測紀錄不等於可恢復狀態。
- AI 正式模型訓練、資料／切分／模型產物位置、評估 RNG 與訓練錯誤。

磁碟滿、磁碟故障等硬體／資源層專用處理及獨立錯誤保存媒介，屬於本版明確不納入的範圍，不是延後區裡等待重開的需求。
