# 08｜跨語言資料交接與共享記憶體

狀態：D35 已選 Python worker 內同程序 C++ 擴充模組，D34 已選 worker 同步保存。正式資料表示、所有權與問題數值 SHM 仍未定案，不因呼叫選型或控制原型就直接定案。對應 D27–D40、P01–P03、P07、P09。

「Python 如何呼叫 C++」及其故障範圍、開發測試、異常輸入保存與單 task 重跑，已獨立收錄於 [14 呼叫與失敗任務重跑](14_python_cpp_invocation_and_failure_replay.md)。本章集中於數值交接與共享資料的生命週期。

## 已有的邊界

- Python 安排一個完整求解任務。
- 傳統問題的搜尋、objective、constraints 與最終驗證在 C++ 內完成。
- C++ 在任務結束一次回傳最終結果與全部紀錄；Python 保存。
- 不在傳統問題每次 objective 呼叫時返回 Python。

以上是責任與頻率。後續已選同程序擴充模組與 worker 保存，但正式 binding、共享記憶體與所有權細節仍須獨立確認。

## 呼叫與資料交接的關係

D35 已選同程序 C++ 擴充模組，並在主程序外隔離執行；D29 的健康程序重用及 D34 的 worker 保存不變。選型依本輪對照與使用者確認，不是恢復「配合舊流程所以優先 A」的理由。每題狀態獨立、只替換必要 worker、其他正常 task 不取消／不重跑及異常輸入可重建仍須滿足。

D32 已確認 Python 正式 API 只需一個完整求解能力，不要求逐步算法介面；函數名稱、參數及結果 schema 尚未定。呼叫決策見 [14](14_python_cpp_invocation_and_failure_replay.md)，控制對照見 [17](17_invocation_comparison_experiment.md)。

不能把語言交接與程序交接混為一談。已選擴充模組在 Python worker 內返回，由該 worker 同步保存後只向主程序交摘要與位置；不再把整份歷史交主程序。這沒有取消跨 worker 共用唯讀題目數值的需求，也不能因 SHM／buffer 名稱就推定全程無複製。保存與已確認的通知政策／待細化機制見 [15](15_task_failures_and_result_storage.md)。

D36–D40 的派工與異常政策不決定資料所有權：主程序派工前要有可重建輸入，並不等於每題複製整份數據。固定數值傳值或共享、持有者、釋放及轉換成本是下一單元（Q3.2），本次未作新決定。

## 使用者提出的共享記憶體方向

```text
Python 讀取題目固定數值
  → 必要時放入共享記憶體
  → 分派 task 時交付必要數值或存取資訊
  → 執行中的 C++ 直接使用準備好的本地可存取資料
```

方向合理，但使用者也明確要求後續再評估，不能現在直接宣告所有數值都必須 SHM 或一定零複製。

## 哪些資料可能共享，哪些不該共享可寫狀態

| 資料 | 目前候選做法 | 原因 |
| --- | --- | --- |
| 同題重複任務的 values／weights／座標／距離等固定大陣列 | 共享唯讀資料，或量測後採一次傳值。 | 避免各 task 重複載入同份大數據。 |
| seed、少量算法參數、迭代上限 | 隨 task 傳值。 | 小資料不一定值得額外管理 SHM。 |
| population、trial、容量工作緩存、RNG | 每個任務自己持有。 | 不同 seed／算法執行狀態不能互相覆寫。 |
| addAct 歷史 | 本任務獨立保存，完成後返回。 | 不把題庫共享記憶體誤當成全量歷史儲存。 |

worker 的 Python 執行環境與算法工作空間，不會因題目資料有 SHM 就全部共用。這是先前記憶體討論中特別需要澄清的地方。

健康程序可跨 task 存在，但本題的 RNG、population、工作狀態與歷史仍須獨立初始化及正確交接／清理。共享唯讀題目數值則依其擁有者與使用者生命週期管理，不因某個 task 結束就提早移除，也不因程序重用就變成可共用的可寫算法狀態。

## 原始數值與衍生數值的責任

- Python 可以載入原始數值，但不因此取得問題數學定義的責任。
- 距離捨入、限制式衍生表、可行性相關轉換，必須遵循問題規則。
- 同一題多次求解可共用適合共享的衍生唯讀資料；建立一次的位置與型別需明確。
- 不允許 Python 和 C++ 各用不同距離規則，又把同名矩陣視為同一道題。

若問題需要算法專用 lookup table，應區分是共通問題資料，還是算法內部緩存；不一律搬到實驗管理。

## 生命週期需要回答什麼

以下是下一輪要決定的問題，不是已實作契約：

1. 誰建立及擁有共享區？是否由父程序統一管理？
2. worker 何時附接、何時釋放自己的存取？
3. 所有使用者結束前，如何避免提早移除資料？
4. C++ 保存的視圖能否跨越 Python 物件或共享區的生命週期？
5. 形狀、型別、排列不符時，拒絕還是明確轉換／複製？
6. 結果仍被使用時不得提前釋放已是原則；worker 輸出器如何持有完整歷史，何時能回收 C++ 記憶體？binding 或保存格式是否又建立完整副本？不預設再向主程序交完整歷史。
7. task 異常後如何取得當時的實際輸入？不能只留下已釋放的 SHM 名稱或可變來源路徑；需要另保留可重建的數據。

memoryview 或 buffer 介面名稱本身不等於保證零複製。需要實際型別／布局／持有者符合要求，並檢查傳輸全程。
