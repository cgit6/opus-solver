# 09｜實驗安排、算法支援與統計

狀態：D41–D73 的分組、讀取、停止及輸入規則保留，D47 判重鍵不變；D74–D78 補足求解前題目準備、共享生命週期及未知題目欄位拒絕。完整設定讀取交接、C++ 停止機制與支援查詢、輸入紀錄格式及統計仍待實作前細化；D79–D80 將算法錯誤改為停止整場，Python 保存錯誤依 D40。對應 D24–D80、P04–P05、P08–P10。

## 使用者的實驗需求

- 一般實驗固定讀 cli/run/run_cfg.yaml，不提供命令列換檔或實驗參數覆寫；從專案根目錄執行 .venv/bin/python -m mkp.cli.run。題庫／參數目錄固定，錯誤位置或固定檔無法讀取／解析時不派工、不改讀其他設定，詳見 D65–D67。
- 實驗模組根據分組選題、算法參數組與有效 seed 清單展開任務；不派生 seed，不另設 repeat。
- 希望同一次實驗能跑不同問題類型下的多題／題庫，前提是算法支援。
- 原始結果保留，以便不同研究報告採不同統計方式。
- 高併發與問題資料共享要一起考慮，而不是只增加 worker。

多問題需求不表示任意算法都能解任意問題，也不表示不同目標值可直接混成一個平均。

## 一般入口和 seed 收集入口不能混淆

現況：

- [cli/run/main.py](../../../cli/run/main.py) 是一般模擬入口。
- `cli/exp` 用於根據特定條件收集 seed，會使用共同的下層模擬能力。
- `cli/exp/exp_cfg.yaml` 不是一般實驗安排的通用設定範本。

重構應沿著共同執行流程整理責任，但保留兩種入口不同的使用意圖。不要只因名稱叫 exp，就拿它定義所有未來實驗格式。

D41 的明確 seeds 與不派生規則針對一般實驗，不移除 cli/exp 的 seed 搜尋／收集流程。一般批次與指定配對重跑使用同一種安排格式，並非把不同用途的全部設定都併成一個 schema。

D65–D67 的固定設定與啟動限制同樣只針對一般入口；目前 cli/run 仍使用命令列業務參數，尚未建立 run_cfg.yaml 或加入位置檢查。兩段設定範例重構後都寫入同一固定檔，由研究者修改內容，不透過命令列選另一檔；本次不修改任何入口程式。

## 目前支援檢查怎麼做

[cli/run/support.py](../../../cli/run/support.py) 的 `validate_execute_args()` 讀取題目 metadata，檢查 solver YAML 的：

- problem_types。
- encodings。
- directions。

例如 [cdels.yaml](../../../configs/solvers/cdels.yaml) 宣告 SCVRP、route／transfer 編碼與最小化。拿它跑 MKP，這條一般 CLI 路徑會在預檢拒絕。算法 adapter 本身也有型別限制。

目前一般入口還要求一個 solver，且不能混用 problem_type／encoding／direction；不能把未來跨問題實驗需求寫成現在已支援。

## 未來支援清單要解決的問題

| 問題 | 需要明確化的責任 |
| --- | --- |
| 算法支援哪些題型／編碼／方向？ | 宣告應由算法實作及其維護者負責，不能僅靠研究者手填任意配對。 |
| Python 如何知道 C++ 有哪些算法？ | 由呼叫契約暴露或取得支援資訊；具體查詢方式待定。 |
| YAML 和 C++ 宣告不一致怎麼辦？ | 不能各自維護互相矛盾的有效清單；權威及同步方式待定。 |
| 某些組合不支援？ | D46 已確認啟動前列出不支援配對，整場不啟動；不自行跳過或先跑合法配對。正式查詢與診斷格式仍待定。 |
| 群組的停止設定是否支援？ | 須確認選定主要方式、零次初始化及已啟用的達標／無改善選項，不支援時整場不啟動；查詢仍待定，不因支援題型就推定全部停止能力，也不由 Python 猜測或覆蓋。 |

這裡的相容性預檢是任務安排責任，不是實驗側重算 objective 或驗證最終解。

## 多問題任務展開：已確認規則

一場研究包含 MKP 題與 SCVRP 題，選用的算法只支援 SCVRP，就不能直接對全部題目做笛卡兒積，然後把 MKP 失敗當正常樣本。

具體按 D41–D47：

- 每組一種問題，可有多個題庫；題庫可選 all 或明列題名。整場可有不同問題的多組。
- 最上層 seeds 預設全場共用；組內另寫則只用該組清單，不附加、不合併。
- 每組所有選定題目，分別搭配各算法的每個選定參數組及每個有效 seed；不同組不配對。
- 參數另外存檔，實驗選組；task 保存完整有效數值與明確 seed，不能只存索引或重新派生。
- all 在本次啟動前展開並記錄實際題目清單；不能以日後重新掃描當作原範圍。
- 相同問題類型／題庫／題名／算法／參數組／seed 重複出現時，依 D47 指出來源，整場不啟動；不自動去重或重複執行。

D50–D57 另確認：算法可設定參數必須明寫，停止設定由實驗群組唯一提供，明選迭代數或求解時間及數值，並明列是否達標提早停止；C++ 負責實際執行。開啟達標停止卻缺已知最佳值時整場不啟動，可行解以原始目標作方向比較，不設容許差。時間範圍與檢查點見 [02](02_problem_data_and_configuration.md)。這不把預處理、最終驗證或 Python 寫檔算成算法求解預算，也不新增 worker 強制超時。

D58–D64 補足：初始化不算迭代，完成整輪才加 1，允許 0 次只初始化；達標於初始化後及整輪後檢查，不額外 evaluate。每組必填無改善輪數，正整數啟用、null 關閉；它保留主要上限，依算法歷史最佳解的嚴格規則累計，和重啟計數分開。停止欄位及型別見 [18](18_experiment_configuration_and_task_expansion.md#已確認的群組停止欄位)；開啟無改善不要求題庫目標，但若同時開啟達標，D56 不豁免。

保留 D47：停止設定不同不構成判重例外。同題、算法、參數組及 seed，分在 1,000／5,000 代兩組仍拒絕整場啟動；停止設定須記錄，但不加入判重鍵。

每組 task 數＝選定題目數 × 各算法所選參數組數的合計 × 有效 seed 數。算法參數不是跨算法互相組合；同名但不同題庫的題目也須保留各自身分。

同一種格式可用兩組分別描述「題 1／seed 3」與「題 3／seed 5」，而不是把兩題與兩個 seeds 交叉展開成四筆。D48–D49 允許將不同原實驗的失敗 task 整理到同格式設定，讀本次指定題庫與參數檔，不按原實驗拆開，不新增歷史來源欄位或自動恢復數值。若要重現原 task，實際輸入一致由人維護；系統保存本次實際值，不因歷史差異自動比對、阻擋或修正。完整草案、120＋2＝122 筆計數及四種讀取情境見 [18](18_experiment_configuration_and_task_expansion.md)，不是正式重跑命令已完成。

上述是啟動前設定預檢；執行中算法錯誤另依 D79–D80 停止整場，不能把預檢失敗、正常不可行或 Python 保存錯誤一律改列算法錯誤。

## 預處理與正式求解的分界

- D78 的題目未知欄位檢查屬啟動前輸入檢查：指出題目及欄位，整場不啟動；不忽略、猜測、修正或先濾掉欄位。專用規則仍由 C++ 問題模組負責，正式預檢交接待定。
- 同一題的多個 seed／算法 task 共用固定資料，避免按 task 重複準備；全部選中題目備妥才正式求解。D74 已選的隔離 worker 逐題準備是原交接基線。
- 求解端唯讀保護與 task 可變狀態／RNG 私有是不變要求；D75 的先算搬入 SHM、D77 的主程序持有與每 task 連接／解除是原交接基線。新候選偏離時依 [08](08_cpp_invocation_and_shared_memory.md#不變需求與原交接基線) 列差異待確認，不自動換機制。
- 任一題預處理失敗，記錄原因，不進入正式求解。此時正式求解尚未開始，與 D79–D80 的求解中算法錯誤停止分開；不是任意 task 錯誤一律停止。
- 原交接基線在 task 使用及同步保存完畢後解除本 task 存取，由主程序在整場結束且所有使用者釋放後清理；新候選也須確保 task、結果與保存方仍在使用時不提前回收。

這些不變要求與原交接機制均有確認依據，不是正式派工、唯讀映射或共享資料交付已完成；新候選的機制差異仍須確認。原始來源、H01–H08 及分層對照見 [08](08_cpp_invocation_and_shared_memory.md#不變需求與原交接基線)；題目未知欄位的 W01–W05 見 [18](18_experiment_configuration_and_task_expansion.md#題目未知欄位規則核對)。不改變 D54 排除預處理的求解計時口徑，也不在本章新增歷史副本自動恢復。

## 不可行解的統計：問題已記錄，規則未定

求解結果不可行仍正常完成，原始解、真實目標值與 feasible=false 必須保留。

但不能默默把不可行目標值和可行解放在一起比較「誰更好」。待討論項目包括：

- 可行率／成功率的定義與分母。
- objective 平均值是否只計可行結果，是否另列全樣本描述。
- 全部 seed 都不可行時，報表怎麼表示，不偽造零分。
- 算法自身錯誤、連帶停止、尚未啟動、保存失敗、交付未確認及正常不可行結果如何分列與設定分母；不能偽造零分或默默隱去異常 task，正式狀態名稱仍待定。
- 跨題目、不同單位／方向如何分組，是否需要正規化或排名。

以上是待設計項，不是已選定某種統計公式。

## 保存與中斷

完整回傳是單 task 粒度；D34 的同一邏輯工作鏈在求解完成後同步保存／交接及清理，再接下一題，主程序只收摘要／路徑，不要求同 host 其他鏈等它保存。task、host 與 worker 依 [14 名詞表](14_python_cpp_invocation_and_failure_replay.md#執行名詞與替換範圍) 區分；正式檔案格式、通訊／監督及整場續跑仍待設計。

異常 task 的實際輸入保存與事後單獨重跑則已確認為需求，不能等正常結果返回才處理，也不和整場自動續跑一起延後；呼叫方式與故障邊界見 [14](14_python_cpp_invocation_and_failure_replay.md)。

目前 [cli/run/support.py](../../../cli/run/support.py) 通常等整批 Simulator 結束才呼叫 writer；[tools/show.py](../../../tools/show.py) 還會重設 variant 輸出目錄。未來若改任務級保存，必須一起核對，避免完成後又刪掉先前紀錄。

SCVRP 專用資料驗證命令已有自己的 plan／逐任務保存機制，不代表一般實驗入口已支援相同續跑。這兩條能力不可混稱。

最新 D79–D80 要求非預期算法執行錯誤（可捕捉錯誤或致命崩潰）停止整場，包括其他算法及正在求解的 task；不再啟動新 task，不自動重跑，已保存結果保留。正常不可行仍正常保存；Python 保存錯誤仍依 D40，不擴大為算法錯誤。

D36–D40 要求先記實際輸入與 task 的執行關聯。實體 host 退出先處理各題已交付通知，逐 task 判定完整回報；缺回報者記未確認，不自動核對／補登／重跑，已交付結果不撤銷。D40 清理成功且可信才重用，否則不再用不可信環境；舊基線可換程序，新拓撲的連帶範圍／時機依 [14](14_python_cpp_invocation_and_failure_replay.md#執行名詞與替換範圍) 待確認。替換不增加 task 重跑，也不把普通保存錯誤全場停；報表欄位、分組與分母仍待定。

算法錯誤的連帶停止是已接受範圍，不再記為違反「其他 task 必須繼續」要求；但連帶停止不能冒充成功、不可行或算法自身錯誤，不自動重派。本章不先決定統計分母、狀態 enum 或退出碼。正常運行每題 RNG／狀態仍獨立；停止時點、安全收尾及未知原因退出判定待架構細化，不加入卡住超時。

求解異常保留輸入／已知事實，不要求 C++ 根因；D25 的範圍內 Python 軟體保存失敗則要求原因與 task 事後可查，不只記失敗或收到通知。正式留存機制及二次軟體失敗／留存前退出的保障依 [15](15_task_failures_and_result_storage.md#保存錯誤原因的留存界線) 待確認；不降低要求、不宣稱已全涵蓋，也不將這些自動排入 D26。磁碟滿／磁碟故障等硬體／資源層專用處理仍排除；artifact 不能充當結果成功交付或報表成功樣本。

D34 的同步 task 保存位置及主管只收摘要／路徑保留；Python 輸出器是有效舊基線，候選語言及 D18 返回差異依 [07](07_history_return_and_storage.md#已確認交付需求與保存基線) 待確認。D35 是重新評估基線，[19](19_architecture_candidate_experiments.md) 已有候選控制證據，仍依 [14 的維度](14_python_cpp_invocation_and_failure_replay.md#架構狀態與比較維度) 確認組合，未選架構、搬移排程或改好一般入口。正式報表需確認摘要足以彙整，詳查可按需讀已存文件，不在主程序保留整場完整歷史；統計分母／排名尚未定，整場重啟跳過完成 task 仍是後續功能。

## 本章驗收方向

多問題任務展開應先只測小型組合：合法配對、不支援與重複、同名但不同題庫、明確 seed、參數組、不可行及執行失敗。先驗證任務清單與分組，再談大量執行效能。

先前 [18 的 V01–V06](18_experiment_configuration_and_task_expansion.md#本輪推演證據與限制) 有 80／2／122 筆選題推演，R01–R04、S01–S14 與 [T01–T21](18_experiment_configuration_and_task_expansion.md#本輪-21-項獨立模型核對) 則是讀取及停止模型；本次保留數據、不重跑這些整組模型。D65–D67 另以 [L01–L04](18_experiment_configuration_and_task_expansion.md#固定設定與啟動情境核對) 核對固定讀檔規則，不是正式入口、C++ 停止機制、支援 API、完整重跑或統計驗收。固定設定及一般命令不再待選；Python／C++ 輸入交接、支援查詢及同時符合多停止條件的結果表示仍待對應單元細化，不可行與執行失敗的統計規則也不因此定案。
