- 題庫設定與實驗參數數值：實驗人員維護，確保數值符合研究目的。
- 題目欄位的數學意義與必要條件：問題開發者定義。
- 算法參數意義、必要欄位、合法範圍及支援的停止方式：算法開發者定義；可提供完整範例，但執行時不自動補預設值。
- 設定載入與任務交接機制：系統實作。

同一個人可以兼任以上角色；「責任不同」不是要求多人維護。

### 誰讀取與準備：原則已確認，正式交接待細化

以下是 D74–D77 原交接基線的讀取與準備安排；不變需求及新候選偏離時須確認的差異，統一見 [08 的分層對照](08_cpp_invocation_and_shared_memory.md#不變需求與原交接基線)。

1. Python 讀實驗設定，知道需要哪些題目及參數組。
2. Python 讀共同的題目設定與原始數值，保留專用檢查所需內容，不先轉型或刪未知欄位來掩蓋錯誤。
3. 一個隔離 worker 逐題呼叫 C++ 問題模組，依數學規則準備本次選中題目的固定資料；衍生資料先算好，再搬入共享記憶體一次。
4. 全部題目準備成功後才分派正式求解；任一題準備失敗，記錄原因，不進入正式求解。
5. 各正式 task 按需連接唯讀題目資料，算法使用準備好的數值及本地 evaluator；使用與保存結果完畢後解除本 task 的存取。

例如同一題城市座標搭配 10 個 seed，距離表不由 10 個 task 各自重算。資料不依附準備者、仍有人使用時不提前回收是不變要求；主程序持有、先算再搬及每 task 連接／解除是 D74–D77 確曾選定的原交接機制。沿用時繼續細化實作，新候選若改機制則列差異待確認，不自動替換或把原決定說成未定。正式 API、傳遞內容、資料描述與映射／回收仍依 [08](08_cpp_invocation_and_shared_memory.md#不變需求與原交接基線) 細化，不宣稱零複製。

### 題目未知欄位政策，已確認

D78 於 2026-10-23 新增確認：選中的題目 YAML 含問題模組不認識的欄位時，指出題目及未知欄位，整場不啟動。即使必要欄位已齊全，也不能警告後忽略；例如已有正確的 capacities，又多寫 capacties，仍須指出多出的拼錯欄位，不猜測哪一個才是研究者想用的數值。

## 第 3 單元子題：數值型別與轉換規則，已確認

D72–D73 適用題目與算法參數的外部輸入，由 D69–D70 所屬 C++ 問題／算法模組執行專用檢查：

| 目標欄位 | 已確認的輸入規則 | 邊界 |
| --- | --- | --- |
| 整數 | 接受整數 20，拒絕浮點 20.0、20.7、字串及布林值。 | 數值剛好是整數也不能把浮點輸入視為整數；不先截斷或四捨五入。 |
| 浮點 | 接受浮點輸入，也接受能精確表示於目標型別的整數，例如 100；不接受字串或布林值。 | 整數轉換會失真或超出欄位合法範圍就報錯；不能只因轉換結果有限就接受，也不一律拒絕大整數。 |

原輸入的型別與數值必須保留足夠資訊供檢查，不能先 int()、astype() 或以整數 dtype 建陣列，讓 20.7 變成 20，再宣稱 C++ 已檢查原輸入。即使 20.0 轉成 20 不改變數值，也不符合 D72 的整數型別要求。這只約束外部輸入檢查，不改算法內部原有取整操作或問題明定的距離捨入規則。

例如假設某欄位明定使用 binary64／float64，整數 9007199254740993（2**53＋1）轉換會失真，必須拒絕；9007199254740994（2**53＋2）可精確表示，若也符合欄位範圍與其他條件便可接受。因此不能簡化成超過 2**53 一律不准，也不能據此把所有整數欄位先轉為浮點。此為示例，不是為所有問題或算法選定 float64。

現況核對（2026-10-23）：[BSCA](../../../solver/BSCA.py) 目前以 int() 讀取種群數；[MKP loader](../../../problem/mkp.py) 在建立模型前以 int()／np.asarray(..., dtype=int) 轉換部分欄位。[連續問題](../../../problem/continuous.py) 則會把邊界整理成 float64。這些是現有實作，不代表已遵守 D72–D73；本次不修改或宣稱已修正。

D61 的停止設定型別不變。正式檢查／轉換 API、具體位寬與浮點精度、其他跨精度轉換、陣列布局、共享資料描述及交付實作仍待細化；D74–D77 的不變需求與原交接基線依 [08](08_cpp_invocation_and_shared_memory.md#不變需求與原交接基線) 核對，不把原機制當成未定，也不免除新候選的差異確認。不在本輪加入通用浮點預設值。案例與限制見 [18 的 N01–N10](18_experiment_configuration_and_task_expansion.md#數值轉換規則核對) 及 [08](08_cpp_invocation_and_shared_memory.md#已確認的數值型別與轉換邊界)。

## 第 3 單元子題：參數明寫與群組停止條件，已確認

### 設定提供什麼，誰負責執行

- 算法參數檔明列可由實驗設定的參數。缺少就報錯，不由 Python 或 C++ 補值；例如算法要求種群數，就不能因沒寫而自動用 20。
- 算法內部常數、依題目尺寸計算的緩存大小，不必為此全部移入 YAML。完整參數範例可由算法開發者維護，供研究者複製修改，不是執行時隱藏預設。
- 每個實驗群組明選迭代數或求解時間及其數值，明寫達標開關及連續無改善輪數或 null。算法參數組不另設上限，不再和群組設定互相覆蓋；主要上限或任一已啟用提早停止條件成立，即可正常結束。
- Python 讀取設定、安排與記錄實際輸入；C++ 算法執行停止判斷。不支援所選方式、達標／無改善選項或零次初始化用途時，啟動前報錯、整場不啟動，不自行退回其他方式或暗改數值。
- task 的實際輸入紀錄包含完整算法參數及群組停止設定，不能只留參數組索引。這仍是 D23、D45 的記錄責任，不變成自動恢復歷史值。

這些是重構目標，不是對現有算法的行為描述。目前 [BSCA](../../../solver/BSCA.py) 仍會為部分缺漏參數補值，也會在個體更新後因達標直接返回；[CDELS](../../../solver/CDELS.py) 的正式入口則要求完整參數、正整數上限及固定迭代。現有 [算法設定](../../../configs/solvers/) 的停止上限仍放在算法檔，本次沒有修改它們。未來統一達標檢查點會改變原有提早停止時點，不能未經對照就宣稱舊軌跡不變。

### 迭代計數與零次初始化

初始化不算一次迭代。設定 1,000 次，表示先完成初始化，再完成 1,000 整輪更新；不是初始化加 999 輪。每個算法須說明一整輪包含哪些操作，種群個體逐一更新、多個運算子及局部搜尋不因此各自成為一輪；也不以 evaluate 或 addAct 次數計數。

這是對外的完成輪數，不強制改動算法內部從 0 或 1 起算的代號、公式或 RNG 順序。例如 CDELS 內部把初始族群稱為第 1 代，不代表對外已完成一次更新。

允許 max_iterations 為 0：執行原本初始化所需的緩存、初始解建立及正常評估／修復，之後不進入更新輪次，完成迭代為 0；仍由求解任務做最終驗證、交付初始結果及實際歷史。不是略過輸入預檢，也不能把 0 偷改成 1；算法未支援時整場不啟動。初始候選解不可行依 D06 回報，若根本沒有候選解，其結果型別仍待 [03](03_task_and_result_contract.md) 細化。

### 時間停止的範圍與限制

從算法開始初始化起算，包含算法緩存配置、初始解建立與搜尋；題目資料預處理、最終驗證、結果轉換及 Python 寫檔不計入這個上限。

初始化完成後先檢查時間，之後每代完成時再檢查，不切斷正在執行的初始化或世代。例如上限 60 秒，第 59 秒開始的一代到第 69 秒才結束，就在整代完成後停止；不能宣稱保證在第 60 秒返回。若初始化已耗盡時間，完成初始化後就不再開始新一代。

這是 C++ 算法的正常停止條件，不是主程序的強制中止、卡住偵測或 worker 超時；D28、D31 不變。D16 也不變：時間停止不承諾固定 seed 下的過程與結果可重現。先前控制實驗的既有計時數字不套用新口徑重寫。

### 達標停止的判定與缺值處理

開啟達標停止時，每個所選題目都必須有已知最佳值；缺少就啟動前報錯，整場不啟動。研究者可補數值，或將該題分到明寫關閉達標停止的群組，不由系統代做選擇。

達標使用可行解的原始目標值，不使用搜尋罰分；最大化須大於或等於目標，最小化須小於或等於目標。不設容許差、不加 epsilon，也不把實際分數改成目標。例如最小化目標為 0，分數 0.00000001 還不算達標。不可行解即使數值符合也不能觸發達標停止；若最後依主要停止條件結束仍不可行，依 D06 正常保存不可行結果。

D59 已確認在初始化完成後及每輪全部操作完成後檢查達標；初始解達標可返回，完成迭代為 0。如果某輪更新到第 17 個個體就達標，仍保留達標解、完成該輪後再停止，不在中途切斷。檢查只讀算法已維護的真實目標與可行性，不為此額外 evaluate 或消耗 RNG；這也不限制 addAct 的任意提交時點。

### 連續無改善提早停止

每個群組必填 max_no_improvement_iterations：正整數表示允許連續多少整輪沒有改善，null 表示關閉。它是主要代數／時間上限之外的提早停止條件，不另設無上限的獨立模式，也不是暫停後續算。這個條件不需要題庫已知最佳值；但同時開啟達標選項時，D56 的目標必填要求仍在。

「改善」依算法自身選取歷史最佳解的嚴格規則，由算法回報該輪是否改善，可反映可行性或搜尋分數；實驗模組不重算，也不額外 evaluate。這不把搜尋罰分冒充真實目標，更不替換 D57 的達標規則。

計數初始化為 0，每輪全部操作完成後，有嚴格改善就歸零，否則加 1，達設定輪數即停止。例如設 3，五輪依序「無、改善、無、無、無」，計數為 1、0、1、2、3，第 5 輪後停止。若某輪本來可能使計數達到門檻，但該輪確有改善，就先歸零，不能提前判停。

這個計數和算法內部 restart 計數分開。同分換解、單純重啟或重建種群不使它歸零；重啟後真的嚴格改善歷史最佳解才可以。檢查須涵蓋該輪全部操作，不能直接借用重啟函式自行清零的舊計數器。

### 重複判定與尚未決定的細節

D47 保持原規則：同問題類型、題庫、題名、算法、參數組與 seed 重複，整場不啟動；一組跑 1,000 代、另一組跑 5,000 代也不例外。停止設定必須記錄，但不加入重複判定鍵。

迭代計數、達標檢查點及停止欄位已依 D58–D64 確認，固定設定位置及一般命令另依 D65–D67，不再列為待選。C++ 支援查詢、任務交接及多條件同時成立的結果表示仍待對應單元細化，不先指定停止原因的優先順序。規則與限制見 [18 的 21 項模型核對](18_experiment_configuration_and_task_expansion.md#本輪-21-項獨立模型核對)。

## 連續型題目的具體例子

[f01.yaml](../../../configs/problems/continuous/book_benchmarks/f01.yaml) 目前包括：

```yaml
problem_id: f01

problem_type: continuous
dimension: 30
objective_id: sphere
lower_bounds: -100

```

這份檔案指定 Sphere 的一個 30 維實例，不是把平方和的程式寫進 YAML。`continuous` 是問題類型，`sphere` 是具體目標定義，`book_benchmarks` 是題庫分組；這三個概念不要都叫成一個「註冊」。

重構後可以保留類似設定，但 Sphere 的實際計算由 C++ 問題模組提供。這不是已確認的完整新格式。

## 算法設定放實驗側，為什麼不算責任重疊

以溫度為例：

- 研究者在設定中選擇本次初始溫度。

- 迭代中的溫度是算法執行狀態，不回頭修改原始 YAML。

D50 已選不使用執行時參數預設值，D51 已選停止設定由實驗群組唯一提供；不再保留兩套預設或覆蓋順序作為有效方案。D45 的完整有效數值記錄仍保留，具體表示與交接另議；實驗側記錄數值不等於擁有算法規則。

## AI 設定是否不同

AI 題目通常不把所有圖片／CSV／模型塞進 YAML；YAML 引用它們並指定切分、模型與評分規則。它不只是「啟動訓練的命令」，也描述候選解如何被評分。

傳統題也可以引用外部 `.vrp`／數據檔。因此共同點是「設定描述一題，專用資料另放」，不用強迫不同問題有完全相同欄位。逐欄交接見 [10](10_ai_feature_selection_boundary.md)。
