# 02｜問題資料、數學定義與設定

狀態：概念與責任已收斂；設定的正式格式、讀取分工及最終路徑仍有待議項。對應 D03、P01–P02。

## 必須分清楚的五件事

| 項目 | 例子 | 性質 |
| --- | --- | --- |
| 問題數學定義 | MKP 的價值加總、各容量限制；Sphere 的平方和。 | 規定什麼叫分數、什麼叫可行。傳統問題在 C++ 實作。 |
| 問題實例數值 | 某題的 values、weights、capacities；座標、需求量。 | 同一種數學問題的具體一題，可內嵌 YAML 或引用外部檔。 |
| 題目設定 | problem_type、題目 ID、維度、資料位置、objective 選項。 | 告訴系統要準備哪個問題及用哪些數值。 |
| 算法參數設定 | 種群數、mutation 參數、初始溫度。 | 研究者這次要使用的數值；參數意義與限制仍由算法定義。 |
| 實驗安排 | 哪些題、哪些參數組、重複次數、seed、worker。 | 告訴實驗管理如何產生及分派任務。 |

停止條件可能由實驗提出、由算法實際執行；不能在兩處各維護一個不同的有效迭代上限。實際解析規則須在 schema 定案時明確化。

## 先決定維護者，再決定讀取者，最後決定位置

這是使用者指定的討論順序，不應因為目前目錄長相就反推責任。

### 誰維護

- 題庫設定與實驗參數數值：實驗人員維護，確保數值符合研究目的。
- 題目欄位的數學意義與必要條件：問題開發者定義。
- 算法參數意義、預設值及合法範圍：算法開發者定義。
- 設定載入與任務交接機制：系統實作。

同一個人可以兼任以上角色；「責任不同」不是要求多人維護。

### 誰讀取：目前方向，尚待交接細化

1. Python 讀實驗設定，知道需要哪些題目及參數組。
2. Python 可讀共同的題目設定與原始數值。
3. 求解任務中的問題模組依數學規則建立可計算資料。
4. 算法開始迭代後，只使用準備好的本地數值及 evaluator。

例如 Python 先讀到城市座標，不代表 C++ 每次算距離都要再開 YAML 或呼叫 Python。可以在開始前一次傳入數值，或由任務附接共享資料。哪一種還要依 [08](08_cpp_invocation_and_shared_memory.md) 收斂。

### 檔案放哪裡：可行方向，不是假裝已搬移

共同題目設定與算法參數設定放在實驗側管理的目錄是合理方向。原因是它們是「這場實驗選用什麼」的資料，不是某個算法的程式私有實作。

但不能因為檔案放實驗側，就讓實驗管理擁有 objective；也不用因為 evaluator 是 C++，就把所有原始題庫搬入 C++ 原始碼樹。

## 現況核對

- [engine/repository.py](../../../engine/repository.py)：依問題類型／dataset／problem_id 找 YAML，透過問題 registry loader 建模。
- [problem/registry.py](../../../problem/registry.py)：維護問題類型、loader 與共享資料封裝契約。
- [engine/bank.py](../../../engine/bank.py)：保存實驗所需問題並提供 worker 的共享資料。
- 題目設定目前在 `configs/problems/`；算法設定在 `configs/solvers/`。
- 一般執行入口是 [cli/run/main.py](../../../cli/run/main.py)。`cli/exp` 是符合條件的 seed 收集用途，不能拿它代表全部一般實驗設定。

現有設定分類還包括特定工具／驗證命令的設定；不必全部併成一種 YAML。

## 連續型題目的具體例子

[f01.yaml](../../../configs/problems/continuous/book_benchmarks/f01.yaml) 目前包括：

```yaml
problem_id: f01
dataset: book_benchmarks
problem_type: continuous
dimension: 30
objective_id: sphere
lower_bounds: -100
upper_bounds: 100
best_known: 0
```

這份檔案指定 Sphere 的一個 30 維實例，不是把平方和的程式寫進 YAML。`continuous` 是問題類型，`sphere` 是具體目標定義，`book_benchmarks` 是題庫分組；這三個概念不要都叫成一個「註冊」。

重構後可以保留類似設定，但 Sphere 的實際計算由 C++ 問題模組提供。這不是已確認的完整新格式。

## 算法設定放實驗側，為什麼不算責任重疊

以溫度為例：

- 算法定義溫度的意義、使用方式與合法範圍。
- 研究者在設定中選擇本次初始溫度。
- 任務接收解析後的數值，交給算法初始化。
- 迭代中的溫度是算法執行狀態，不回頭修改原始 YAML。

預設值只應有明確權威與解析順序。是否由 C++ 提供預設、Python 是否保存完整有效參數，尚待格式與呼叫方式一起決定；不要維護兩套不同預設。

## AI 設定是否不同

AI 題目通常不把所有圖片／CSV／模型塞進 YAML；YAML 引用它們並指定切分、模型與評分規則。它不只是「啟動訓練的命令」，也描述候選解如何被評分。

傳統題也可以引用外部 `.vrp`／數據檔。因此共同點是「設定描述一題，專用資料另放」，不用強迫不同問題有完全相同欄位。逐欄交接見 [10](10_ai_feature_selection_boundary.md)。

## 待議項

- 題目設定與算法參數設定的最終目錄、schema、預設值解析。
- 哪些原始資料由 Python 讀取、哪些由問題模組專用 loader 準備。
- 距離矩陣等衍生數值由誰建立、何時共享，避免不同捨入規則。
- AI 訓練／測試檔案及模型輸出位置；目前不指定新的正式路徑。
- 不強制引入版本／digest／DSL／code generator 來代替以上責任決定。
