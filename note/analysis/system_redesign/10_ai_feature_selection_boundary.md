# 10｜AI 情境：特徵篩選的設定與交接

狀態：用來檢查共同責任邊界的設計情境；AI 正式 schema、訓練整合與呼叫協議未實作。本章不批准新增 AI 模組。

## 為什麼現在仍要保留這個情境

已知未來要做 AI 研究，不能把「所有 evaluator 都只能 C++」鎖死成整個系統的唯一規則；但也不用在第一階段做完完整模型訓練平台。

目前原則是一起檢查共同邊界，先細化傳統優化問題。AI 的資料準備、訓練與評分屬於求解任務內的問題責任，不新增第二套外層實驗管理。

## 白話例子

資料有三個特徵：年齡、收入、瀏覽次數。候選解 `[1, 0, 1]` 表示用第 1、3 個特徵，不用第 2 個。

C++ 搜尋算法提出組合；Python AI 問題模組選欄位、依題目規則訓練與評分；分數回傳算法。C++ 不必載入整份模型實作，也不是每次都讓 Python 重新安排一場外層實驗。

## 逐欄交接

以下是必須能表達的資訊，不是正式 YAML 欄位名；哪些可用預設仍待確認。

| 設定提供什麼 | AI 問題模組準備什麼 | 最後交給 C++ 什麼 |
| --- | --- | --- |
| 資料來源／檔案位置 | 載入表格或資料集。 | 一般不必把整份訓練資料送給搜尋算法；由 evaluator 保有。 |
| 標籤欄、特徵欄及排除欄 | 分開 X／y，固定可選特徵順序。 | 解的長度、位置意義所需約定。 |
| 切分／交叉驗證規則 | 準備評分用資料切分及必要隨機上下文。 | 可呼叫的評估能力；不是把每折訓練變成外層 task。 |
| 前處理規則 | 建立與評估切分相容的轉換流程。 | evaluator 內部處理，不要求算法理解標準化。 |
| 使用哪個模型及固定模型參數 | 準備模型建立方式；每次如何建立／重設待定。 | evaluator 的評分結果。 |
| 哪些值由候選解決定 | 建立二元 mask，或 HPO 的參數解碼規則。 | 編碼種類、長度、各位置範圍。 |
| 評分指標、方向及聚合規則 | 依題目定義算正確率／錯誤率等。 | 真實目標值及最小化／最大化方向。 |
| 最少／最多選幾個特徵等限制 | 實作可行性判定及空子集規則。 | 每次評估的可行性。 |
| 評估隨機設定 | 管理資料抽樣、模型初始化等評估上下文。 | 評估能力的可重現行為；和搜尋 RNG 的分工待定。 |
| 最終測試與模型保存需求 | 按預先規定檢查最終候選解、產生需要的模型產物。 | 任務最終結果；產物交付方式另定。 |

算法 ID、算法參數、搜尋 seed、停止條件仍是任務安排資訊，不由 AI 資料檔偷偷決定。

## 準備與執行的先後

```text
Python 實驗側建立特徵篩選任務
  → AI 問題模組讀資料，確認特徵順序與數量、建立評分能力
  → 求解任務把編碼規則與評估能力接給 C++
  → C++ 產生候選解
  → Python AI 問題模組依該解訓練／評分
  → C++ 使用分數繼續搜尋
  → 任務依 AI 問題規則最終檢查
  → 一次回傳最終結果及全部已提交歷史
```

例如讀資料後才知道有 96 個可選特徵，必須先告訴 C++ 有 96 個二元位置，再建立初始解。這就是「AI 問題模組準備資料」的具體意義，不是要求實驗管理理解訓練數學。

評估可以包裝成函數／物件，概念上就是目標函數入口；不代表必須每個候選解啟動一次新的 Python 腳本。callback、批次評估或 ask/tell 都是未定案的接法。

## YAML 與真實資料放置

AI YAML 可以引用外部 CSV、圖片、切分清單與模型設定，並不內嵌全部資料。傳統問題也可引用外部檔，所以兩者不是完全不同的設定機制。

共同之處是描述「哪一道題」，不同的是每種問題必填欄位與準備方式。訓練／測試數據實際目錄、模型輸出位置尚未定，不因這份表格就建立正式路徑。

## AI 加入前仍要確認的細節

- 搜尋評分用的驗證資料與最終測試資料是否區分，避免用最終測試集反覆挑解。
- 前處理如何避免把評估資料的資訊洩漏到訓練中。
- 空子集的真實目標值／可行性、訓練失敗如何表示。
- 評估 RNG、模型狀態、GPU／執行緒非確定性與最終驗證方法。
- 模型快取及重複候選解是否重用分數；不能預設隨機評估快取不影響研究意義。
- 完整歷史保存的是已提交狀態，不會為了顯示分數額外訓練一次。

以上保留為未來問題需求，不用現在就把它們實作進傳統求解任務。
