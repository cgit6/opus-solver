## 一、已確認

| 編號 | 決策 | 理由與邊界 | 詳細文件 |
| --- | --- | --- | --- |
| D01 | Python 作為實驗系統主體；傳統問題的目標方向是 C++ 求解模組。 | 不等於現在刪除 Python 算法。舊實作仍是遷移比對依據。 | [01](01_scope_and_responsibilities.md) |
| D02 | 問題負責判定，算法負責搜尋，求解任務負責最終驗證，實驗管理負責安排與記錄。 | 不新增含糊的「後端服務」責任層。 | [01](01_scope_and_responsibilities.md) |
| D03 | 傳統問題的 objective 與 constraints 在 C++ 執行。 | 不在高頻候選解評估時反覆跨回 Python。資料讀取／傳遞方式另議。 | [02](02_problem_data_and_configuration.md)、[08](08_cpp_invocation_and_shared_memory.md) |
| D04 | 一個任務是一題、一算法、一組參數、一個 seed 的完整求解。 | 算法內的一次評估／一次訓練，不另當成一次外層實驗任務。 | [03](03_task_and_result_contract.md) |
| D05 | 實驗模組接收已由求解任務驗證的結果，不重做數學驗證。 | 通訊解碼與必要輸入契約檢查不等於重算 objective；不能因此要求系統認證人為題目設定正確。 | [01](01_scope_and_responsibilities.md)、[03](03_task_and_result_contract.md) |
| D06 | 達停止條件時最終解不可行，仍是正常完成，標示不可行。 | 和執行錯誤、輸入錯誤、最終核對不一致分開。 | [03](03_task_and_result_contract.md) |
| D07 | 真實目標值與算法搜尋罰分分開。 | 罰分可存於算法內部／外部狀態，不冒充編碼的真實適應值。 | [05](05_evaluation_and_incremental_updates.md) |
| D08 | 算法有主結構、內部結構與外部結構，以及主執行函數與輔助函數。 | 共用結構概念不等於共用一份可變全域狀態；C++ 型別／模板／繼承方式未定。 | [04](04_algorithm_state.md) |
| D09 | 編碼與真實適應值是算法的共同解狀態；由算法更新。 | 不要求所有問題都被壓成同一種一維數值編碼。 | [04](04_algorithm_state.md) |
| D10 | 最佳解由算法保存，可放在外部結構。 | 必須和歷史紀錄、會被覆寫的候選解緩存區別。 | [04](04_algorithm_state.md) |
| D11 | evaluate 接收一個個體的完整編碼，返回真實適應值與可行性布林值。 | 本輪以單目標為例；多目標型別、例外表示等尚未定。 | [05](05_evaluation_and_incremental_updates.md) |
| D12 | 允許正確的增量更新，不要求每個小操作都完整 evaluate。 | 例如移除背包物品時，同步改編碼、扣價值、更新容量及可行性。 | [05](05_evaluation_and_incremental_updates.md) |
| D13 | addAct(文字狀態, 編碼, 外部結構或 nil) 只提交狀態。 | 不評估、不訓練、不修復、不修改搜尋狀態、不消耗 RNG。適應值取自同次對應的解狀態。 | [06](06_state_submission.md) |
| D14 | 算法可自行選擇提交時點；不自動加「未評估」標記。 | 提交安排在完整小操作之後；不能用記錄函數偷算分數來修補不同步。 | [06](06_state_submission.md) |
| D15 | 提交內容應對齊，快照不可被後續緩存覆寫。 | 列為開發原則與測試要求，不新增實驗系統逐筆掃描驗證。 | [06](06_state_submission.md) |
| D16 | 固定 seed、固定迭代數時，開關狀態紀錄不應改變搜尋過程與結果。 | 不承諾時間停止條件可重現；AI 額外的非確定性另行驗證。 | [06](06_state_submission.md)、[11](11_migration_and_verification.md) |
| D17 | 所有任務的每次實際提交都保留，不抽樣、不只保留指定 seed。 | 每次提交當時的編碼、對應適應值及實際提供的外部快照均保存；nil 仍是 nil。 | [07](07_history_return_and_storage.md) |
| D18 | 每個任務由 C++ 求解、最終驗證後，一次完整返回 Python，包含最終結果及全部紀錄；此返回邊界仍為有效舊保存基線。 | 每 task 完整計算、驗證及一次交付不變。候選若改 C++ 序列化／保存或完整歷史轉入 Python 的方式，須列返回內容及所有權差異待確認，不能默默取消返回 Python，也不是等整場完成才交付。 | [07 保存基線](07_history_return_and_storage.md#已確認交付需求與保存基線) |
| D19 | 保存屬實驗／輸出責任，算法及 addAct 不做文件 I/O；當時選定 Python 輸出器，沿用仍是有效舊保存基線。 | Python-only 與獨立 C++ 輸出元件已有 [19 的候選對照](19_architecture_candidate_experiments.md)，未改為採用；C++ 語言輸出元件不等於算法負責文件。候選交付與所有權差異須確認；不加 Redis、背景 writer 或分批，錯誤按業務階段而非語言區分。 | [07 保存基線](07_history_return_and_storage.md#已確認交付需求與保存基線) |
| D20 | 此版接受完整單任務歷史可能耗盡記憶體的已知風險。 | 這是延後解決，不是已證明安全；不能用截斷、環形覆寫來暗中規避。 | [07](07_history_return_and_storage.md) |
| D21 | 先用傳統與 AI 情境檢查責任邊界，再集中細化傳統問題。 | 避免完全忽略已知 AI 需求，也不一次實作完整 AI 平台。 | [10](10_ai_feature_selection_boundary.md)、[11](11_migration_and_verification.md) |
| D22 | 重構採小步修改、每步對照驗證、有明確停止點。 | 這次文件整理不批准執行任何程式重構或刪除算法。 | [11](11_migration_and_verification.md) |
| D23 | task 非預期未完成時，實驗模組須保留其實際工作與輸入，供事後單獨從頭重跑。 | 不要求 Python 診斷 C++ 根因，不是中間 checkpoint，也不保證每次都再次崩潰。不能只保留可變來源路徑或暫時 SHM 名稱。 | [14](14_python_cpp_invocation_and_failure_replay.md) |
| D24 | 系統軟體流程異常須保留實際輸入與已知錯誤，依錯誤種類處置；算法錯誤停止整場，Python 保存錯誤依 D40 處理。 | D79–D80 取代算法錯誤後繼續派工的要求；不自動重試原 task，不把正常不可行解當錯誤，也不擴大預檢或硬體／資源故障範圍。 | [15](15_task_failures_and_result_storage.md) |
| D25 | 範圍內的 Python 軟體保存失敗，實際原因與 task 對應須事後可查，不只記「失敗」；求解異常保留輸入／已知事實，不要求 C++ 根因。 | 產生原因、通知與持久保存不同；正式誰／何時／何處保存及完成判定仍待確認，不可只靠通知宣稱達標，也不降成允許原因遺失。二次軟體失敗／留存前退出的保障依 [15](15_task_failures_and_result_storage.md#保存錯誤原因的留存界線) 待確認，D26 排除不變；不保證同 seed 重現檔案環境問題。 | [15 留存界線](15_task_failures_and_result_storage.md#保存錯誤原因的留存界線) |
| D26 | 本版不處理磁碟滿、磁碟故障等硬體／資源層非預期行為，不為錯誤紀錄新增獨立儲存媒介或服務。 | 原因留存保障不包含由這些已排除故障造成整個儲存不可寫；不能把路徑／權限／序列化等軟體問題一律排除。不增加另一顆磁碟、另一台機器或跨媒介備援。 | [15](15_task_failures_and_result_storage.md#保存錯誤原因的留存界線) |
| D27 | 算法錯誤依 D79–D80 停止整場，不再要求其他正常 task 必須繼續；不自動重跑。 | 正常執行時，各 task 的 RNG 與可變狀態仍須獨立。已保存結果保留；連帶停止的工作不能冒充成功或算法自身出錯，停止機制與時點仍待細化。 | [14](14_python_cpp_invocation_and_failure_replay.md)、[16](16_process_lifecycle_experiment.md) |
| D28 | 本版不加入卡住後自動超時中止。 | 沒有明確錯誤或程序終止、但一直未完成的工作，暫由研究者人工處理；不等於更動算法本身的正常停止條件。 | [14](14_python_cpp_invocation_and_failure_replay.md) |
| D29 | 重用健康的求解程序；每 task 的 RNG、算法狀態與歷史獨立，交付後正確清理。算法錯誤依 D79–D80 停止整場。 | 同一邏輯工作鏈須同步保存、交接及清理後才接下一題，不代表同 host 其他鏈必須等它保存；結果仍被使用時不可釋放或覆寫。D40 替換範圍及新拓撲待確認，名詞依 [14](14_python_cpp_invocation_and_failure_replay.md#執行名詞與替換範圍)，不預設鏈永久綁 thread／程序。 | [14](14_python_cpp_invocation_and_failure_replay.md)、[16](16_process_lifecycle_experiment.md) |

## 三、延後處理

- 大型完整歷史的記憶體上限、分批交付、背景寫入、Redis：先遵守 D17–D20，不並行實作替代路線。
- 算法內部 checkpoint、RNG 中途恢復：不以 addAct 取代；任務級重跑與算法中途續算是不同功能。
- 整場實驗重啟後辨識／跳過已完成 task：待核心重構通過驗證後設計與實作，不宣稱現有一般入口已具備。D23–D25 的異常輸入、寫檔原因及 D79–D80 的算法錯誤停止須納入核心驗收，必要的單次交付判定不能一併延後。
- AI 的正式模型訓練整合、GPU／遠端執行、訓練失敗與快取策略：先保留交接情境，不擴充第一版。
- Legacy bug 修正、算法流程變更與新效能優化：不和系統重構混成同一批修改。
- 舊設定遷移、大規模目錄搬移與舊算法淘汰：另設遷移關卡。
