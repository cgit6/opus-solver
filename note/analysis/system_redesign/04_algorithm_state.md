# 04｜算法主結構、內部結構與外部結構

狀態：結構責任及健康程序重用下的每題狀態獨立已接受；C++ 型別與實際布局待定。對應 D08–D10、D29、P06–P07。

## 概念結構

```text
一個任務擁有的算法主結構
├─ 解狀態：目前各個體的編碼、真實適應值
├─ 內部結構：初始參數、工作緩存、衍生查表與算法私有狀態
├─ 外部結構：允許對外觀察的自訂數值／標籤／最佳解等
└─ 紀錄控制：例如 isSim 的既定用途
```

「系統共同的子結構」指共同的資料概念，不是所有 task 都寫進同一份全域 population。每個任務的可變狀態互相隔離。

## 主結構與解狀態

編碼及真實適應值是不同算法都需要表示的資料，可作為共同解狀態。算法輔助函數直接更新它，不再另設一份同名分數當成另一個權威。

- 單一解算法：當前候選解可能只有一筆。
- 種群算法：當前候選解是多筆，編碼與適應值順序一一對應。
- 當前種群、下一代種群、歷史最佳解，是不同的邏輯狀態，可以合法有不同儲存。
- 不強迫路線、二元向量、實數向量都塞入相同固定型別陣列；正式表示留待實作細化。

目前方向是解狀態直接持有資料；不先加入一套通用借用／延遲同步框架。C++ 是否使用模板、組合或其他機制，仍未定案。

## 內部結構：算法自己需要，但不必全量提交的資料

例子：

- 由 task 帶入的問題數值引用、算法參數及初始化數值。
- 背包目前各維度負載、路線位置表、轉移標記及必要容量狀態。
- mutant、trial、Local-search 等工作緩存。
- 把權重轉成抽選用 lookup table 等衍生緩存。

共享唯讀問題數值是否以引用保留，由 [08](08_cpp_invocation_and_shared_memory.md) 決定。內部結構不表示必須把題目大陣列再深度複製一份。

求解開始前先初始化所需工作空間，再進入迭代。具體大小、何時失效／重建，必須根據算法確定，不能直接把所有緩存統一每代清空。

## 重用程序，不延續上一題的算法狀態

D29 已確認健康求解程序繼續接新 task；每題仍有獨立的 RNG、主／內／外結構及歷史容器，初始化時使用本題 seed 與參數，不能把上一題的世代編號、種群或搜尋進度帶進來。

工作緩存在同一次求解的迭代間可以持續重用；任務交接完成後，按資料生命週期結束不再需要的本題狀態。這不批准跨任務保留一份可變算法緩存池，也不要求每代重新配置。配置器可能保留已釋放空間供下次使用，不能只看 RSS 就判定任務狀態尚未清理。

結果或歷史若仍由接收／保存方引用，必須維持有效性，不得為了開始下一題就釋放或覆寫。D34–D35 已選同程序 C++ 返回該 Python worker，由它同步保存；不要求公開逐步算法物件。正式 C++ 所有權與布局仍待定，控制證據見 [16](16_process_lifecycle_experiment.md)、[17](17_invocation_comparison_experiment.md)，不等於正式外部結構已驗收。

## 外部結構：算法選擇暴露的狀態

可以包含：

- 溫度、控制參數目前值、運算子名稱或執行階段。
- 個體可行性、容量摘要、算法自己的搜尋罰分。
- 目前最佳解及其真實適應值。

它可以作為提交快照的來源，但本身仍是算法正在維護的可變狀態，不等於已保存的歷史。

最佳解也不能只是指向之後會被改寫的 trial。即使外部結構內保存最佳解，仍由算法負責選取、更新與保護其資料。

## isSim 的邊界

使用者提出 isSim 決定提交時是否包含外部結構；布林方向與具體設定層級尚未定案。

必須區分：

1. 算法需要更新外部結構中的某狀態，才能正確搜尋。
2. 本次 addAct 是否保存該狀態的快照。

第二件事關閉，不代表可以停止做第一件事。也不能自行解讀成「關閉全部基本編碼與適應值紀錄」；本輪全量歷史指每次實際提交完整保留。

## 輔助函數如何更新主狀態

`removeItem()` 是討論中的算法自訂輔助函數名稱，不是既有系統通用 API。它可以持有／接收該算法解狀態的可寫引用，同步更新原本的編碼、分數與負載；不用靠返回另一份完整解來達成更新。

其他算法可以有自己的 `swapCustomers()`、`repair()` 等函數。問題相關的增量數學必須正確，但不要求所有算法採同一套函數名稱。

## Population buffer 的前期結論

以舊世代產生全部下一代的算法，整代期間可能要保留舊種群不變。處理第 17 個個體後，後續 mutation 仍可能讀到舊第 17 個個體，不能提前覆寫。

current／next 可在一代完成後交換引用，避免整代深度複製；但產生候選解需要的資料寫入不會因此全部消失。之前固定 trial pool、連續 backing storage、packed／flat list、Copy-on-Write 的實驗屬於個別算法實作研究，不自動成為所有 C++ 算法的共同框架規格。詳見 [12](12_prior_work_and_references.md)。

## 開發檢查，而不是主系統逐次檢查

初始化時可檢查維度、陣列長度與必要結構。開發測試驗證操作後狀態正確、快照不受後續覆寫影響。不要求實驗管理在每次提交時掃整個種群、重新評估或認證狀態對齊。
